# 平台启动-x86_64

v0.1 · 2026-09-25

本篇覆盖：`arch/x86_64/boot/boot.S`、`arch/x86_64/boot/gdt.c`、`arch/x86_64/boot/start_arch.c`、`arch/x86_64/boot/smp.c`（跳板拷贝与 SIPI 的架构侧；整机编排见 `06-SMP与同步/28-SMP启动与处理器拓扑.md`）、`include/arch/x86_64/desc.h`、`include/arch/x86_64/boot/arch_setup.h`、`include/arch/x86_64/boot/multiboot.h`、`include/arch/x86_64/boot/multiboot2.h`。链接脚本侧见 `00-总览/01-构建与链接.md`；`cmain` 何时调用下面的钩子见 `02-启动流程总览.md`。memmap / RSDP 消费见 `02-内存管理/06-物理内存与Buddy分配器.md` 与 `09-平台模块/35-ACPI与MADT-x86_64.md`。运行期 IRQ 见 `05-陷阱与中断/26-平台中断-x86_64-APIC与PIC.md`。

本篇按三块讲清楚：汇编如何把机器交到 `cmain`；全机只做一次的平台钩子；每个核都要跑的 `arch_start_core`。

---

## 1. 概述

x86_64 这条路径的入口约定是：**用 Multiboot1/2 加载一份 `kernel.bin`，落到大约物理地址 `0x100000`，在 32 位保护模式、分页关闭的状态下进入 `bsp_entry`**。链接脚本把内核挂在高半核 VA `0xffff800000000000 + 0x100000` 上。`boot.S` 要在汇编里完成三件事：按内核镜像实际大小填好早期 2 MiB 页表、按 Intel 手册要求的顺序进入 IA-32e 长模式、再绝对跳到链接高半，然后 `call cmain`。

平台相关的工作故意不塞进汇编。`prepare_arch` 只核对 Multiboot magic、把 cmdline 指出来；内存图和 RSDP 要等到 `phy_mm_init`；ACPI 和 PCI 要等到有了 `kallocator` 之后，由 `arch_start_platform` 全机做一次；每个核自己的 GDT、中断控制器、syscall MSR、时间则在 `arch_start_core`。AP 的 INIT-SIPI 跳板也在本篇源码里，但「谁在什么时候拷贝、发几次 IPI」的编排属于 SMP 篇。

为什么坚持 **bin + Multiboot**，而不是直接丢 ELF、也不走 PVH？历史上的症结是：当时常见的 QEMU/引导路径对「直接以 x86_64 ELF 当内核」支持不完整；Multiboot1 能可靠地按 **address 字段** 把一段扁平镜像装到指定物理地址，而 bin 正是靠这些字段描述 load/bss/entry 的。换 UEFI 直启是另一套协议（evolution **E7**），不是改几条页表就能切换的。

---

## 2. 目标与边界

**本篇要讲清：** Multiboot 头为什么要写 address / entry tag；从 `bsp_entry` 到 `cmain` 的寄存器、页表与模式切换；`setup_info` 里哪些字段由谁填写；三个 BSP 钩子与每核 `arch_start_core` 各自负责什么。

**本篇不展开：** IOAPIC/MSI 完整路由表；ACPI 表字段逐项；并行唤醒多个 AP。跳板必须落在低 1 MiB 的页对齐地址（SIPI 向量是页帧号），`0x0` 是实模式向量表，所以实现选 `0x1000`。并行会抢同一份 `setup_info` 里的栈和 `cpu_id`，因此架构侧串行发 SIPI——这条权衡的代码在 `arch/x86_64/boot/smp.c`，顺序见 SMP 篇。

失败路径：非 Multiboot magic 时 `prepare_arch` 返回 `-E_RENDEZVOS`，`cmain` panic；CPUID 无长模式则在 `boot.S` 里 `hlt`；SIMD 探测失败只 `pr_error`，`arch_start_core` 仍返回 0。

---

## 3. 分层与调用方

`boot.S` 只对固件 / Multiboot 装载器负责，成功路径结束于 `cmain`。`start_arch.c` 里的 `prepare_arch`、`arch_cpu_info`、`arch_start_platform`、`arch_start_core` 由 `cmain`（以及 AP 侧的 `start_secondary_cpu`）按可移植名字调用，参数形态与 aarch64 对齐，这样编排层不必 `#ifdef` 分架构。

ACPI 对象模型和 PCI 树的细节不在本篇；本篇只说明它们在 `arch_start_platform` 里被拉起，而且分配一律走 `per_cpu(kallocator, BSP_ID)`。链接方若要换引导协议，动的是本篇的头与 `boot.S`，不是 `cmain` 的编排顺序。

## 4. 数据结构与不变量

### 4.1 `struct setup_info`（x86_64）

定义在 `include/arch/x86_64/boot/arch_setup.h`，`boot.S` 的 `.boot.data` 里有同名符号，**packed** 布局须与汇编一致。前缀是本架构专用字段；尾部 `ap_boot_stack_ptr` / `cpu_id` 是跨 ISA **通用字段**（语义与谁写谁读见 `02-启动流程总览.md` §4.1.1，此处只给本 ISA 偏移）。

| 偏移 | 字段 | 谁写 | 谁读 / 用途 |
|------|------|------|-------------|
| `0x0` | `multiboot_magic` | `bsp_entry`（`eax`） | `prepare_arch` 分支 MB1 / MB2（`0x2BADB002` / `0x36d76289`） |
| `0x4` | `multiboot_info_struct_ptr` | `bsp_entry`（`ebx`，**物理**地址） | 经 `GET_MULTIBOOT_INFO` / `GET_MULTIBOOT2_INFO` 加 `KERNEL_VIRT_OFFSET` 后给 memmap / cmdline 等 |
| `0x8` | `phy_addr_width` | `bsp_entry`（CPUID `0x80000008` AL） | `prepare_arch` → 全局 `max_phy_addr_width` |
| `0xc` | `vir_addr_width` | 同上（AH） | 随结构保存；当前消费者以物理宽度为主 |
| `0x10` | `rsdp_addr` | **稍后** `arch_init_pmm`（进 `cmain` 时为 0） | `arch_start_platform` → `acpi_init` |
| `0x18` | `ap_boot_stack_ptr` | `arch_start_smp`（发 SIPI 前） | 通用字段，见总览 §4.1.1 |
| `0x20` | `cpu_id` | `arch_start_smp`（发 SIPI 前） | 通用字段，见总览 §4.1.1 |

C 里读 Multiboot info **必须**经上述 GET 宏：物理指针加上高半偏移，因为此时已经跑在高半恒等映射上。RSDP **不**在 `prepare_arch` 里找，而在物理内存路径写回本结构后再给平台钩子用。

### 4.2 链接、加载与早期物理布局

链接脚本 `script/link/x86_64_linker.ld`：

- `kernel_virt_offset = 0xffff800000000000`
- `kernel_start_offset = 0x100000`
- `ENTRY(_start)`，VMA 从 `kernel_virt_offset + kernel_start_offset` 起排

因此链接 VA 形如 `0xffff800000100000`。`.text` 收纳 `.boot` / `.boot_64` / `.boot.*`；早期页表页在 `.boot.page`（4 KiB 对齐）；boot 栈在 `.bss` 的 `.boot_stack`（`_boot_stack_bottom`）。

产物路径：ELF 经 `objcopy` 成 `kernel.bin`。Multiboot 头里写了 load / bss / entry 的**物理**地址（符号减去 `kernel_virt_offset`），引导器按这些字段把镜像装到约 PA `0x100000`，与 `kernel_start_offset` 一致。这样早期恒等关系才是「高半 VA ↔ 同偏移 PA」——不是巧合，而是 Multiboot address 字段与链接脚本共同定下的。

`BIOS_MEM_UPPER`（`0x100000`）也是后面 `phy_mm_init` 插入可用区时的下限：低于 1 MiB 的区不进 buddy，给 BIOS / 跳板留着。

### 4.3 早期页表（四级，2 MiB 大页）

静态表在 `.boot.page`：

- **L0（PML4）**：第 0 项和第 256 项都指向同一张 `L1_table`。第 0 项覆盖低地址恒等取指；第 256 项对应高半 `0xffff8000…`（PML4 索引的高半窗口）。两扇门进同一张下一层表，所以同一份物理页在低址和高半都能看见。
- **L1（PDPT）**：只有第 0 项指向 `L2_table`。因为加载点在 1 MiB，落在这张 PDPT 的第一项覆盖范围内。
- **L2（PD）**：启动时全零；`bsp_entry` 在开分页前按 `[_kstart, _end)` 的物理范围，以 2 MiB 步进写入 `P | RW | PS | G`。`PS` 表示这是 2 MiB 页，不是指向更下一层表。实现**故意不用 1 GiB 页**：不少机器的 CPUID 并不保证 1 GiB 大页，而 2 MiB 足够覆盖当前内核镜像；页数按镜像实际上界动态填，而不是固定写满一整 GiB。

开长模式之后，执行流先仍在低地址恒等区，再靠 `movabs` 跳到链接高半。`clean_tmp_page_table` 符号存在，但 BSP 成功路径上**不会**调用它去拆恒等映射——当前实现一直保留这份早期表，直到内存子系统后续另建运行时页表。

### 4.4 进入 IA-32e 的硬件顺序

Intel SDM 对「到 IA-32e paging」的要求是固定的：必须先开 **PAE**（`CR4.PAE`，实现里还顺带开了 `CR4.PGE`），再写 **EFER.LME**（实现同时开了 `SCE` 与 `NXE`），把 `L0_table` 的物理地址装进 **CR3**，最后开 **CR0.PG**。顺序反了进不了长模式。细节与手册章节对照见 §4.6。

随后 `lgdt` 临时 GDT（空描述符 + 一条 64 位代码段，`L` 位置位），`ljmp $0x08, …` 进到 `.boot_64` 的 `x86_64_entry`。这份临时 GDT 的作用很窄：把 CS 从 32 位保护模式换成 64 位代码段；正式的每核 GDT 要等到 `arch_start_core` 里再装。

### 4.5 `BSP_ID` 与 percpu

`arch_cpu_info` 把 `BSP_ID` 设为 CPUID 叶 1 的 APIC ID。`cmain` 在此之前已经用初值 0 调用过 `arch_enable_percpu`。若机器上 BSP 的 APIC ID 不是 0，则「用 0 启用的那个槽」和「之后按 APIC ID 索引的槽」不是同一个——这是总览里已经写过的编排次序问题，不是本函数再启用一次 percpu。

### 4.6 与官方文档的对照（启动必知）

下面只摘与本实现直接相关的条款，不代替读手册。章号以 Intel《64 and IA-32 Architectures Software Developer’s Manual》常见分卷为准（不同年份版次小节号可能微调，以你手头 PDF 的目录检索关键字为准）。

**模式与控制寄存器（SDM Vol. 3A）**

- 进入 **IA-32e mode** 并启用分页时，软件必须按固定顺序操作控制寄存器：先置 `CR4.PAE`，再置 `IA32_EFER.LME`，加载页表根到 `CR3`，最后置 `CR0.PG`。手册在分页 / 模式切换相关章节用状态图说明：在未开 PAE 时置 LME、或未开 LME 时开 PG，都不会得到合法的 64 位分页环境。本实现的四个宏正是按这条链路写的。
- 同时置位的附属位：`CR4.PGE`（允许页表项 `G` 全局位生效）、`IA32_EFER.SCE`（允许 `SYSCALL`/`SYSRET`）、`IA32_EFER.NXE`（允许页表 NX 位）。它们不是「进长模式」的最小集合，但是本内核后续 syscall 与页保护会用到。
- 长模式下代码段描述符的 **L 位**（64-bit code segment）必须为 1、`D` 位为 0；临时 GDT 那一项就是按此编码的。`ljmp` 换 CS 之后，CPU 才真正按 64 位指令译码执行。

**四级页表与 2 MiB 页（SDM Vol. 3A，Paging）**

- IA-32e 默认是 **4-level paging**：PML4 → PDPT → PD → PT。VA 的高 16 位必须是规范形式（canonical）：位 63…48 等于位 47 的符号扩展。`0xffff800000000000` 满足这一约束，故可作高半核窗口。
- PD 项的 **PS=1** 表示 2 MiB 页（不再下指 PT）。1 GiB 页则是 PDPT 项 PS=1，且需要 CPUID 声明支持；本实现只用 2 MiB，见 §4.3。
- PML4 索引由 VA\[47:39\] 取出。`0xffff8000…` 的 \[47:39\] 为 `0x100`（十进制 256），所以静态表把 **第 256 项** 指到与第 0 项相同的 PDPT——这是硬件索引规则，不是随便选的「高半槽位」。

**CPUID（SDM Vol. 2A / Vol. 3A）**

- 扩展叶 `0x80000001`：EDX bit 29 = Long Mode。没有这一位就不能按上面的链路开 PG。
- 扩展叶 `0x80000008`：EAX\[7:0\] 物理地址宽度、EAX\[15:8\] 线性地址宽度。boot 写入 `setup_info`，供后续物理/虚拟宽度上限使用。

**多核启动与 SIPI（SDM Vol. 3A，Multiprocessor / Local APIC）**

- AP 从 INIT 复位后处于实模式；BSP 通过 Local APIC 发 **SIPI**，向量字段是「起始页帧号」：CPU 从物理地址 `vector << 12` 开始取指。因此跳板必须落在低 1 MiB、页对齐处；本实现选 `0x1000`，避开 `0x0` 实模式向量表。INIT-SIPI 的完整编排见 SMP 篇，本篇只解释为何跳板地址受手册约束。

**引导协议（非 Intel，但是本路径的装载约定）**

- [Multiboot Specification](https://www.gnu.org/software/grub/manual/multiboot/multiboot.html)（Multiboot1）：装载器进入入口时 `EAX` = magic `0x2BADB002`，`EBX` = multiboot information 结构物理地址；若头里提供了 address 字段，则按给定物理区间装载扁平镜像——这正是 bin 路径能工作的原因。
- Multiboot2 另有 magic 与 tag 流；本镜像同时嵌入两套头，`prepare_arch` 两种都认。

## 6. 流程

### 6.1 Multiboot 头：为什么长成这样

镜像开头先 `jmp multiboot_entry`，后面紧跟 Multiboot1 头：magic `0x1BADB002`，flags 打开「需要内存信息」和「提供 load 地址」；因为产物是 **bin 不是 ELF**，头里必须显式给出 header / load / load_end / bss_end / entry 的物理地址（一律 `符号 - kernel_virt_offset`）。同一文件里还有一套 Multiboot2 头（magic `0xE85250D6`），带 address tag 与 entry address tag，方便将来换支持 MB2 的装载器；运行时 `prepare_arch` 两种 magic 都认。

### 6.2 `bsp_entry`：32 位到 `cmain`

进入时仍是 32 位、分页关闭；`eax` 是 magic，`ebx` 是 info 物理指针。两者立刻写进 `setup_info` 头两个 `u32`（写地址是符号减去高半偏移，因为此刻 PC 还在物理低址）。

接下来有一段「清 BSS」循环：设栈前按字节写 0，但比较条件是「若 `_bss_end` **大于** `_bss_start` 就直接去设栈」。正常镜像里 `_bss_end > _bss_start` 恒成立，于是循环体根本不会执行——这是指令级的事实，文档如实记录，本轮不改代码。栈指针设成 `_boot_stack_bottom` 的物理地址，再 `push 0; popf` 清 flags。

CPUID `0x80000001`：EDX bit 29（长模式）必须为 1，否则 `hlt`。CPUID `0x80000008`：AL / AH 分别是物理与线性地址宽度，写入 `setup_info` 后四个字节。

然后按 §4.3 填 L2：下界对齐 `_kstart` 的物理地址，上界对齐 `_end`，每 2 MiB 写一项。接着宏展开：`enable_pae` → `enable_lme` → `load_kernel_page_table`（CR3 ← L0 物理）→ `enable_pg`。`lgdt` 临时描述符后 `ljmp` 进 `x86_64_entry`。

64 位入口用 `movabs` 跳到真正的高半标签（此时低址恒等与高半都映射着同一份代码），把 DS/SS/FS/GS 清 0，RSP 换成高半的 `_boot_stack_bottom`，`rdi = setup_info`（高半虚地址），`call cmain`。若返回则 `hlt`。

### 6.3 AP 入口（本篇只到跳板）

`.boot.ap_code` 里的 `ap_start` 是 16 位实模式入口，落在拷贝后的 PA `0x1000`。它本地有一份给保护模式用的临时 GDT，开 PE 后进 32 位，再走与 BSP 相同的 PAE/LME/CR3/PG，最后 `call start_secondary_cpu`。谁负责 `memcpy` 跳板、谁写 `ap_boot_stack_ptr` / `cpu_id`、谁发 INIT-SIPI，见 SMP 篇。

### 6.4 全局只做一次的 C 钩子

`prepare_arch`：把 `phy_addr_width` 抄到全局 `max_phy_addr_width`；只认 Multiboot1 / Multiboot2 magic；有 cmdline 就把 `cmdline_ptr` 指过去（MB1：物理 cmdline 经 `KERNEL_PHY_TO_VIRT`；MB2：string tag 已在虚地址空间）。**这里不读 memmap，也不找 RSDP**——那两件事在 `phy_mm_init` → `arch_init_pmm`：可用区且起点超过 1 MiB 才插入 buddy；RSDP 写回 `setup_info->rsdp_addr`。

`arch_cpu_info`：参数不用。`get_cpu_info` 用若干 CPUID 叶填全局 `cpu_info`（厂商串、APIC ID、SSE/AVX 相关 feature、扩展叶地址宽度等），然后 `BSP_ID = APIC ID`。core **不追求**把所有 CPUID 叶扫全；上层若要更细的特征，需自己再维护。

`arch_start_platform`：必须在 `virt_mm_init` 之后。`acpi_init(rsdp_addr)`，再用 BSP 的 `kallocator` 分配 PCI 根节点并 `pci_scan_all`。失败把错误码交给 `cmain`。AP 不会再进这个函数。

### 6.5 每个核：`arch_start_core(cpu_id)`

BSP 由 `cmain` 调，AP 由 `start_secondary_cpu` 调。大致顺序：

1. 为本核准备 GDT 并 `lgdt`（用户数据段排在用户代码段前面，是为了 `IA32_STAR` 的段索引约定）；写 `MSR_KERNEL_GS_BASE = 0`；`cpu_number = cpu_id`；装本核 TSS。
2. `init_interrupt` → `init_irq`（优先 x2APIC，否则 xAPIC，再否则 8259；依赖 MADT 已在平台阶段解析）→ `smp_ipi_init` → TLB flush 初始化。
3. `init_syscall`：写 `IA32_STAR`、`IA32_FMASK = 0x200`（屏蔽 IF）、`LSTAR` 入口。
4. 开中断，`rendezvos_time_init`，空的 `enable_cache`，CR0 置 `MP`/`NE`，再按 `cpu_info` 决定是否打开 SSE/AVX（CR4 `OSFXSR`/`OSXMMEXCPT`，可选 `OSXSAVE` 与 XCR0）。SIMD 失败只打印。

线程和 port **不在**本函数里创建；那些属于 `cmain` / initcall 之后的可移植路径。

## 7. 公开 API

本篇拥有的 C 接口在 `include/arch/x86_64/boot/arch_setup.h`（实现 `arch/x86_64/boot/start_arch.c`）。说明与该头注释一致，并已与实现核对。`boot.S` 入口仅由 Multiboot 装载器 / 跳板进入，无公开 C 头（装载与入口约定见 §6.1–§6.3）。`arch_start_smp` 见 SMP 篇；`arch_enable_percpu` 见 per-CPU 篇；memmap/RSDP 的 `arch_init_pmm` 见物理内存篇。

### 7.1 编排顺序（`cmain` / AP，与源码一致）

| 调用方 | 本篇相关顺序 |
|--------|----------------|
| BSP `cmain` | … → **`prepare_arch`** → `phy_mm_init` → `arch_enable_percpu` → **`arch_cpu_info`** → `virt_mm_init` → **`arch_start_platform`** → **`arch_start_core(BSP_ID)`** → … |
| AP `start_secondary_cpu` | … → **`arch_start_core(cpu_id)`** → …（**不**再 `prepare_arch` / `arch_cpu_info` / `arch_start_platform`） |

### 7.2 `setup_info` 与 Multiboot 访问

```c
struct setup_info { /* packed；须与 boot.S .boot.data 一致 */
        u32 multiboot_magic;              /* 0x0 */
        u32 multiboot_info_struct_ptr;    /* 0x4 物理地址 */
        u32 phy_addr_width;               /* 0x8 */
        u32 vir_addr_width;               /* 0xc */
        vaddr rsdp_addr;                  /* 0x10 入口为 0；arch_init_pmm 填写 */
        vaddr ap_boot_stack_ptr;          /* 0x18 通用，见总览 §4.1.1 */
        cpu_id_t cpu_id;                  /* 0x20 通用，见总览 §4.1.1 */
};
struct multiboot_info  *GET_MULTIBOOT_INFO(struct setup_info *);
struct multiboot2_info *GET_MULTIBOOT2_INFO(struct setup_info *);
```

| 项 | 说明 |
|----|------|
| `GET_MULTIBOOT_*` | 把 info 的**物理**指针加上 `KERNEL_VIRT_OFFSET` 得到可解引用的内核 VA（高半映射已开之后）。 |
| `BIOS_MEM_UPPER` | `0x100000`；buddy 可用区下限（物理内存篇消费）。 |
| Multiboot 结构体 | 协议字段定义在 `multiboot.h` / `multiboot2.h`，本篇不逐字段当「调用 API」展开。 |

### 7.3 可移植钩子（x86 实现语义）

```c
error_t prepare_arch(struct setup_info *arch_setup_info);
error_t arch_cpu_info(struct setup_info *arch_setup_info);
error_t arch_start_platform(struct setup_info *arch_setup_info);
error_t arch_start_core(cpu_id_t cpu_id);
```

| 接口 | 说明 |
|------|------|
| `prepare_arch` | 抄 `phy_addr_width` → `max_phy_addr_width`；只认 MB1/MB2 magic；可选设置 `cmdline_ptr`（MB1：`KERNEL_PHY_TO_VIRT(cmdline)`；MB2：cmdline string tag）。**不**读 memmap、**不**找 RSDP。成功返回 `0`；magic 不对 → `-E_RENDEZVOS`（`cmain` panic）。 |
| `arch_cpu_info` | 参数未用。`get_cpu_info()` 填全局 `cpu_info`，再 `BSP_ID = APIC ID`。恒返回 `REND_SUCCESS`。 |
| `arch_start_platform` | **全机一次**，须在 `virt_mm_init` 之后。`acpi_init(rsdp_addr)` → 用 `per_cpu(kallocator, BSP_ID)` 分配 `pci_root` → `pci_scan_all`。返回 ACPI/PCI 错误码。AP 不得调用。 |
| `arch_start_core` | **每核一次**。体内顺序见头文件 / §6.5（GDT/TSS → IRQ/IPI/TLB → syscall MSR → 开中断 → 时间 → FP/SIMD）。恒返回 `0`；SIMD 探测失败只 `pr_error`，不令本函数失败。不建线程/port。 |

### 7.4 本篇源码但不列入本 §7 的符号

| 符号 | 归属 |
|------|------|
| `bsp_entry` / `x86_64_entry` / `ap_start`（`boot.S`） | 装载器 / SIPI 跳入；无 C 声明头 |
| `arch_start_smp`（`smp.h`） | SMP 篇 §7 |
| GDT 下标等（`desc.h`） | `arch_start_core` 内部与 syscall `IA32_STAR` 约定；非独立「启动编排」导出 |

## 8. 多架构

仅 x86_64。与 aarch64 对照时，差别集中在：引导协议（Multiboot + BIOS 区 RSDP，而不是 Image + DTB）；`BSP_ID` 来自 APIC ID（不是固定 0）；AP 需要低地址 16 位跳板。交给 `cmain` 的四个钩子名字与参数相同。
