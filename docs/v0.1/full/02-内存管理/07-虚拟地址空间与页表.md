## 1. 概述

本层回答两个问题：**怎样修改任意地址空间里的页表项**，以及 **`VSpace` 对象如何承载一棵硬件页表**。某段虚拟地址属于哪个用户映射，由 radix 记账（见 `08-Radix树与用户映射.md`）；本层的 `map` / `unmap` 只是改 PTE 的工具。

核心机制是每核一份 **`Map_Handler` 临时窗口**：要修改哪张物理页（尤其是**页表页本身**），就把它临时映射到固定的高地址槽位，改完再卸下。这不是 Linux 那种「启动时把全部 RAM 线性映射进 direct map」，也不是递归 PML4 self-map。

为什么这么选：若一开始就把物理内存和所有页表帧永久映射满，调试期的 UAF、错指针更容易「碰巧还能读到」；修改其他地址空间的页表也会更别扭。代价是多几次 `util_map` 和本地 TLBI；换来的是可调试，且页表帧默认不出现在线性映射里。内核**内容页**仍可以走 `KERNEL_PHY_TO_VIRT` + `map()` 建立线性 PTE；**中间级页表页**通常只走窗口。旧稿若写成「完全没有高半线性」就说过头了——分清内容页和页表页即可。

记一个反例：A 核 `unmap` 了用户页，B 核 TLB 里还有旧项——若没有按 `tlb_cpu_mask` 做 shootdown，「卸映射即 fault」就不成立。细节见 TLB 篇。

## 2. 目标与边界

提供：`VSpace` 生命周期骨架；`sys_init_map` / `virt_mm_init`；`map` / `unmap` / `have_mapped`；Map_Handler 槽位与零页、拷贝辅助；内核恒等区间组合层 `ensure_kernel_identity_range` / `map_kernel_identity_empty_range` / `unmap_kernel_identity_range`（无 radix）；以及与 arch 的标志编解码。

不做：用户 VMA 策略（那是 radix / 兼容层的事）；完整 COW 语义（`clone_vspace` 的标志约束见 radix / 线程篇）；IOMMU；堆页的 radix+map 编排（仍在 `kmalloc` / `core_get_free_pages`）。

失败策略单独说明：`map` 中途缺少中间级表时，可以从 `ppn_cache` 补给；失败路径 **不回滚** 已经生成的内核页表页（源码注释的理由：内核增长有界，用户侧靠进程退出拆除）。泄漏算上层 bug，不要指望本层自动清理。

## 3. 分层与调用方

时间顺序大致是：boot 的 `L0_table` 提供最早可用的映射；BSP 的 `sys_init_map` 挂上永久的 MAP_L1→L2→L3 链，并预创建高半全部 L1；每核 `Map_Handler` 用临时 4 槽访问任意物理页；随后 `map` / `unmap` 持 `vspace_lock` 修改任意 `VSpace`；radix / 兼容层决定「映射什么」，再调本层写入 PTE。

组合层（都在 `map`/`have_mapped` 之上，互不替代）：

| 层 | 对象 | 是否 radix |
|----|------|------------|
| `mm_user_utils` | 用户 VA | 是（+ 常 PMM） |
| `mm_kernel_utils` | 内核恒等 `KERNEL_PHY_TO_VIRT(phy)` | **否**（不是任何 zone 分配器交出的 PA：固件表 / MMIO 等） |
| `kmalloc` / `core_get_free_pages` | 堆页 → 恒等 VA | 是（某 zone 的 `pmm_alloc` + bind/rmap；默认 buddy） |

调用方须注意：MCS 的 `me` 用 **本核** handler 上的节点；窗口已被占用时，不要在同一份 handler 上嵌套使用（头文件有说明）。

## 4. 数据结构与不变量

### 4.1 窗口几何与「为何四槽」

先建立四级页表遍历的直观模型（x86_64 与 aarch64 主线都是 4 KiB granule、每级 9 bit 索引）：

```text
   VA:  47─────39 38─────30 29─────21 20─────12 11────────0
        ┌─────────┬─────────┬─────────┬─────────┬──────────┐
        │ L0 idx  │ L1 idx  │ L2 idx  │ L3 idx  │  offset  │
        │  9 bit  │  9 bit  │  9 bit  │  9 bit  │  12 bit  │
        └────┬────┴────┬────┴────┬────┴────┬────┴──────────┘
             │         │         │         │
             ▼         ▼         ▼         ▼
            L0        L1        L2        L3          物理页帧
          (PML4)   (PDPT)     (PD)      (PT)         (4 KiB)
           表页      表页      表页      表页
             │         │         │         │
             ▼         ▼         ▼         ▼
          [root]──→ [L1]──→ [L2]──→ [L3]──→ PPN+offset
         根页帧    中间级页表页            叶 PTE
```

一次 `map` 要同时访问 **L0 / L1 / L2 / L3 四张不同的物理页表页**——这就是窗口「四槽并行」的原因。

基址是 `map_pages`（`0xFFFFFFFFFFE00000`）——**一整段 2 MiB**，由一张 L2 项指向整页填充的 `MAP_L3_table`。每个 CPU 在这段里占 **连续 4×4 KiB 槽**（共 16 KiB），不是「每核独占 2 MiB」。按 4 槽计，容量上限可以精确算出：2 MiB / 16 KiB = **128 个 CPU**；`NR_CPUS` 与 `RENDEZVOS_MAX_CPU_NUMBER` 都以此为约束，超过就要扩窗口或减槽数。

这不是 Linux 式 direct map，也不是「递归 PML4 自映射」：改页表页时，要把**那张物理页**临时映射到固定高地址槽，改完可卸下。四级页表一次 `map` 可能同时访问 L0/L1/L2/L3 **四张不同物理页**——若只有一槽反复 remap，中间级指针还没写稳就丢窗口，或嵌套 `map` 时把自己踩掉。故每核固定 **4 槽并行**：

```text
槽 0 → 当前访问的 L0 表页
槽 1 → L1
槽 2 → L2
槽 3 → L3（叶）
```

下图把 `map_pages` 整段布局与一次 `map` 的窗口使用画在一起：

```text
   高地址
   0xFFFF_FFFF_FFE0_0000  ┌───────────────────────────────────────┐
     map_pages (2 MiB)     │  MAP_L1 ──→ MAP_L2 ──→ MAP_L3_table   │
                           │  (sys_init_map 永久挂好的骨架)          │
                           └───────────────────────────────────────┘
                                          ▲
                                          │ 运行期 util_map 只改
                                          │ MAP_L3 槽项（指向目标物理页）
   ┌──────────┬──────────┬──────────┬──────────┬─────────┐
   │  CPU 0   │  CPU 1   │  CPU 2   │  CPU 3   │   ...   │  每核 4×4 KiB
   │ slot 0-3 │ slot 0-3 │ slot 0-3 │ slot 0-3 │         │  = 16 KiB
   └─┬─┬─┬─┬──┴──────────┴──────────┴──────────┴─────────┘
     │ │ │ │
     │ │ │ └─ slot 3 ──→  L3 表页（要写入的叶 PTE 所在物理页）
     │ │ └─── slot 2 ──→  L2 表页
     │ └───── slot 1 ──→  L1 表页
     └─────── slot 0 ──→  L0 表页（含 va 的 L0 项）

   CPU 经 slot 0/1/2 沿树向下读出下一级表页物理地址，
   再用对应 slot 把该物理页临时映射进窗口、写入新项，
   改完卸下窗口（本地 TLBI）——页表帧默认不被永久线性访问。
```

`sys_init_map` 永久挂好 `MAP_L1→L2→L3` 链（整段 `map_pages` 的骨架）；运行期 `util_map` 只改已经落在镜像映射里的 **`MAP_L3_table` 槽项**。`mapped_ppn[i]` 命中同一物理页时可跳过重写和 TLBI；`ppn_cache` 则缓存「刚从 buddy 拿来、马上要装进中间级」的页，减少窗口颠簸。

`map_util_page.S` 只是给 `MAP_L*` 做 **bss 占位**，没有运行时 helper。每核真正使用的是 `struct map_handler`（`DEFINE_PER_CPU`，`vmm.c`）：

```c
#define map_pages 0xFFFFFFFFFFE00000

struct map_handler {
        cpu_id_t cpu_id;
        vaddr map_vaddr[4];
        ppn_t ppn_cache[4];
        ppn_t mapped_ppn[4];
        struct pmm *pmm;
        spin_lock_t vspace_lock_node;
};
```

槽的惯例：`map` 走 L0…L3 用槽 0…3；`copy_data_range` 用 **0 与 2**（避开相邻页越界冲突）；简单 zero 常用槽 0。

### 4.2 `VSpace`

`VSpace` 包含根页帧、`asid`、`tlb_cpu_mask`、`vspace_lock`（MCS）、radix、注册用的红黑树节点等。`root_vspace` 由 BSP 的 `init_root_vspace` 从**当前**内核根读出，再挂上共享的内核高半；`vspace_lock` 初值为空，永不 `del`。

```c
struct VSpace {
        asid_t asid;
        u16 asid_padding;
        bool registered;
        struct pmm *pmm;
        ref_count_t refcount;
        vs_tlb_cpu_bitmap_t tlb_cpu_mask;
        cas_lock_t tlb_cpu_mask_lock;
        spin_lock vspace_lock;
        void *root_radix; /* L0：Radix_entry_t *，见 08 */
        paddr vspace_root_addr;
        union {
                struct { /* root_vspace */
                        struct list_entry root_manage_list_head;
                        struct rb_root _vspace_rb_root;
                        cas_lock_t vspace_register_lock;
                };
                struct { /* 普通地址空间 */
                        struct rb_node _vspace_rb_node;
                        VSpace *root_vs;
                };
        };
};
```

### 4.3 仅 BSP 存活时才能做的页表准备

`sys_init_map` 只在还只有 BSP 这一核时调用：挂好 `map_pages` 那条链；对空的高半 `L0[256..511]` **预分配全部 L1**。注释里的动机是：运行期没法向所有已存在的地址空间广播「又多了一条新的 L0 项」。编辑 boot 的 L0 时可以经已有的 `KERNEL_PHY_TO_VIRT(root)`——这是窗口规则在自举阶段的例外，多核启动后不能再这么干。

### 4.4 页表改写约定

`map` 及同类路径须遵守：

- 叶 level 只允许 **2（2 MiB）或 3（4 KiB）**。
- 同一 PPN 且已 VALID：可以只改 flags（类似 mprotect）；要换 PPN 必须带 `PAGE_ENTRY_REMAP`，禁止静默偷页。
- 软件位 `LAZY | COW | REMAP` 在写进硬件页表前会被清除（`entry_flags_rm_sw_flags`）。
- 缺中间级：从 `ppn_cache` 取页、装上 `nonfinal` 标志（含 USER，以便用户地址能继续向下遍历树）、在窗口里 memset。
- 缺 root：直接失败——调用方须先 `new_vs_root`。

### 4.5 可移植标志与硬件页表项：encode / decode

可移植层（`map` / `unmap` / `have_mapped`）只使用 `ENTRY_FLAGS_t`（`include/common/mm.h`）。真正写进页表的是各 ISA 的 `ARCH_PFLAGS_t`。

```c
enum ENTRY_FLAGS {
        PAGE_ENTRY_NONE = (1ULL << 0),
        PAGE_ENTRY_VALID = (1ULL << 1),
        PAGE_ENTRY_WRITE = (1ULL << 2),
        PAGE_ENTRY_READ = (1ULL << 3),
        PAGE_ENTRY_EXEC = (1ULL << 4),
        PAGE_ENTRY_USER = (1ULL << 5),
        PAGE_ENTRY_DEVICE = (1ULL << 6),
        PAGE_ENTRY_UNCACHED = (1ULL << 7),
        PAGE_ENTRY_GLOBAL = (1ULL << 8),
        PAGE_ENTRY_HUGE = (1ULL << 9),
        PAGE_ENTRY_LAZY = (1ULL << 61),  /* 软件位，写硬件前剥掉 */
        PAGE_ENTRY_COW = (1ULL << 62),
        PAGE_ENTRY_REMAP = (1ULL << 63),
};
typedef u64 ENTRY_FLAGS_t;
typedef u64 ARCH_PFLAGS_t;
```

对应关系由 arch 的两个函数完成（`arch/*/mm/vmm.c`）：

- **`arch_decode_flags(level, ENTRY_FLAGS)`**：产出 `ARCH_PFLAGS`（可移植编成硬件），供 `arch_set_L*_entry` 写入。
- **`arch_encode_flags(level, ARCH_PFLAGS)`**：产出 `ENTRY_FLAGS`（硬件解回可移植），供 `have_mapped` 等读回。

写页时的典型顺序是：先清除软件位，经 `decode` 得到硬件标志，再交给 `arch_set_L*_entry(paddr, vaddr, table, flags)` 写入（把物理地址按该级掩码写入描述符，并或上 flags）。四级索引宏 `L0_INDEX`…`L3_INDEX` 在现行主线各 ISA 上都是 VA 每级 9 bit，与「4 KiB granule / 4-level」模型对齐。

#### x86_64（Intel SDM Vol. 3A，Paging / IA-32e）

四级叫 PML4E、PDPTE、PDE、PTE。本实现常用位（定义在 `page_table_def.h`）：

| 可移植 | 硬件位（各级同名语义） |
|--------|------------------------|
| VALID | `P` |
| WRITE | `RW`（可读总是隐含的；无单独「只读可读」位，靠不置 RW） |
| EXEC 取反 | `XD`（需 boot 已开 `IA32_EFER.NXE`） |
| USER | `US` |
| DEVICE / UNCACHED | `PCD \| PWT`（粗粒度；未接入 PAT 精细表） |
| HUGE | L1：`PDPTE.PS`（1 GiB）；L2：`PDE.PS`（2 MiB）；L0/L3 无 |
| GLOBAL | 大页上的 `G`，或 PTE 的 `G`（依赖 `CR4.PGE`） |

地址字段用 `PML4E_ADDR` / `PDPTE_ADDR` / `PDE_ADDR` / `PTE_ADDR`，并按 `max_phy_addr_width`（来自启动时 CPUID）裁剪，对应手册里的 MAXPHYADDR。

#### aarch64（ARM ARM，VMSAv8-64 描述符）

四级描述符：L0–L2 可以是 **table** 或 **block**，L3 是 **page**。有效位是 `PT_DESC_V`；table/page 与 block 靠 bit1 等区分（本实现用 `PT_DESC_BLOCK_OR_TABLE` / `PT_DESC_PAGE`）。叶属性分 lower / upper：

| 可移植 | 硬件侧 |
|--------|--------|
| VALID / READ | 置 `V`；decode 里用 READ 决定有效 |
| WRITE 取反 | 叶上 `AP[RO]` |
| USER | `AP[EL0]`；用户可执行看 `XN`，内核可执行看 `PXN`（与 EL0/EL1 执行权限模型对应） |
| DEVICE / UNCACHED / Normal | `AttrIndx` 索引到 `MAIR_EL1` 槽（`MEM_ATTR_*`）；boot 的 `mair_init` 先写好 MAIR |
| HUGE | **不**置 table/page 的「下一级」形态，保留 block（L1/L2） |
| GLOBAL 取反 | 叶上 `nG`（非全局，才与 ASID 绑定） |
| （叶） | 常置 `AF`，配合 TCR 的硬件 AF 更新 |

手册出处：Intel SDM 的页表项位图与 PS/G/XD；ARM ARM 的 Stage 1 EL1&0 描述符、AP/XN/PXN、AttrIndx 与 MAIR。本篇不抄完整表格，只固定「可移植标志 ↔ 本仓库宏」这层对应；改权限时先改 `ENTRY_FLAGS`，再由 decode 生成硬件位，避免在 `map_handler.c` 里直接写 `PTE_RW` 之类。

## 6. 流程

### 6.1 `virt_mm_init`

`cmain` 在 BSP 上调用 `virt_mm_init(BSP_ID, setup_info)`。当 `cpu_id == BSP_ID` 时，构建整机的 `sys_init_map`、ASID 子系统和 `root_vspace`；本核栈底取链接脚本里的 `boot_stack`，不用 `setup_info`。AP **不**建 root；栈底取 `setup_info->ap_boot_stack_ptr`——所以 AP 若传入空指针会直接失败。

BSP 与 AP 都会 `init_map` 本核 Map_Handler，把 `current_vspace` 指向同一份 `root_vspace`，并通过 `kinit` 建立本核内核堆。返回成功之后才有可用的 `kallocator`。`cmain` 把 `arch_start_platform` 排在这之后，就是因为平台对象要从这份堆上分配。

对照一下：

- `sys_init_map` / `asid_init` / `init_root_vspace`：只 BSP。
- `init_map`（槽 + `ppn_cache`）、指向 `root_vspace`、`kinit`：BSP 与 AP 都做。
- 栈底：BSP 用链接 `boot_stack`；AP 用 `ap_boot_stack_ptr`。

AP **不会**在这个函数里「重新挂一遍内核映射」——SMP 路径已经共用 boot 根表；这里只建本核的 Map_Handler 状态，并指向共享的 `root_vspace`。

### 6.2 `map` / `unmap` 与 TLB

全程持有 `lock_mcs(&vs->vspace_lock, &handler->vspace_lock_node)`。整棵树只用一把锁：新建表页、memset 这类步骤无法与细粒度锁交错编排。

本层对 TLB 的策略大致是：

- **首次 map（new）**：只做本地 invalidate（假定他核还没有缓存这个 VA）。
- **改映射 / unmap**：按内核 / 用户分别广播到所有核；用户侧按 `tlb_cpu_mask` 广播（x86 走 IPI；aarch64 细节见 TLB 篇）。
- 窗口槽变更：本地 kernel-page invalidate。

### 6.3 与内存栈其它层

Zone 内物理页由该 zone 的 `pmm` 分配（默认 buddy），Map_Handler 负责改 PTE，用户/堆语义由 radix 记账；kmalloc 对堆内容页走恒等 VA + radix bind。固件表、MMIO 等**不经任何 zone 分配器**拿到的 PA 走 `mm_kernel_utils`（只建 PTE，无 radix/rmap）。调度时换硬件 AS 并维护 `tlb_cpu_mask`（见所有权篇）。

### 6.4 内核恒等区间三件套（无 mode）

对 `[phy, phy+len)` 按 4 KiB 步进，VA=`KERNEL_PHY_TO_VIRT`；**从不**新建 2 MiB 叶。按生命周期选函数，不靠开关：

| 函数 | 用途 | 已有映射 | 空洞 | 失败时 |
|------|------|----------|------|--------|
| `ensure_kernel_identity_range` | 开机常驻（ACPI **表**、IOAPIC MMIO 等） | 恒等 L2/L3 → 跳过；非恒等 → 失败 | 装 4 KiB + eflags | **不**回滚；上层放弃子系统/启动 |
| `map_kernel_identity_empty_range` | 全空才装（驱动窗等） | **任一页已在 → 整段失败、不装** | 预检 `++` 至 `page_end` 后 `--` 装 4 KiB | `fail_unmap_rollback`：从失败页再 `++` 卸已装页 |
| `unmap_kernel_identity_range` | 配对 empty 的拆卸 | L3 恒等 → 卸；空洞跳过；L2/非恒等 → log 并继续 | — | 尽力清理；返回负错误码；不崩内核。卸不干净则下次 empty 装不上（保险丝） |

`ensure_*` **不**提供业务 unmap（固件常驻）。已有叶的 flags 在 ENSURE 下不校验、不改写。Device 等属性由调用方传入的 `eflags` 表达，函数名不绑定「MMIO」。

**并发：** 本层**不再**为「这段 PA」加第二把锁，只依赖下层 `vspace_lock`；同一物理区间约定由调用方互斥。empty 预检、ENSURE 跳过都**不能**代替互斥。

**与 ACPI / IOAPIC：** legacy probe 自行 ensure 探测窗；`acpi_init()` ensure RSDT/子表（见 ACPI 篇）；`ioapic_init` ensure 各 IOAPIC MMIO（UNCACHED/DEVICE 等由 `eflags`，见 APIC 篇）。空槽只认 `!PAGE_ENTRY_VALID`（`have_mapped` / `map`）；`ppn==0` 为合法已映射。`ensure` 仅在 `-E_REND_NOFOUND` 时去 `map`，其它 `have_mapped` 负错误原样返回。

## 7. 公开 API

本篇涉及的接口分布在：`include/rendezvos/mm/vmm.h`、`include/rendezvos/mm/map_handler.h`、`include/rendezvos/mm/mm_kernel_utils.h`（实现于 `kernel/mm/vmm.c`、`map_handler.c`、`mm_kernel_utils.c`）。接口说明以头文件注释为准。用户映射语义记账见 radix 篇；TLB shootdown 见 TLB 篇；调度换根见 VSpace 所有权篇。

**注意：** 旧稿 §7 签名有误（`map` 参数顺序、`create_vspace` 无参、`have_mapped` 写成 bool 等）；以下以当前头文件为准。

### 7.1 编排顺序（与源码一致）

| 路径 | 顺序 |
|------|------|
| BSP `virt_mm_init` | 依次 **`sys_init_map(pmm)`**、**`init_map`(本核)**、`asid_init`、**`init_root_vspace`**，再设 `current_vspace=&root_vspace` 并 `kinit` |
| AP `virt_mm_init` | **`init_map`**（**不**再 `sys_init_map` / root）；栈底取 `ap_boot_stack_ptr`；其后同 BSP 设 `current_vspace` 并 `kinit` |
| 用户 AS 创建 | **`create_vspace(pmm)`** 后 **`register_vspace(vs, &root_vspace)`**；拆除收尾先 **`unregister_vspace`**，末次 ref 落到 **`del_vspace`** |
| 改 PTE | 持 `vspace_lock`（经 handler 的 MCS `me`）调 **`map` / `unmap` / `have_mapped`**；handler 一般为 `&percpu(Map_Handler)` |

### 7.2 初始化

```c
error_t virt_mm_init(cpu_id_t cpu_id, struct setup_info *arch_setup_info);
error_t sys_init_map(struct pmm *pmm);           /* 仅 BSP */
error_t init_map(struct map_handler *h, cpu_id_t cpu_id, struct pmm *pmm);
error_t init_root_vspace(VSpace *root_vs, cpu_id_t cpu_id);
```

| 接口 | 说明 |
|------|------|
| `virt_mm_init` | `phy_mm_init` 之后、每核调用。BSP 建窗口树+root；AP 只 `init_map`，且 `arch_setup_info` 不得为 NULL。失败返回负 `error_t`。 |
| `sys_init_map` | 把 `map_pages` 永久挂上 MAP_L1→L2→L3，并预分配高半 L0[256..511] 的 L1 页。 |
| `init_map` | 为本核填 4 个槽的 VA（`cpu_id*4`）与 `pmm` / MCS 节点。 |

### 7.3 页表改写（`map_handler.h`）

```c
error_t map(VSpace *vs, ppn_t ppn, vpn_t vpn, int level,
            ENTRY_FLAGS_t eflags, struct map_handler *handler);
ppn_t   unmap(VSpace *vs, vpn_t vpn, u64 new_entry_addr,
              struct map_handler *handler);
ppn_t   have_mapped(VSpace *vs, vpn_t vpn, ENTRY_FLAGS_t *flags_out,
                    int *level_out, struct map_handler *handler);
```

| 接口 | 说明 |
|------|------|
| `map` | `level`：2=2 MiB，3=4 KiB。已有 VALID 叶：ppn 相同则只改 flags（mprotect）；ppn 不同则需 `PAGE_ENTRY_REMAP`，否则失败。缺中间表可从 `ppn_cache` 补给；**失败不回滚**已生成的内核 PT 页。软件位（REMAP/LAZY/COW…）写入前清除。 |
| `unmap` | 成功返回原先叶上的 ppn（**含 0**）；未映射或走页/参数失败返回负值（`invalid_ppn`）。`new_entry_addr` 只写入叶描述符的 **paddr 字段**，条目保持无效——这不是写入有效叶 PTE，也不是 remap（见 `map_handler.h`）。 |
| `have_mapped` | `>=0`=已映射 ppn（**含 0**）；`<0`=未映射（`-E_REND_NOFOUND`）或存在错误。可选输出 flags / level。只通过 `!PAGE_ENTRY_VALID` 来判定空，不以 paddr/ppn 是否为 0 判空。 |

窗口辅助（物理页 ↔ 临时 KVA，与当前 CR3/TTBR 无关）：

```c
vaddr map_handler_map_slot(struct map_handler *, int slot_id, ppn_t);
void  map_handler_unmap_slot(struct map_handler *, int slot_id);
error_t map_handler_zero_page(struct map_handler *, ppn_t);
error_t map_handler_copy_data_range(struct map_handler *, paddr dst, paddr src, u64 len);
error_t map_handler_copy_page(...); /* inline，整页交给 copy_data_range */
error_t map_handler_user_kernel_copy(VSpace *, u64 user_va, void *kbuf, size_t, bool to_user);
paddr new_vs_root(paddr old_vs_root_paddr, struct map_handler *);
```

`new_vs_root`：恒填内核半模板；`old==0` 清空用户半，非 0 则浅拷贝用户半 L0 指针（**不是**完整 clone/COW）。

### 7.4 内核恒等区间（`mm_kernel_utils.h`）

```c
error_t ensure_kernel_identity_range(VSpace *vs, paddr phy, size_t len,
                                     ENTRY_FLAGS_t eflags,
                                     struct map_handler *handler);
error_t map_kernel_identity_empty_range(VSpace *vs, paddr phy, size_t len,
                                        ENTRY_FLAGS_t eflags,
                                        struct map_handler *handler);
error_t unmap_kernel_identity_range(VSpace *vs, paddr phy, size_t len,
                                    struct map_handler *handler);
```

| 接口 | 说明 |
|------|------|
| `ensure_kernel_identity_range` | 常驻 ENSURE；半截已映射合法；新叶须 `PAGE_ENTRY_VALID`；不改已有 flags；无 radix/rmap。ACPI 探测窗/表区与 IOAPIC MMIO 均用此。 |
| `map_kernel_identity_empty_range` | 全空才装；单游标 `++` 预检 / `--` map / 失败再 `++` 回滚；无 radix/rmap。 |
| `unmap_kernel_identity_range` | 尽力卸 L3；遇 L2/非恒等只报错并继续；配对 empty，不用于 `ensure_*`。 |

细节与参数说明以 `mm_kernel_utils.h` 为准。

### 7.5 `VSpace` 生命周期（`vmm.h`）

```c
VSpace *create_vspace(struct pmm *pmm);
error_t clone_vspace(VSpace *src, VSpace **dst_out, enum vspace_clone_flags flags);
error_t register_vspace(VSpace *vs, VSpace *root_vs);
error_t unregister_vspace(VSpace *vs);
error_t del_vspace(VSpace **vs);
error_t vspace_clear_user_mappings(VSpace *vs, struct map_handler *h, bool allow_self_use);
```

| 接口 | 说明 |
|------|------|
| `create_vspace` | 分配结构 + 空 L0 + radix + 共享内核高半；失败返回 NULL。之后须 `register_vspace`。 |
| `clone_vspace` | 必须 `VSPACE_CLONE_F_USER_4K_ONLY`，且 **恰好其一**：`COW_PREP` 或 `COPY_PAGES`。细节见 radix/线程篇。 |
| `register` / `unregister` | 挂入/移出 root 的 RB 表；unregister 对未注册的 vs 也返回成功（幂等）。 |
| `vspace_clear_user_mappings` | 清用户低半，保留对象/ASID/根帧/内核半；exec 原地清表时传 `allow_self_use=true`。禁止对 `root_vspace` 调用。 |
| `del_vspace` | 末次引用路径依次完成 clear、毁 radix、放根页、放结构/ASID；`*vs=NULL`。须先 unregister。 |

标志编解码：`arch_decode_flags` / `arch_encode_flags`（§4.5）。`tlb_cpu_mask` 辅助 inline 见头文件；shootdown 约定见 TLB 篇。

## 8. 多架构

页表项位级对照与 encode/decode 见 §4.5。这里只补「根寄存器怎么装」：

```text
   x86_64：单根 CR3，内核/用户同树靠 VA 高/低半区分
   ┌─────────────────────────────────────────┐
   │  VA  0x7FFF_FFFF_FFFF ── 用户低半       │  ← PML4E[0..255]
   │                       (per-VSpace)      │
   ├─────────────────────────────────────────┤
   │  VA  0xFFFF_8000_0000_0000 ── 内核高半  │  ← PML4E[256..511]
   │                       (所有 VSpace 共享) │  GLOBAL 叶在 CR4.PGE 下可跨 CR3 保留
   └─────────────────────────────────────────┘
                  ↑ CR3 指向 PML4 物理地址

   aarch64：双 TTBR，内核/用户分根
   ┌─────────────────────────────────────────┐
   │  TTBR0_EL1 ── 用户低半（带 ASID 高 16 位）│  ← L0[0..255]
   │                       (per-VSpace)      │
   ├─────────────────────────────────────────┤
   │  TTBR1_EL1 ── 内核高半（共享）          │  ← L0[256..511]
   └─────────────────────────────────────────┘
   TCR_EL1.T0SZ/T1SZ 决定两半边界；nG 位决定是否随 ASID 生效
```

- **x86_64**：一个地址空间一根 **CR3**（PML4 物理地址）。内核与用户同树时靠高半/低半 VA 区分；GLOBAL 叶在 `CR4.PGE` 下可跨 CR3 保留。
- **aarch64**：EL1&0 下 **TTBR1** 管高半（内核）、**TTBR0** 管低半（用户），用户根常把软件 ASID 写入 TTBR0（见 ASID 篇）。可移植 API 仍填「内核半」相关标志，以在各 ISA 间保持调用约定一致；真正的切换语义在 arch 装根路径里。

四级各 9 bit 索引的宏，各 ISA 的 vmm 头共用同一套命名。riscv / loongarch 无主线实现。

## 10. 限制与后续

- 整树一把 MCS，并发 `map` 吞吐有限。
- `map` 失败不回滚已生长的内核 PT。
- x86「内核页 all-core」是否真广播，以源码为准（注释更倾向 percpu 路径）。
- x86 的 DEVICE/UNCACHED 都打成 PCD|PWT，未接入 PAT；aarch64 依赖 boot 已初始化的 MAIR。
- 槽位计算与 `NR_CPUS` 上限要一起核对。
- TLB / ASID 的硬件手册对照见 `11` / `12` 篇（后续加强时补 invlpg、`tlbi`、TTBR.ASID、PCID 等）。
