## 1. 概述

本层回答两件事：**怎么改任意地址空间里的页表项**，以及 **`VSpace` 对象怎样承载一棵硬件页表**。用户映射的语义记账在 radix；这里的 `map` / `unmap` 是改 PTE 的工具。

核心机制是每核一份 **`Map_Handler` 临时窗口**：要把哪张物理页（尤其是**页表页本身**）拿出来改，就临时映进固定高址槽，改完可以卸掉。这不是 Linux 式「启动时把全部 RAM 线性映进 direct map」，也不是递归 PML4 self-map。

这样选是因为：若一开始就把物理内存 / 所有页表帧永久映满，调试期的 UAF、错指针更容易「碰巧还能读」；跨地址空间改别人的表也会更别扭。代价是多几次 `util_map` 和本地 TLBI；换来的是可调试性，以及「页表帧默认不可线性访问」。内核**内容页**仍然可以走 `KERNEL_PHY_TO_VIRT` + `map()` 建线性 PTE；**中间级页表页**通常只走窗口。旧稿若写成「完全没有高半线性」就说过头了——分清内容页和 PT 页即可。

反例要记在心上：A 核 `unmap` 了用户页，B 核 TLB 里还有旧项——若没有按 `tlb_cpu_mask` 做 shootdown，「卸映射即 fault」就不成立。细节在 TLB 篇。

## 2. 目标与边界

提供：`VSpace` 生命周期骨架；`sys_init_map` / `virt_mm_init`；`map` / `unmap` / `have_mapped`；Map_Handler 槽与零页 / 拷贝辅助；与 arch 标志编解码。

不做：用户 VMA 策略（那是 radix / 兼容层的事）；完整 COW 语义（`clone_vspace` 的标志约束见 radix / 线程篇）；IOMMU。

失败策略值得单独说：`map` 中途缺中间级表时，可以从 `ppn_cache` 补给；失败路径 **不回滚** 已经长出来的内核页表页（源码注释的理由是：内核增长有界；用户侧靠进程退出拆掉）。泄漏算上层 bug，不要指望本层自动收拾。

## 3. 分层与调用方

从早到晚大致是：boot 的 `L0_table` 提供最早能跑的映射 → BSP 的 `sys_init_map` 挂上永久的 MAP_L1→L2→L3 链，并预创建高半全部 L1 → 每核 `Map_Handler` 用临时 4 槽去碰任意物理页 → `map` / `unmap` 在持 `vspace_lock` 下改任意 `VSpace` → radix / 兼容层决定「映射什么」，再调本层落 PTE。

调用方须注意：MCS 的 `me` 用 **本核** handler 上的节点；不要在已经占用窗口映射时，再嵌套冲突地用同一份 handler（头文件有说明）。

## 4. 数据结构与不变量

### 4.1 窗口几何与「为何四槽」

基址是 `map_pages`（`0xFFFFFFFFFFE00000`）——**一整段 2 MiB**，由一张 L2 项指到满页的 `MAP_L3_table`。每个 CPU 在这段里占 **连续 4×4 KiB 槽**（共 16 KiB），不是「每核独占 2 MiB」。按 4 槽计，容量量级大约能撑到百余个 CPU，具体上限要和 `NR_CPUS` 配置一起核对。

这不是 Linux 式 direct map，也不是「递归 PML4 自映射」：改页表页时，要把**那张物理页**临时映进固定高址槽，改完可卸。四级页表一次 `map` 可能同时摸 L0/L1/L2/L3 **四张不同物理页**——若只有一槽反复 remap，中间级指针还没写稳就丢窗口，或嵌套 `map` 时把自己踩掉。故每核固定 **4 槽并行**：

```text
槽 0 → 当前摸到的 L0 表页
槽 1 → L1
槽 2 → L2
槽 3 → L3（叶）
```

`sys_init_map` 永久挂好 `MAP_L1→L2→L3` 链（整段 `map_pages` 的骨架）；运行期 `util_map` 只改已经落在镜像映射里的 **`MAP_L3_table` 槽项**。`mapped_ppn[i]` 命中同一物理页可跳过重写和 TLBI；`ppn_cache` 则缓存「刚从 buddy 拿来、马上要装进中间级」的页，减少窗口颠簸。

`map_util_page.S` 只是给 `MAP_L*` 做 **bss 占位**，没有运行时 helper。

槽的惯例：`map` 走 L0…L3 用槽 0…3；`copy_data_range` 用 **0 与 2**（避开相邻页越界撞槽）；简单 zero 常用槽 0。

### 4.2 `VSpace`

带着根页帧、`asid`、`tlb_cpu_mask`、`vspace_lock`（MCS）、radix、注册用的红黑树节点等。`root_vspace` 由 BSP 的 `init_root_vspace` 从**当前**内核根读出并装上共享高半；`vspace_lock` 初值为空；永不 `del`。

### 4.3 `sys_init_map` 不变量

只在仅 BSP 存活时做：挂好 `map_pages` 那条链；对空的高半 `L0[256..511]` **预分配全部 L1**。注释里的动机是：运行期没法向所有已存在的地址空间广播「又多了一条新的 L0 项」。编辑 boot L0 时可以经已有的 `KERNEL_PHY_TO_VIRT(root)`——这是窗口规则的 bootstrap 例外。

### 4.4 `map` 约定

- 叶 level 只允许 **2（2 MiB）或 3（4 KiB）**。
- 同一 PPN 且已 VALID：可以只改 flags（类似 mprotect）；要换 PPN 必须带 `PAGE_ENTRY_REMAP`，禁止静默偷页。
- 软件位 `LAZY | COW | REMAP` 在写进硬件页表前会被剥掉（`entry_flags_rm_sw_flags`）。
- 缺中间级：从 `ppn_cache` 取页、装 `nonfinal` 标志（含 USER，以便用户地址能往下走树）、窗口里 memset。
- 缺 root：直接失败——调用方须先 `new_vs_root`。

### 4.5 可移植标志与硬件页表项：encode / decode

可移植层（`map` / `unmap` / `have_mapped`）只认 `ENTRY_FLAGS_t`（`include/common/mm.h`）：`VALID` / `READ` / `WRITE` / `EXEC` / `USER` / `DEVICE` / `UNCACHED` / `GLOBAL` / `HUGE`，外加软件位 `LAZY` / `COW` / `REMAP`。真正写进页表的是各 ISA 的 `ARCH_PFLAGS_t`（64 位描述符里的硬件位）。

对应关系由 arch 的两个函数完成（`arch/*/mm/vmm.c`）：

- **`arch_decode_flags(level, ENTRY_FLAGS) → ARCH_PFLAGS`**：可移植 → 硬件，供 `arch_set_L*_entry` 写入。
- **`arch_encode_flags(level, ARCH_PFLAGS) → ENTRY_FLAGS`**：硬件 → 可移植，供 `have_mapped` 等读回。

写页时典型顺序：剥软件位 → `decode` → `arch_set_L*_entry(paddr, vaddr, table, flags)`（把物理地址按该级掩码打进描述符，再或上 flags）。四级索引宏 `L0_INDEX`…`L3_INDEX` 两边都是 VA 每级 9 bit，与「4 KiB granule / 4-level」模型对齐。

#### x86_64（Intel SDM Vol. 3A，Paging / IA-32e）

四级叫 PML4E → PDPTE → PDE → PTE。本实现常用位（定义在 `page_table_def.h`）：

| 可移植 | 硬件位（各级同名语义） |
|--------|------------------------|
| VALID | `P` |
| WRITE | `RW`（可读总是隐含的；无单独「只读可读」位，靠不置 RW） |
| EXEC 取反 | `XD`（需 boot 已开 `IA32_EFER.NXE`） |
| USER | `US` |
| DEVICE / UNCACHED | `PCD \| PWT`（粗粒度；未接 PAT 精细表） |
| HUGE | L1：`PDPTE.PS`（1 GiB）；L2：`PDE.PS`（2 MiB）；L0/L3 无 |
| GLOBAL | 大页上的 `G`，或 PTE 的 `G`（依赖 `CR4.PGE`） |

地址字段用 `PML4E_ADDR` / `PDPTE_ADDR` / `PDE_ADDR` / `PTE_ADDR`，并按 `max_phy_addr_width`（来自启动时 CPUID）裁剪，对应手册里的 MAXPHYADDR。

#### aarch64（ARM ARM，VMSAv8-64 描述符）

四级描述符：L0–L2 可以是 **table** 或 **block**，L3 是 **page**。有效位是 `PT_DESC_V`；table/page 与 block 靠 bit1 等区分（本实现用 `PT_DESC_BLOCK_OR_TABLE` / `PT_DESC_PAGE`）。叶属性分 lower / upper：

| 可移植 | 硬件侧 |
|--------|--------|
| VALID / READ | 置 `V`；decode 里用 READ 驱动有效 |
| WRITE 取反 | 叶上 `AP[RO]` |
| USER | `AP[EL0]`；用户可执行看 `XN`，内核可执行看 `PXN`（与 EL0/EL1 执行权限模型对应） |
| DEVICE / UNCACHED / Normal | `AttrIndx` → `MAIR_EL1` 槽（`MEM_ATTR_*`）；boot 的 `mair_init` 先写好 MAIR |
| HUGE | **不**置 table/page 的「下一级」形态，留下 block（L1/L2） |
| GLOBAL 取反 | 叶上 `nG`（非全局，才跟 ASID 走） |
| （叶） | 常置 `AF`，配合 TCR 的硬件 AF 更新 |

官方背景：Intel SDM 的页表项位图与 PS/G/XD；ARM ARM 的 Stage 1 EL1&0 描述符、AP/XN/PXN、AttrIndx 与 MAIR。本篇不抄整表，只钉「可移植标志 ↔ 本仓库宏」；改权限时先改 `ENTRY_FLAGS`，再让 decode 生成硬件位，避免在 `map_handler.c` 里直接写 `PTE_RW` 之类。

## 6. 流程

### 6.1 `virt_mm_init`

`cmain` 在 BSP 上调用 `virt_mm_init(BSP_ID, setup_info)`。当 `cpu_id == BSP_ID` 时，建整机的 `sys_init_map`、ASID 子系统和 `root_vspace`；本核栈底取链接脚本里的 `boot_stack`，不用 `setup_info`。AP **不**建 root；栈底取 `setup_info->ap_boot_stack_ptr`——所以 AP 若传入空指针会直接失败。

两侧都会 `init_map` 本核 Map_Handler，把 `current_vspace` 指到同一份 `root_vspace`，并 `kinit` 出本核内核堆。返回成功之后才有可用的 `kallocator`。`cmain` 把 `arch_start_platform` 排在这之后，就是因为平台对象要从这份堆上分配。

对照一下：

- `sys_init_map` / `asid_init` / `init_root_vspace`：只 BSP。
- `init_map`（槽 + `ppn_cache`）、指向 `root_vspace`、`kinit`：BSP 与 AP 都做。
- 栈底：BSP 用链接 `boot_stack`；AP 用 `ap_boot_stack_ptr`。

AP **不会**在这个函数里「重新挂一遍内核映射」——SMP 路径已经共用 boot 根表；这里只建本核的 Map_Handler 状态，并指向共享的 `root_vspace`。

### 6.2 `map` / `unmap` 与 TLB

全程 `lock_mcs(&vs->vspace_lock, &handler->vspace_lock_node)`。整树一把锁：新建表页和 memset 不能跟细锁交错。

本层对 TLB 的策略大致是：

- **首次 map（new）**：只做本地 invalidate（假定他核还没有缓存这个 VA）。
- **改映射 / unmap**：按内核 / 用户分别走 all-core；用户侧带着 `tlb_cpu_mask`（x86 走 IPI；aarch64 广播细节见 TLB 篇）。
- 窗口槽变更：本地 kernel-page invalidate。

### 6.3 与内存栈其它层

物理页从 buddy 来 → Map_Handler 改 PTE → 用户侧由 radix 记账；kmalloc 对内容页走 `KERNEL_PHY_TO_VIRT` + `map`；调度时换硬件 AS 并维护 `tlb_cpu_mask`（见所有权篇）。

## 7. 公开 API

本篇拥有：`include/rendezvos/mm/vmm.h`、`include/rendezvos/mm/map_handler.h`（实现 `kernel/mm/vmm.c`、`map_handler.c`）。接口说明以头文件注释为准，并已与实现核对。用户映射语义记账见 radix 篇；TLB shootdown 见 TLB 篇；调度换根见 VSpace 所有权篇。

**注意：** 旧稿 §7 签名有误（`map` 参数顺序、`create_vspace` 无参、`have_mapped` 写成 bool 等）；以下以当前头文件为准。

### 7.1 编排顺序（与源码一致）

| 路径 | 顺序 |
|------|------|
| BSP `virt_mm_init` | **`sys_init_map(pmm)`** → **`init_map`(本核)** → `asid_init` → **`init_root_vspace`** → `current_vspace=&root_vspace` → `kinit` |
| AP `virt_mm_init` | **`init_map`**（**不**再 `sys_init_map` / root）→ 栈底=`ap_boot_stack_ptr` → 同上 `current_vspace` / `kinit` |
| 用户 AS 创建 | **`create_vspace(pmm)`** → **`register_vspace(vs, &root_vspace)`** → … → 拆除收尾：**`unregister_vspace`** → 末次 ref → **`del_vspace`** |
| 改 PTE | 持 `vspace_lock`（经 handler 的 MCS `me`）调 **`map` / `unmap` / `have_mapped`**；handler 一般为 `&percpu(Map_Handler)` |

### 7.2 初始化

```c
error_t virt_mm_init(cpu_id_t cpu_id, struct setup_info *arch_setup_info);
error_t sys_init_map(struct pmm *pmm);           /* 仅 BSP */
error_t init_map(struct map_handler *h, cpu_id_t cpu_id, struct pmm *pmm);
error_t init_root_vspace(VSpace *root_vs, cpu_id_t cpu_id);
```

| 接口 | 说明 |
|------|------|
| `virt_mm_init` | `phy_mm_init` 之后、每核调用。BSP 建窗口树+root；AP 只 `init_map`，且 `arch_setup_info` 不得为 NULL。失败负 `error_t`。 |
| `sys_init_map` | 把 `map_pages` 永久挂上 MAP_L1→L2→L3，并预分配高半 L0[256..511] 的 L1 页。 |
| `init_map` | 为本核填 4 个槽的 VA（`cpu_id*4`）与 `pmm` / MCS 节点。 |

### 7.3 页表改写（`map_handler.h`）

```c
error_t map(VSpace *vs, ppn_t ppn, vpn_t vpn, int level,
            ENTRY_FLAGS_t eflags, struct map_handler *handler);
ppn_t   unmap(VSpace *vs, vpn_t vpn, u64 new_entry_addr,
              struct map_handler *handler);
ppn_t   have_mapped(VSpace *vs, vpn_t vpn, ENTRY_FLAGS_t *flags_out,
                    int *level_out, struct map_handler *handler);
```

| 接口 | 说明 |
|------|------|
| `map` | `level`：2=2 MiB，3=4 KiB。已有 VALID 叶：同 ppn → 只改 flags（mprotect）；异 ppn 需 `PAGE_ENTRY_REMAP`，否则失败。缺中间表可从 `ppn_cache` 补给；**失败不回滚**已长出的内核 PT 页。软件位（REMAP/LAZY/COW…）写入前剥掉。 |
| `unmap` | 成功返回原先叶上的 ppn（L3 空叶可为 **0**）；失败负值。`new_entry_addr` 只写入叶描述符的 **paddr 字段**，条目保持无效——**不是**写入有效叶 PTE / remap（见 `map_handler.h`）。 |
| `have_mapped` | >0=ppn；0=未映射/无效；<0=错误。可选输出 flags / level。 |

窗口辅助（物理页 ↔ 临时 KVA，与当前 CR3/TTBR 无关）：

```c
vaddr map_handler_map_slot(struct map_handler *, int slot_id, ppn_t);
void  map_handler_unmap_slot(struct map_handler *, int slot_id);
error_t map_handler_zero_page(struct map_handler *, ppn_t);
error_t map_handler_copy_data_range(struct map_handler *, paddr dst, paddr src, u64 len);
error_t map_handler_copy_page(...); /* inline → copy_data_range 整页 */
error_t map_handler_user_kernel_copy(VSpace *, u64 user_va, void *kbuf, size_t, bool to_user);
paddr new_vs_root(paddr old_vs_root_paddr, struct map_handler *);
```

`new_vs_root`：恒填内核半模板；`old==0` 清空用户半，非 0 则浅拷用户半 L0 指针（**不是**完整 clone/COW）。

### 7.4 `VSpace` 生命周期（`vmm.h`）

```c
VSpace *create_vspace(struct pmm *pmm);
error_t clone_vspace(VSpace *src, VSpace **dst_out, enum vspace_clone_flags flags);
error_t register_vspace(VSpace *vs, VSpace *root_vs);
error_t unregister_vspace(VSpace *vs);
error_t del_vspace(VSpace **vs);
error_t vspace_clear_user_mappings(VSpace *vs, struct map_handler *h, bool allow_self_use);
```

| 接口 | 说明 |
|------|------|
| `create_vspace` | 分配结构 + 空 L0 + radix + 共享内核高半；失败返回 NULL。之后须 `register_vspace`。 |
| `clone_vspace` | 必须 `VSPACE_CLONE_F_USER_4K_ONLY`，且 **恰好其一**：`COW_PREP` 或 `COPY_PAGES`。细节见 radix/线程篇。 |
| `register` / `unregister` | 挂/卸 root 的 RB 表；unregister 在已未注册时成功幂等。 |
| `vspace_clear_user_mappings` | 清用户低半，保留对象/ASID/根帧/内核半；exec 原地用 `allow_self_use=true`。禁止对 `root_vspace`。 |
| `del_vspace` | 末次引用路径：clear → 毁 radix → 放根页 → 放结构/ASID；`*vs=NULL`。先 unregister。 |

标志编解码：`arch_decode_flags` / `arch_encode_flags`（§4.5）。`tlb_cpu_mask` 辅助 inline 见头文件；shootdown 约定见 TLB 篇。

## 8. 多架构

页表项位级对照与 encode/decode 见 §4.5。这里只补「根寄存器怎么装」：

- **x86_64**：一个地址空间一根 **CR3**（PML4 物理地址）。内核与用户同树时靠高半/低半 VA 区分；GLOBAL 叶在 `CR4.PGE` 下可跨 CR3 保留。
- **aarch64**：EL1&0 下 **TTBR1** 管高半（内核）、**TTBR0** 管低半（用户），用户根常把软件 ASID 打进 TTBR0（见 ASID 篇）。可移植 API 仍填「内核半」相关标志以保持两侧调用一致，真正切换语义在 arch 的装根路径。

四级各 9 bit 索引的宏两边共用。riscv / loongarch 无主线实现。

## 10. 限制与后续

- 整树一把 MCS，并发 `map` 吞吐有限。
- `map` 失败不回滚已生长的内核 PT。
- x86「内核页 all-core」是否真广播，以源码为准（注释更倾向 percpu 路径）。
- x86 的 DEVICE/UNCACHED 都打成 PCD|PWT，未接 PAT；aarch64 依赖 boot 已初始化的 MAIR。
- 槽位算术与 `NR_CPUS` 上限要一起核对。
- TLB / ASID 的硬件手册对照见 `11` / `12` 篇（后续加强时补 invlpg、`tlbi`、TTBR.ASID、PCID 等）。
