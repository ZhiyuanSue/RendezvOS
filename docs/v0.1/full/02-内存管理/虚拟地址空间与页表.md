## 1. 概述

本层回答：**如何改任意地址空间的页表项**，以及 **VSpace 对象如何承载一棵硬件页表**。用户「这块 VA 含义是什么」以 radix 为真源；本篇的 `map`/`unmap` 是改 PTE 的工具。

核心机制是每核 **`Map_Handler` 临时窗口**：把要手术的物理页（尤其是**页表页本身**）映进固定高址槽，改完可卸掉——**不是** Linux 式「启动时把全部 RAM 线性映进 direct map」，也**不是**递归 PML4 self-map。

**设计意图（五问压缩）：**

| 问 | 答 |
|----|----|
| 面对什么？ | 若永久映满物理内存 / 所有 PT 帧，调试期 UAF、错指针更易「碰巧可读」；跨 AS 改表也难 |
| 对比谁？ | Linux 宽 direct map + 递归自映射；本实现用窄 boot 脚手架 + 按需窗口 |
| 代价/收益？ | 多几次 `util_map`/本地 TLBI；换可调试性与「PT 帧默认不可线性访问」 |
| 反例？ | A 核 `unmap` 用户页后 B 核 TLB 仍命中——无 `tlb_cpu_mask` shootdown 则「卸映射即 fault」不成立 |
| 咬合？ | kmalloc 仍用 `KERNEL_PHY_TO_VIRT`+`map()` 给**内容页**建线性 PTE；**中间级 PT 页**通常只走窗口 |

澄清：内核内容页可以有线性 VA；页表页故意偏窗口路径。§1 旧稿若写成「完全无高半线性」过满。

## 2. 目标与边界

**提供：** `VSpace` 生命周期骨架；`sys_init_map` / `virt_mm_init`；`map`/`unmap`/`have_mapped`；Map_Handler 槽、零页/拷贝辅助；与 arch 标志编解码。

**不做：** 用户 VMA 策略（radix/兼容层）；完整 COW 语义（`clone_vspace` 标志约束，细节在 radix/线程篇）；IOMMU。

**失败策略：** `map` 中途缺中间级表可从 `ppn_cache` 补给；失败路径**不回滚已生长的内核 PT**（注释：内核增长有界；用户侧靠进程退出拆掉）——泄漏算上层 bug。

## 3. 分层与调用方

| 层 | 职责 |
|----|------|
| Boot `L0_table` | 最早可跑映射 |
| `sys_init_map` | 永久 MAP_L1→L2→L3 链；预创建高半全部 L1 |
| `Map_Handler` | 临时 4 槽触及任意物理页 |
| `map`/`unmap` | 在持 `vspace_lock` 下改任意 `VSpace` |
| radix / 兼容层 | 决定映射什么；调用本层落 PTE |

调用方须：MCS `me` 用**本核** handler 节点；勿在持窗映射时嵌套冲突使用同一 handler（见头文件）。

## 4. 数据结构与不变量

### 4.1 窗口几何（纠正旧表述）

- 基址：`map_pages`（约 `0xFFFFFFFFFFE00000`）——**一整段 2 MiB**（一张 L2→满 `MAP_L3_table`）。
- 每 CPU：**连续 4×4 KiB 槽**（共 16 KiB），不是「每核 2 MiB」。按 4 槽计，容量量级约 **128 CPU**，不是「512×2 MiB」。
- `map_util_page.S`：仅为 `MAP_L*` **bss 占位**，无运行时 helper。
- `util_map` 写的是已在镜像映射里的 `MAP_L3_table` 槽；`mapped_ppn[i]` 命中可跳过重写+TLBI。

槽惯例：`map` 走 L0..L3 用槽 0..3；`copy_data_range` 用 **0 与 2**（避免相邻页越界撞槽）；简单 zero 常用槽 0。

### 4.2 `VSpace`

根页帧、`asid`、`tlb_cpu_mask`、`vspace_lock`（MCS）、radix、注册 RB 等。`root_vspace`：BSP `init_root_vspace` 从**当前**内核根读取并安装共享高半；`vspace_lock` 初值空；永不 `del`。

### 4.3 `sys_init_map` 不变量

在仅 BSP 存活时：挂好 `map_pages` 链；对空的 `L0[256..511]` **预分配全部 L1**（注释：运行期无法向所有 AS 广播新 L0 项）。编辑 boot L0 可经已有 `KERNEL_PHY_TO_VIRT(root)`——窗口规则的 bootstrap 例外。

### 4.4 `map` 契约

- 叶 level 仅 **2（2 MiB）或 3（4 KiB）**。
- 同 PPN + VALID → 可只改 flags（mprotect）；换 PPN 须 `PAGE_ENTRY_REMAP`，禁止静默偷页。
- SW 位 `LAZY|COW|REMAP` 写硬件前剥掉。
- 缺中间级：从 `ppn_cache` 取页、装 `nonfinal` 标志（含 USER 以便用户走树）、窗口 memset。
- 缺 root：失败——先 `new_vs_root`。

## 6. 流程

### 6.1 `virt_mm_init`

| 步骤 | BSP | AP |
|------|-----|-----|
| `sys_init_map` | 是 | **否** |
| `init_map`（槽 + `ppn_cache`） | 是 | 是 |
| `asid_init` | 是 | 否 |
| `init_root_vspace` | 是 | 否 |
| `boot_stack_bottom` | 链接 `boot_stack` | `setup_info->ap_boot_stack_ptr` |
| `current_vspace=&root_vspace` | 是 | 是（共享对象） |
| `kinit` | 是 | 是 |

AP **不**在此函数里「重新挂内核映射」——SMP 路径已共用 boot 根表；这里只建**本核 Map_Handler 状态**并指向 `root_vspace`。

### 6.2 `map` / `unmap` 与 TLB

全程 `lock_mcs(&vs->vspace_lock, &handler->vspace_lock_node)`（整树一把锁：新建表页+memset 不能细锁交错）。

TLB（本层策略）：

- **首次 map（new）：** 本地 invalidate（假定他核无该 VA 缓存）。
- **改映射 / unmap：** 按内核/用户走 all-core；用户带 `tlb_cpu_mask`（x86 IPI；aarch64 广播细节见 TLB 篇）。
- 窗口槽变更：本地 kernel-page inv。

### 6.3 与内存栈其它层

```
buddy 物理页 → Map_Handler 改 PTE →（用户）radix 记账
             → kmalloc：KERNEL_PHY_TO_VIRT + map 内容页
             → schedule：HW AS + tlb_cpu_mask（所有权篇）
```

## 10. 限制与后续

- 整树 MCS：并发 map 吞吐有限。  
- `map` 失败不回滚内核 PT 生长。  
- x86「内核页 all-core」实现是否真广播以源码为准（注释倾向 percpu）。  
- 槽位算术与 `NR_CPUS` 上限需配置时一起核对。  
- 与 radix COW / `tlb_cpu_mask` 的完整故事分见兄弟篇。
