# 系统调用入口

v0.1 · 2026-09-27

本篇覆盖：`kernel/system/syscall.c`（weak）、`arch/x86_64/trap/kernel_entry.S`、`arch/x86_64/boot/start_arch.c`（`init_syscall` / MSR）、`arch/aarch64/boot/start_arch.c`（`arch_syscall_helper` + `register_fixed_trap`）、`include/arch/*/trap/trap.h` 参数宏、`arch/*/task/arch_thread.c` 里 Path A 返回助手（点到为止）。

Trap 双入口总图与 schedule 表见 `23-Trap抽象与分类.md`；Path A/B 与 `arch_return_to_user` 细节见 `14-线程创建与ELF加载.md`。本篇**不**写 APIC / GIC / Timer。

手册：Intel SDM（`SYSCALL` / `SYSRET`、IA32_STAR / LSTAR / FMASK）；ARM ARM（`SVC`、ESR.EC、DAIF / SPSR、`eret`）。

---

## 1. 概述

core **不做** Linux syscall 表。它只保证：用户用架构指令进内核时，拿到可读写的上下文指针，再调到一个**可被链接覆盖**的 `syscall(tf)`。

两条硬件路，不要写成同一条。

| | x86_64 | aarch64 |
|--|--------|---------|
| 硬件门 | `syscall` → **IA32_LSTAR** | `svc` → VBAR Sync → **`trap_handler`** |
| 与 trap 框架 | **旁路**（不经 `trap_handler`） | **走** `irq_vector[EC]` + `TRAP_CLASS_SYSCALL` |
| 末尾自动 `schedule` | **否** | **是**（用户来源） |
| boot 注册 | 写 STAR / FMASK / LSTAR | `register_fixed_trap(SYSCALL, arch_syscall_helper, …)` |

旧稿写「两 arch 都 register_fixed_trap(SYSCALL)」或「x86 也走 sysenter」——**错**。实现只有 **syscall / sysret**；x86 的 `x86_trap_class_map` **无** SYSCALL 项。

---

## 2. 目标与边界

**提供：** weak `syscall` 挂钩；两 arch 进核帧约定；中断标志继承策略说明；参数 / 返回值宏；与 Path A 返回的边界。

**不做：** NR_syscalls、seccomp、strace、vsyscall、int 0x80（未接入）。fork / exec 特殊返回由 compat 在 `syscall` 内自管。

---

## 3. 分层与调用方

**兼容层** — 强符号覆盖：

```c
void syscall(struct trap_frame *tf)
{
        /* 读 ARCH_SYSCALL_ID / ARG*，写 ARCH_SYSCALL_RET */
}
```

须在用户跑起来前链接进镜像。**不要**在 linux_layer 再做 aarch64 DAIF inherit——只在 `arch_syscall_helper`。

**core 测试用例** — 无强符号时 weak 为空；用户 SVC / `syscall` 无 ops。

---

## 4. 数据结构与不变量

### 4.1 弱符号

```c
__attribute__((weak)) void syscall(struct trap_frame *syscall_ctx);
```

返回值写 **frame 槽**（`ARCH_SYSCALL_RET`），不是依赖 C 函数返回后的 `%rax` / `x0`——x86 exit 从栈上 rax 槽恢复。

### 4.2 参数宏

| | ID | RET | ARG1–6 |
|--|----|-----|--------|
| x86 | `rax` | `rax` | `rdi,rsi,rdx,r10,r8,r9` |
| aarch64 | `REGS[8]` (x8) | `REGS[0]` | `REGS[0..5]` |

aarch64：ARG1 与 RET **同槽 x0**——先读参再写返回值。

### 4.3 x86 syscall_ctx ≠ 完整 iret 帧

入口拼「类 trap_frame」前部；**不填**完整 `trap_info` / rip / cs / … 尾。用户 PC 在硬件 **RCX**（入口保存）；用户 SP 在 **`percpu(user_rsp_scratch)`**，不是 `tf->rsp`。Path A 只依赖重叠寄存器区 + scratch。

### 4.4 aarch64

EC **0x15**（EL0 SVC）绑 fixed wrapper。`tf->SP` = 异常后的 **内核栈指针**，**不是**用户 SP——用户 SP 走 `SP_EL0` / `arch_syscall_set_user_return`。

## 6. 流程

### 6.1 x86（MSR 旁路；SDM：SYSCALL / SYSRET）

每核 `arch_start_core`：`init_interrupt` → … → **`init_syscall`** → **`arch_enable_irq`**。

1. **IA32_STAR**：`KERNEL_CS<<32` + `GDT_TSS_UPPER*8<<48`（靠 `+16/+8` 算术落到 USER_CS / DS，不是直接写 USER_CS 字面）。
2. **IA32_FMASK = 0x200**：进核清 **IF**。
3. **IA32_LSTAR** → `arch_enter_kernel`。

#### SYSCALL / SYSRET 硬件流程（SDM Vol.2）

`syscall` 不走 IDT，CPU 直接从 MSR 取目标地址与段选择子，省去访存查表：

```text
  用户态执行 syscall
    │
    ├─ RCX ← 下一条用户指令 RIP（返回地址）
    ├─ R11 ← RFLAGS（用户 EFLAGS 副本，SYSRET 时恢复）
    ├─ CPL ← 0；CS ← STAR[47:32]    （KERNEL_CS）
    ├─ SS ← STAR[47:32] + 8          （KERNEL_SS，靠 +8 算术）
    ├─ RIP ← LSTAR                   （arch_enter_kernel）
    └─ RFLAGS ← RFLAGS AND NOT FMASK （按 FMASK 清位，本仓库清 IF=bit9）

  内核态执行 sysretq
    ├─ RCX → RIP（恢复用户 PC）
    ├─ R11 → RFLAGS（恢复用户标志）
    ├─ CPL ← 3；CS ← STAR[63:48] + 16 （USER_CS）
    ├─ SS ← STAR[63:48] + 8           （USER_SS）
    └─ 继续从用户 RCX 处执行
```

#### 相关 MSR 位布局

```text
  IA32_STAR (0xC0000081):
    [63:48]  USER_CS 选择子（SYSRET 用，+8 得 USER_SS）
    [47:32]  KERNEL_CS 选择子（SYSCALL 用，+8 得 KERNEL_SS）
    [31:0]   保留

  IA32_LSTAR (0xC0000082):
    [63:0]   syscall 入口 RIP（arch_enter_kernel）

  IA32_FMASK (0xC0000084):
    [63:0]   进核时 RFLAGS 中要清的位（本仓库 0x200 = bit9 = IF）
```

注意：SYSCALL **不**保存用户 RSP——内核栈来自 `percpu(user_rsp_scratch)` 或 TSS.RSP0（实现细节），用户 RSP 由入口汇编另存到 scratch 槽。SYSRET 也不恢复 RSP，必须由 `arch_exit_kernel` 显式恢复。

```text
syscall → swapgs、切 DS/ES、TSS 内核栈
  → 压类 trap_frame 前部；rdi=rsp
  → sti
  → call syscall
  → cli → 恢复 → scratch RSP → swapgs → sysretq
```

**不**经 IDT / `trap_handler` / EOI / 统一 `schedule`。出口从栈上 rax 槽取返回值（见 `arch_exit_kernel`），不是依赖 C 的 `%rax`。

#### `kernel_entry.S` 栈布局（syscall 路径）

入口在内核栈上拼一个「类 trap_frame」前部，只覆盖 syscall 路径需要的字段，**不**填完整 iret 帧：

```text
  入口前          入口压栈后（内核栈，从高到低）
  ──────         ────────────────────────────────
  用户 RSP ──►   ┌────────────────────┐
                 │  用户 RFLAGS (R11)  │  ← 入口已保存
                 │  用户 RIP   (RCX)  │  ← 入口已保存（SYSRET 用）
                 │  用户 RSP (scratch)│  ← 软件存，非硬件压
                 │  ……通用寄存器……    │
                 │  rax 槽（返回值）  │  ← syscall() 写 ARCH_SYSCALL_RET
                 │  rdi = 当前 rsp    │  ← 传给 syscall(tf)
                 └────────────────────┘
                 ↑ 内核 RSP 指向此处
```

`rdi` 在 `call syscall` 时作为第一个参数（C ABI）= `tf` 指针，所以入口先把当前 RSP 写到 RDI。`arch_exit_kernel` 从栈上 rax 槽取返回值，再依次弹栈、恢复用户 RSP/RCX/R11、`swapgs`、`sysretq`。

### 6.2 aarch64（SVC + helper；ARM ARM：SVC / ESR）

须先 `init_interrupt`（EC 槽 USED），再 `init_syscall`：

```c
register_fixed_trap(TRAP_CLASS_SYSCALL, arch_syscall_helper, IRQ_NO_ATTR);
```

#### SVC / ERET 硬件流程（ARM ARM）

`svc` 是一条普通指令，触发同步异常进 EL1，与 IRQ 共用 VBAR Sync 入口：

```text
  EL0 执行 svc #imm
    │
    ├─ SPSR_EL1 ← PSTATE（含 DAIF、EL0 模式位）
    ├─ ELR_EL1  ← svc 的下一条指令（返回后不必重执行 svc）
    ├─ PSTATE.I/F/A/D ← 1（硬件屏蔽异步）
    ├─ PSTATE.M ← EL1h（当前 EL 用 SP_ELx）
    ├─ ESR_EL1.EC ← 0b010101（EL0 SVC，AArch64）
    ├─ ESR_EL1.IL ← 1
    ├─ ESR_EL1.ISS ← imm16（svc 立即数，本仓库未用）
    └─ PC ← VBAR_EL1 + 0x200（Lower EL, AArch64, Sync 槽）

  内核执行 eret
    ├─ PC    ← ELR_EL1（svc 之后）
    ├─ PSTATE ← SPSR_EL1（恢复 EL0 + DAIF 用户态）
    └─ 继续从用户 svc 下一条执行
```

与 x86 SYSCALL 的关键差异：

| | x86 SYSCALL | aarch64 SVC |
|--|-------------|-------------|
| 入口来源 | MSR（LSTAR），不查表 | VBAR Sync 槽，与 fault/IRQ 共入口 |
| 用户 PC 保存 | RCX（专用寄存器） | ELR_EL1（系统寄存器） |
| 用户标志保存 | R11 | SPSR_EL1 |
| 中断屏蔽 | FMASK 清 IF | 硬件 DAIF 全屏蔽 |
| 是否经 trap_handler | 否（旁路） | 是（fixed wrapper） |
| 返回指令 | sysretq | eret |

```text
svc → VBAR Sync → trap_info=ESR.EC → trap_handler
  → fixed wrapper → arch_syscall_helper:
       EL0: 保存 DAIF → inherit SPSR.I → syscall(tf) → 恢复 DAIF
  → 无 EOI → 用户来源则 schedule → eret
```

每核都调 `register_fixed_trap`（写全 CPU 槽，幂等覆盖）。

### 6.3 中断窗口：sti vs DAIF（并非完全等价）

| | x86 | aarch64 |
|--|-----|---------|
| 入口硬件 | FMASK 清 IF | 异常入口 DAIF 全屏蔽 |
| syscall 窗口 | 入口 **无条件 `sti`** | EL0：**只继承 user SPSR.I** |
| 出口 | `cli` + sysret 恢复 RFLAGS | 恢复 saved DAIF；用户 I 仍在 SPSR |

若用户态进核前 I 已屏蔽：aarch64 保持屏蔽，x86 `sti` 仍打开。

### 6.4 返回用户（边界）

| | Path A（syscall 返回） | Path B（首次 drop） |
|--|------------------------|---------------------|
| API | `arch_syscall_set/get_user_return` | empty drop + set + **`arch_return_to_user`** |
| x86 | rcx=pc, rax=ret, scratch/sp | `arch_drop_to_user` |
| aarch64 | ELR / REGS[0] / SP_EL0；`tf->SP=(vaddr)tf` | 同左再 drop |

**禁止**对正在 Path A 返回的线程再调 `arch_return_to_user`。

### 6.5 schedule 不对称（主不变量）

| 路径 | 统一末尾 schedule？ |
|------|---------------------|
| x86 `syscall` 指令 | **否**（除非 `syscall()` 内自调） |
| aarch64 用户 SVC | **是**（经 `trap_handler`）→ 顺带 kfree / EBR 排水 |

## 7. 公开 API

本篇涉及的接口分布在：用户进核挂点——weak `syscall`、`ARCH_SYSCALL_*` 帧槽宏；以及进核 boot 编排序（`init_syscall` 本身是 arch `static`，不上公开表）。说明改写自 `include/rendezvos/system/syscall.h` + `arch/*/trap/trap.h` 宏注释（已与 `syscall.c` / `kernel_entry.S` / `start_arch.c` 核对）。

**本篇不涉及：** `arch_syscall_set/get_user_return` / `set_user_int_arg` / `arch_return_to_user` / Path A·B 细节 → `14` §7.4；`register_fixed_trap` → `23`；`trap_handler` / EOI → `25`。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 顺序 |
|------|------|
| x86 每核 | `init_interrupt` → … → **`init_syscall`**（STAR / FMASK / LSTAR→`arch_enter_kernel`）→ **`arch_enable_irq`** → … |
| aarch64 每核 | `init_interrupt`（EC 槽 USED）→ … → **`init_syscall`** = `register_fixed_trap(SYSCALL, arch_syscall_helper, …)` |
| 兼容层 | 链接强符号 **`syscall(tf)`**（覆盖 weak）；在用户跑起来前进镜像 |
| Path A 改返回 | 在 `syscall()` 内 `arch_syscall_set_user_return`；**禁止**再调 `arch_return_to_user`（见 `14`） |

`init_syscall` / `arch_syscall_helper` / `arch_enter_kernel` 均为 arch boot / 汇编内部，不是上层可调 API。

### 7.2 weak `syscall`

```c
void syscall(struct trap_frame *syscall_ctx);  /* weak default: 空操作 (no-op) */
```

| 要点 | 行为 |
|------|------|
| 定义 | `kernel/system/syscall.c`：`__attribute__((weak))` 空体 |
| 声明 | `include/rendezvos/system/syscall.h` |
| 调用方 | x86：`arch_enter_kernel` `call syscall`；aarch64：`arch_syscall_helper` → `syscall(tf)` |
| 返回值 | 写 **`ARCH_SYSCALL_RET` 帧槽**；x86 `arch_exit_kernel` 从栈上 rax 槽恢复，不依赖 C `%rax` |
| 表 | core **无** NR_syscalls；分发表在兼容层强符号里 |

### 7.3 `ARCH_SYSCALL_*` 宏

```c
/* x86_64 trap_frame 字段名 */
tf->ARCH_SYSCALL_ID / RET / ARG_1..6
/* aarch64 同理，展开为 REGS[n] */
```

| | ID | RET | ARG1–6 |
|--|----|-----|--------|
| x86 | `rax` | `rax` | `rdi,rsi,rdx,r10,r8,r9`（ARG4≠rcx；rcx=用户 RIP） |
| aarch64 | `REGS[8]` (x8) | `REGS[0]` | `REGS[0..5]`（ARG1 与 RET **同槽**——先读参再写返回） |

### 7.4 与 Path A 的交汇（细节归 `14`）

进核后若要改用户返回点，用 `14` 的：

```c
void arch_syscall_set_user_return(struct trap_frame *, Arch_Thread_Context *,
                                  vaddr pc, vaddr sp, u64 ret);
void arch_syscall_get_user_return(...); /* out-params；非 u64 返回 */
void arch_syscall_set_user_int_arg(struct trap_frame *, unsigned idx, u64);
```

| arch | set_user_return 写哪里 |
|------|------------------------|
| x86 | `rcx`=PC，`rax`=ret，`user_rsp_scratch`=SP（**不是** `tf->rsp`） |
| aarch64 | `ELR`=PC，`REGS[0]`=ret，`SP_EL0`=SP；`tf->SP=(vaddr)tf`（内核保存区） |

x86 syscall 路径**不**经 `trap_handler` 末尾 `schedule`；aarch64 用户 SVC **会**。细节见 §6.5 与 `23`。
