# 锁与内存屏障

v0.1 · 2026-10-02

本篇覆盖：`include/rendezvos/sync/spin_lock.h`（MCS）、`cas_lock.h`、`barrier.h`、`include/common/atomic.h`、`arch/{x86_64,aarch64}/atomic.c`、`include/arch/*/sync/barrier.h`。

MSQ/EBR 见 04 无锁篇；`sched_lock` 见 TM 篇；MCS `me` 事故权威亦见 `doc/ai/INVARIANTS.md`。本篇**不**写软 IPI / TLB 握手。

**官方手册：** Intel SDM — `LOCK` 前缀、`mfence`/`lfence`/`sfence`、`pause`；ARM ARM — `LDXR`/`STXR`、`DMB`/`DSB`/`ISB`、`YIELD`。

---

## 1. 概述

core 只要 **短临界区** 的 SMP 互斥；长串行化走 IPC / server，不扩 mutex / rwsem / RCU（除 EBR）。

分层看：

| 层 | 原语 | 用途 |
|----|------|------|
| 原子 | `atomic64_*` | CAS / exchange / load/store / add… |
| MCS | `lock_mcs` / `unlock_mcs` | 可扩展、多等待者 |
| CAS lock | `lock_cas` / `unlock_cas` | 极短区（调度环、mask） |
| 屏障 | arch `barrier` / `dmb`/`dsb`/`mfence`… | **没有** `mb`/`rmb`/`wmb`/`smp_mb` 包装层 |

`include/rendezvos/sync/barrier.h` **只是** `#include` arch 头——旧稿宣称的 `mb()/rmb()/wmb()` **不存在**。
`include/common/spin.h` 只有 `cpu_idle()` 死循环，**不是**锁包装。

### 1.1 硬件在锁路径里实际干什么

- **x86：** `atomic64_*` / CAS 多靠带 **`lock` 前缀** 的 RMW，本身带全屏障语义；自旋用 **`pause`**（`arch_cpu_relax`）。显式 `mfence`/`lfence`/`sfence` 在头文件里有，**锁路径几乎不调**。
- **aarch64：** RMW 常配 **`ldaxr`/`stlxr`** 或事后 **`dmb ISH`**；自旋用 **`yield`**。TLB 路径才密集用 `dsb`/`isb`（见 TLB 篇）。

MCS 交棒：unlock 用 `atomic64_store(successor->spin, 1)`，lock 自旋用 `atomic64_load`——依赖仓库原子实现里的屏障（aarch64 `dmb`；x86 TSO + `barrier`），**不是**另套 C11 `memory_order_*` API，但已不再是「普通 store/load 裸交棒」。

## 2. 目标与边界

**提供：** MCS、CAS lock、atomic64、arch 屏障原语说明、调用方表、`me` 纪律。

**不做：** mutex / rwsem；Linux 风格 `smp_mb` 全家桶；把 MSQ 说成有锁。

持锁不可 sleep——须 unlock 再 `schedule`（如 unregister 等 `ops_count`）。

## 3. 分层与调用方

| 场景 | 原语 | `me` / 备注 |
|------|------|-------------|
| tid / `Id_Manager` | MCS | `percpu(id_spin_lock)` |
| ASID bitmap | MCS | `asid_lock` + `percpu(asid_mcs_node)` |
| Port 表 register / unregister | MCS on `by_name.lock` | `percpu(port_table_spin_lock)` |
| name_index lookup / resolve | MCS on **同一** `by_name.lock` | `percpu(name_index_spin_lock)` |
| `VSpace::vspace_lock` | MCS | `handler->vspace_lock_node` |
| PMM / rmap | MCS | `percpu(pmm_spin_lock[zone])` |
| log | MCS | `percpu(log_spin_lock)` |
| `sched_lock` / `tlb_cpu_mask_lock` / root register / kmalloc / page_slice | CAS | 极短区 |
| MSQ / EBR | 无锁 | 04 篇 |

**注意：同一把 MCS 头、两套 percpu `me`。** Port register 用 `port_table_spin_lock`；lookup 走 name_index 用 `name_index_spin_lock`。合法，但 **禁止同 CPU 嵌套这两条入口**（双节点自死锁）。

## 4. 数据结构与不变量

### 4.1 MCS

- `spin_lock` = 队列头指针；`spin_lock_t` = waiter `{next, spin}`。
- **`me` 必须本 CPU、持锁者私有**——用他核 slot 或 `per_cpu(..., handler->cpu_id)` 会队列损坏（PMM 历史事故）。
- 正确：`&percpu(xxx)` 或嵌在本核 `Map_Handler` 的 node。

### 4.2 CAS lock

单 word TAS（exchange 到 1）。适合极短区；持锁勿 schedule。

### 4.3 Atomic

`atomic64_cas/exchange/load/store`、`add/sub/inc/dec`、`fetch_*`。头文件有 `atomic_t` 类型，**无**完整 32-bit 实现族当主路径。

### 4.4 屏障真实情况

| | x86 | aarch64 |
|--|-----|---------|
| 锁路径 | 主要靠 `lock` 前缀；偶尔编译器 `barrier()` | RMW 路径常带 `dmb(ISH)`；`ldaxr/stlxr` 等 |
| 显式 fence | `sfence/lfence/mfence` **几乎不被锁路径调用** | `isb`/`dmb`/`dsb`（TLB 路径更常见） |
| MCS unlock→后继 | `atomic64_store(spin, 1)` / waiter `atomic64_load` | 走仓库 `atomic64_*` 屏障，非裸 C 赋值 |
| relax | `pause` | `yield` |

riscv / loongarch：barrier 头在 include 链上，树内文件可能缺失——主线只验收 x86 / aarch64。

### 4.5 aarch64 屏障速查：域 × 序

手册把屏障拆成 **作用域（shareability）** × **访问类型（Load / Store / Any）**。本仓库锁路径常用 **`dmb(ISH)`**；TLB 维护用 **`dsb` + `tlbi` + `dsb` + `isb`**（见 `11` / `32`）。下面矩阵便于读 `barrier.h` / 手册时对号，**不是**主张业务代码随便换域。

**作用域（越往下越大）：**

| 后缀 | 域 | 直观 |
|------|-----|------|
| **NSH** | Non-shareable | 仅本 PE 观察顺序 |
| **ISH** | Inner Shareable | 本 inner 共享域（典型一颗 SoC 上的 CPU 簇；SMP 锁/原子常用） |
| **OSH** | Outer Shareable | 更大域（常含 DMA / 其它 agent，实现相关） |
| **SY** | Full system | 全系统 |

**访问类型：**

| 后缀 | 含义 |
|------|------|
| **LD** | 仅对先前的 Load 排序 |
| **ST** | 仅对先前的 Store 排序 |
| （无 LD/ST） | Load+Store（Any） |

组合例：`DMB ISHST` = Inner 域上「Store 屏障」；`DSB SY` = 全系统数据同步屏障（比 DMB 更强：等先前访存对指定域完成）。**`ISB`** 刷新流水线 / 取指上下文，不替代 DMB/DSB 的数据序——改系统寄存器或依赖刚写的指令流时才成对出现。

`DMB` vs `DSB`：前者约束可见顺序；后者还要等先前访问对指定域**完成**（TLB / 缓存维护指令前后几乎总要 DSB）。锁的 RMW 路径已通过 `atomic64_*` 内的 `dmb(ISH)` 覆盖交棒；不要在持 MCS 时再随手插一层 `dsb sy`「求安心」。

### 4.6 `trylock_mcs`

仅当头为 NULL 时 CAS 挂入 `@p me`（`(u64)me`，不是 `&me`）。成功返回 0，忙返回 1；失败路径**不**链 `next`。树内调用仍少。

## 6. 流程

典型：取本核 `me` → `lock_mcs` → 短临界区 → `unlock_mcs`。
CAS：`lock_cas` → … → `unlock_cas`。
需要让出 CPU：先 unlock，再 `schedule`。

## 7. 公开 API

本篇拥有：短临界区同步原语——MCS（`spin_lock.h`）、CAS lock（`cas_lock.h`）、`atomic64_*`（`atomic.h`）、arch 屏障 / `arch_cpu_relax`（经 `sync/barrier.h` 伞头）。说明改写自上述头文件 Doxygen（已与 inline / `arch/*/atomic.c` 核对）。

**本篇不拥有：** MSQ / EBR 无锁协议 → `22`/`17`；软 IPI → `30`；TLB `dsb`/`isb` 握手细节 → `32`/`11`；`sched_lock` 业务语义 → `13`。

**不存在：** 可移植 `mb()` / `rmb()` / `wmb()` / `smp_mb()`。`common/spin.h` 只有 `cpu_idle()`，不是锁。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 顺序 |
|------|------|
| MCS | 取**本核** `me` → `lock_mcs` → 短临界区 → `unlock_mcs`；若需让出 CPU：**先 unlock 再 `schedule`** |
| CAS | `lock_cas` → 极短区 → `unlock_cas`（持锁禁 schedule） |
| 同一把 MCS 头 | 禁止同 CPU 嵌套两条不同 `me` 入口（如 `port_table_spin_lock` 与 `name_index_spin_lock`） |

### 7.2 MCS

```c
typedef spin_lock_t *spin_lock;   /* 队列头 */
struct spin_lock_t { spin_lock_t *next; u64 spin; };  /* waiter / me */

void lock_mcs(spin_lock *m, spin_lock_t *me);
void unlock_mcs(spin_lock *m, spin_lock_t *me);
int trylock_mcs(spin_lock *m, spin_lock_t *me);  /* 0=拿到，1=忙 */
```

| 接口 | 说明 |
|------|------|
| `lock_mcs` | `me` = `&percpu(…)` 或本核 `Map_Handler` 内嵌 node。**禁止**他核 slot。等待时 `atomic64_load(&me->spin)`。 |
| `unlock_mcs` | 无后继则 CAS 清空头；否则 `atomic64_store(&next->spin, 1)`。 |
| `trylock_mcs` | 空队列 CAS 挂 `(u64)me`；忙则 1。 |

### 7.3 CAS lock

```c
typedef u64 cas_lock_t;
void lock_init_cas(cas_lock_t *);
void lock_cas(cas_lock_t *);
void unlock_cas(cas_lock_t *);
u64 trylock_cas(cas_lock_t *);  /* 返回旧值：0=拿到 */
```

单 word TAS。用于 `sched_lock`、`tlb_cpu_mask_lock`、kmalloc 等极短区。

### 7.4 Atomic64

```c
u64 atomic64_cas / exchange / load(…);
void atomic64_store / init / add / sub / inc / dec(…);
i64 atomic64_fetch_add / fetch_sub / fetch_inc / fetch_dec(…);
```

主路径是 **64-bit**。`atomic_t`（32-bit）类型在，无完整 API 族。x86 多靠 `lock` RMW；aarch64 常配 `ldaxr`/`stlxr` 或 `dmb`。

### 7.5 屏障

| | x86 | aarch64 |
|--|-----|---------|
| 宏 | `barrier` / `sfence`/`lfence`/`mfence` / `arch_cpu_relax`=`pause` | `barrier` / `isb`/`dmb`/`dsb` / `arch_cpu_relax`=`yield` |
| 锁路径 | 主要靠 `lock` 前缀；显式 fence 几乎不用 | RMW 常带 `dmb`；TLB 路径才密集 `dsb`/`isb` |

`rendezvos/sync/barrier.h` **仅** `#include` arch 头。

## 10. 限制与后续

- 无 mutex；无 `smp_mb` 包装；无 C11 `memory_order_*` API——交棒靠 `atomic64_store/load`。
- port / name_index 双 `me` 嵌套禁忌。
- `next` 链入仍是普通写 + `barrier()`（与 `spin` 交棒分开）；若日后弱序上暴露问题再收紧。
