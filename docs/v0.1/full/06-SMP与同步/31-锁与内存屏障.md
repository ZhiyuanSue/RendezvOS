# 锁与内存屏障

v0.1 · 2026-10-02

本篇覆盖：`include/rendezvos/sync/spin_lock.h`（MCS）、`cas_lock.h`、`barrier.h`、`include/common/atomic.h`、`arch/{x86_64,aarch64}/atomic.c`、`include/arch/*/sync/barrier.h`。

MSQ（Multi-producer Single-consumer Queue，多生产者单消费者队列）/ EBR（Epoch-Based Reclamation，基于世代的回收）见 04 无锁篇；`sched_lock` 见 TM 篇；MCS（Mellor-Crummey & Scott 队列锁）的 `me` 参数事故权威亦见 `doc/ai/INVARIANTS.md`。本篇**不**写软 IPI / TLB 握手。

**官方手册：** Intel SDM — `LOCK` 前缀、`mfence`/`lfence`/`sfence`、`pause`；ARM ARM — `LDXR`/`STXR`、`DMB`/`DSB`/`ISB`、`YIELD`。

---

## 1. 概述

core 只需 **短临界区** 的 SMP 互斥；长串行化走 IPC / server，不扩展 mutex / rwsem / RCU（Read-Copy-Update，读时复制；除 EBR 外）。

分层看：

| 层 | 原语 | 用途 |
|----|------|------|
| 原子 | `atomic64_*` | CAS（Compare-And-Swap，比较并交换）/ exchange / load/store / add… |
| MCS | `lock_mcs` / `unlock_mcs` | 可扩展、多等待者 |
| CAS lock | `lock_cas` / `unlock_cas` | 极短区（调度环、mask） |
| 屏障 | arch `barrier` / `dmb`/`dsb`/`mfence`… | **没有** `mb`/`rmb`/`wmb`/`smp_mb` 包装层 |

`include/rendezvos/sync/barrier.h` **只是** `#include` arch 头——旧稿宣称的 `mb()/rmb()/wmb()` **不存在**。
`include/common/spin.h` 只有 `cpu_idle()` 死循环，**不是**锁包装。

### 1.1 硬件在锁路径里实际干什么

- **x86：** `atomic64_*` / CAS 多靠带 **`lock` 前缀** 的 RMW（Read-Modify-Write，读-改-写），本身带全屏障语义；自旋用 **`pause`**（`arch_cpu_relax`）。显式 `mfence`/`lfence`/`sfence` 在头文件里有，**锁路径几乎不调**。
- **aarch64：** RMW 屏障**按用途分层**——锁路径的 `atomic64_cas`/`exchange` 用 `ldaxr`/`stlxr` + 前后 `dmb ISH`（全屏障）；refcount 的 `atomic64_fetch_add`/`fetch_dec` 用 `ldaxr`/`stlxr`（acquire/release，无 trailing dmb）；纯计数的 `atomic64_add`/`sub`/`inc`/`dec` 用 `ldxr`/`stxr`（最弱序，独占监视器保证原子性，不约束与其他访存的顺序）。自旋用 **`yield`**。TLB 路径才密集用 `dsb`/`isb`（见 TLB 篇）。

MCS 交接：unlock 用 `atomic64_store(successor->spin, 1)`，lock 自旋用 `atomic64_load`——依赖仓库原子实现里的屏障（aarch64 `dmb`；x86 TSO + `barrier`），**并非**另套 C11 `memory_order_*` API，但已不再是「原始 store/load 直接交接」。

#### 1.1.1 x86 内存序要点（TSO）

x86-64 采用 **Total Store Order（TSO）**：所有 store 之间按程序序可见，store→load 可重排（store buffer 可前向读到自己的 store），其余保持顺序。后果：

- **`lock` 前缀**（`lock cmpxchg` / `lock xadd` 等）：RMW 原子 + **全屏障**（等价 `mfence`）。`atomic64_cas` / `fetch_add` 都靠它。
- **`mfence`**：串行化所有前后访存；`sfence` 仅串行化 store；`lfence` 仅串行化 load（主要配合推测控制 / Spectre 缓解，锁路径不用）。
- **`pause`**：不是内存屏障，只是提示 CPU「这是自旋等待」，减少流水线推测浪费与功耗，避免乱序核上 spin loop 的过度探测。

显式 fence 在锁路径几乎不需要——`lock` 前缀已覆盖。`sfence` 主要给页表 / IO 写顺序；`lfence` 给推测控制。

#### 1.1.2 aarch64 内存序要点（弱序）

ARM 是 **弱内存模型**：load/store 可在满足依赖关系外重排，必须靠屏障显式约束。锁路径关键原语：

- **`ldxr` / `stxr`**：独占监视器配对加载 / 存储，失败重试即 CAS。带 acquire/release 变体 **`ldaxr`/`stlxr`**——前者保证后续读写不提前到 ldaxr 前，后者保证先前读写不延后到 stlxr 后。
- **`dmb`**：内存屏障，约束可见顺序，不等访存完成。`dmb ISH` 是 SMP 锁最常用档（inner shareable 域内全序）。
- **`dsb`**：数据同步屏障，比 `dmb` 更强——等先前访存对指定域**完成**才继续。TLB / 缓存维护指令前后几乎总要 `dsb`。
- **`isb`**：指令同步屏障，刷新流水线、丢弃已推测取的指令。改系统寄存器或自修改代码后必须 `isb` 才能看到新效果。**不**替代 `dmb/dsb` 的数据序。
- **`yield`**：提示 PE「当前在自旋等待」，可让出执行资源给同核超线程；不是内存屏障。

#### 1.1.3 acquire / release 语义对照

```text
  acquire 语义：后续读写 不可提前到 acquire 之前
              ┌─────────────────────────┐
  之前 ──────▶│ acquire（如 ldaxr）      │──▶ 之后（含 load/store）
              └─────────────────────────┘
              之后的访存不会越过 acquire 往上跑

  release 语义：先前读写 不可延后到 release 之后
              ┌─────────────────────────┐
  之前 ──────▶│ release（如 stlxr）      │──▶ 之后
              └─────────────────────────┘
              之前的访存不会越过 release 往下跑

  全屏障（mfence / dmb SY / lock 前缀）：前后都不许越过
```

x86 TSO 下 `lock` 前缀天然是 full barrier；aarch64 下 `ldaxr/stlxr` 是 acquire/release，锁路径的 `atomic64_cas`/`exchange` 再加前后 `dmb ISH` 补到全屏障（`fetch_add` 系列只用 acquire/release，纯计数的 `add`/`sub` 系列无屏障）。本仓库 `atomic64_*` 实现按用途分层含屏障，业务代码按场景选用，锁路径无需另加。

## 2. 目标与边界

**提供：** MCS、CAS lock、atomic64、arch 屏障原语说明、调用方表、`me` 纪律。

**不做：** mutex / rwsem；Linux 风格 `smp_mb` 全家桶；把 MSQ 说成有锁。

持锁不可 sleep——须 unlock 再 `schedule`（如 unregister 等 `ops_count`）。

| 场景 | 原语 | `me` / 备注 |
|------|------|-------------|
| tid / `Id_Manager` | MCS | `percpu(id_spin_lock)` |
| ASID bitmap | MCS | `asid_lock` + `percpu(asid_mcs_node)` |
| Port 表 register / unregister | MCS on `by_name.lock` | `percpu(port_table_spin_lock)` |

## 4. 数据结构与不变量

### 4.1 MCS

- `spin_lock` = 队列头指针；`spin_lock_t` = waiter `{next, spin}`。
- **`me` 必须本 CPU、持锁者私有**——使用其他核的 slot 或 `per_cpu(..., handler->cpu_id)` 会队列损坏（PMM 历史事故）。
- 正确：`&percpu(xxx)` 或嵌在本核 `Map_Handler` 的 node。

#### 4.1.1 MCS 队列结构示意

```text
  spin_lock (头)        waiter 链（每核一个 spin_lock_t 节点）
  ┌──────────┐
  │ head ────┼──▶ ┌──────────┐    next   ┌──────────┐    next   ┌──────────┐
  └──────────┘    │ CPU0 me  │ ────────▶ │ CPU2 me  │ ────────▶ │ CPU1 me  │
                  │ spin = 1 │           │ spin = 0 │           │ spin = 0 │
                  │ (持锁)   │           │ (自旋等) │           │ (自旋等) │
                  └──────────┘           └──────────┘           └──────────┘
```

- **lock_mcs**：CAS 把自己的 `me` 挂到 `head`。若 head 原为 NULL → 直接持锁；否则 CAS 失败重试，用 `atomic64_store` 把自己链到队尾 waiter 的 `next`，然后自旋 `atomic64_load(&me->spin)`。
- **unlock_mcs**：读 `me->next`。无后继 → CAS 把 head 清回 NULL（若此时有人正排队，CAS 失败，等 `next` 出现）；有后继 → `atomic64_store(&next->spin, 1)` 唤醒后继。

MCS 的核心优势：每核自旋只读自己的 cache line（`me->spin`），不抢共享头，避免 test-and-set 锁的 cache line ping-pong。代价是节点必须预先存在（per-CPU 分配），且 `me` 不能跨核借用。

#### 4.1.2 CAS 与 ABA

`atomic64_cas` 是无锁算法基石，但有经典 **ABA** 陷阱：值 A→B→A 的两次读都匹配 CAS 期望值，但中间状态被错过。例：栈顶 A 弹出又压回，CAS「A→C」仍成功，但栈其实已变。

MCS 锁本身不依赖 ABA 检测——队列头是单增链入，CAS 只判 NULL→me，不会出现「NULL→非NULL→NULL」的合法路径，故无 ABA。MSQ 等无锁结构若需抗 ABA，靠 EBR / hazard pointer / tagged pointer（见 04 篇）。

### 4.2 CAS lock

单 word TAS（Test-And-Set，测试并置位；exchange 到 1）。适合极短区；持锁勿 schedule。

### 4.3 Atomic

`atomic64_cas/exchange/load/store`、`add/sub/inc/dec`、`fetch_*`。头文件有 `atomic_t` 类型，**无**完整 32-bit 实现族当主路径。

### 4.4 屏障真实情况

| | x86 | aarch64 |
|--|-----|---------|
| 锁路径 | 主要靠 `lock` 前缀；偶尔编译器 `barrier()` | RMW 路径常带 `dmb(ISH)`；`ldaxr/stlxr` 等 |
| 显式 fence | `sfence/lfence/mfence` **几乎不被锁路径调用** | `isb`/`dmb`/`dsb`（TLB 路径更常见） |
| MCS unlock→后继 | `atomic64_store(spin, 1)` / waiter `atomic64_load` | 走仓库 `atomic64_*` 屏障，非原始 C 赋值 |
| relax | `pause` | `yield` |

riscv / loongarch：barrier 头在 include 链上，树内文件可能缺失——主线只验收 x86 / aarch64。

### 4.5 aarch64 屏障速查：域 × 序

手册把屏障拆成 **作用域（shareability）** × **访问类型（Load / Store / Any）**。本仓库锁路径常用 **`dmb(ISH)`**；TLB 维护用 **`dsb` + `tlbi` + `dsb` + `isb`**（见 `11` / `32`）。下面两组表便于读 `barrier.h` / 手册时对照，**并非**主张业务代码随便换域。

**作用域（越往下越大）：**

| 后缀 | 域 | 直观 |
|------|-----|------|
| **NSH** | Non-shareable | 仅本 PE 观察顺序 |
| **ISH** | Inner Shareable | 本 inner 共享域（典型一颗 SoC 上的 CPU 簇；SMP 锁/原子常用） |
| **OSH** | Outer Shareable | 更大域（常含 DMA / 其它 agent，实现相关） |
| **SY** | Full system | 全系统 |

**访问类型：**

| 后缀 | 含义 |
|------|------|
| **LD** | 仅对先前的 Load 排序 |
| **ST** | 仅对先前的 Store 排序 |
| （无 LD/ST） | Load+Store（Any） |

组合例：`DMB ISHST` = Inner 域上「Store 屏障」；`DSB SY` = 全系统数据同步屏障（比 DMB 更强：等先前访存对指定域完成）。**`ISB`** 刷新流水线 / 取指上下文，不替代 DMB/DSB 的数据序——改系统寄存器或依赖刚写的指令流时才成对出现。

`DMB` vs `DSB`：前者约束可见顺序；后者还要等先前访问对指定域**完成**（TLB / 缓存维护指令前后几乎总要 DSB）。锁的 RMW 路径已通过 `atomic64_*` 内的 `dmb(ISH)` 覆盖交接；不要在持 MCS 时再额外插入一层 `dsb sy`「以求安心」。

`trylock_mcs` 的参数怎么填、成功失败返回什么，见 §7.2。它不属于本节的数据结构。

## 6. 流程

典型：取本核 `me` → `lock_mcs` → 短临界区 → `unlock_mcs`。
CAS：`lock_cas` → … → `unlock_cas`。
需要让出 CPU：先 unlock，再 `schedule`。

## 7. 公开 API

本篇涉及的接口分布在：短临界区同步原语——MCS（`spin_lock.h`）、CAS lock（`cas_lock.h`）、`atomic64_*`（`atomic.h`）、arch 屏障 / `arch_cpu_relax`（经 `sync/barrier.h` 伞头）。说明改写自上述头文件 Doxygen（已与 inline / `arch/*/atomic.c` 核对）。

**本篇不涉及：** MSQ / EBR 无锁协议 → `18`/`17`；软 IPI → `30`；TLB `dsb`/`isb` 握手细节 → `32`/`11`；`sched_lock` 业务语义 → `13`。

**不存在：** 可移植 `mb()` / `rmb()` / `wmb()` / `smp_mb()`。`common/spin.h` 只有 `cpu_idle()`，不是锁。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 顺序 |
|------|------|
| MCS | 取**本核** `me` → `lock_mcs` → 短临界区 → `unlock_mcs`；若需让出 CPU：**先 unlock 再 `schedule`** |
| CAS | `lock_cas` → 极短区 → `unlock_cas`（持锁禁 schedule） |
| 同一把 MCS 头 | 禁止同 CPU 嵌套两条不同 `me` 入口（如 `port_table_spin_lock` 与 `name_index_spin_lock`） |

### 7.2 MCS

```c
typedef spin_lock_t *spin_lock;   /* 队列头 */
struct spin_lock_t { spin_lock_t *next; u64 spin; };  /* waiter / me */

void lock_mcs(spin_lock *m, spin_lock_t *me);
void unlock_mcs(spin_lock *m, spin_lock_t *me);
int trylock_mcs(spin_lock *m, spin_lock_t *me);  /* 0=拿到，1=忙 */
```

| 接口 | 说明 |
|------|------|
| `lock_mcs` | `me` = `&percpu(…)` 或本核 `Map_Handler` 内嵌 node。**禁止**使用其他核的 slot。等待时 `atomic64_load(&me->spin)`。 |
| `unlock_mcs` | 无后继则 CAS 清空头；否则 `atomic64_store(&next->spin, 1)`。 |
| `trylock_mcs` | 仅当队列头为 NULL 时用 CAS 把 `(u64)me` 挂进去（注意是 waiter 节点的地址值，不是 `&me` 再取一次地址）；拿到返回 0，忙返回 1。失败时**不会**把本节点链进 `next`。本仓库里实际调用仍少。 |

### 7.3 CAS lock

```c
typedef u64 cas_lock_t;
void lock_init_cas(cas_lock_t *);
void lock_cas(cas_lock_t *);
void unlock_cas(cas_lock_t *);
u64 trylock_cas(cas_lock_t *);  /* 返回旧值：0=拿到 */
```

单 word TAS。用于 `sched_lock`、`tlb_cpu_mask_lock`、kmalloc 等极短区。

### 7.4 Atomic64

```c
u64 atomic64_cas / exchange / load(…);
void atomic64_store / init / add / sub / inc / dec(…);
i64 atomic64_fetch_add / fetch_sub / fetch_inc / fetch_dec(…);
```

主路径是 **64-bit**。`atomic_t`（32-bit）类型在，无完整 API 族。x86 多靠 `lock` RMW；aarch64 常配 `ldaxr`/`stlxr` 或 `dmb`。

### 7.5 屏障

| | x86 | aarch64 |
|--|-----|---------|
| 宏 | `barrier` / `sfence`/`lfence`/`mfence` / `arch_cpu_relax`=`pause` | `barrier` / `isb`/`dmb`/`dsb` / `arch_cpu_relax`=`yield` |
| 锁路径 | 主要靠 `lock` 前缀；显式 fence 几乎不用 | RMW 常带 `dmb`；TLB 路径才密集 `dsb`/`isb` |

`rendezvos/sync/barrier.h` **仅** `#include` arch 头。

## 10. 限制与后续

- 无 mutex；无 `smp_mb` 包装；无 C11 `memory_order_*` API——交接靠 `atomic64_store/load`。
- port / name_index 双 `me` 嵌套禁忌。
- `next` 链入用 `atomic64_store`（自排序，不依赖 `atomic64_exchange` 的 trailing barrier）；`spin` 交接用 `atomic64_store/load`，两者分开。
