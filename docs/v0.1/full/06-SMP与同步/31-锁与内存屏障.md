# 锁与内存屏障

v0.1 · 2026-10-02

本篇覆盖：`include/rendezvos/sync/spin_lock.h`（MCS）、`cas_lock.h`、`barrier.h`、`include/common/atomic.h`、`arch/{x86_64,aarch64}/atomic.c`、`include/arch/*/sync/barrier.h`。

## 1. 概述

core 只需 **短临界区** 的 SMP 互斥；长串行化走 IPC / server，不扩展 mutex / rwsem / RCU（Read-Copy-Update，读时复制；除 EBR 外）。

分层看：

| 层 | 原语 | 用途 |
|----|------|------|
| 原子 | `atomic64_*` | CAS（Compare-And-Swap，比较并交换）/ exchange / load/store / add… |
| MCS | `lock_mcs` / `unlock_mcs` | 可扩展、多等待者 |
| CAS lock | `lock_cas` / `unlock_cas` | 极短区（调度环、mask） |
| 屏障 | arch `barrier` / `dmb`/`dsb`/`mfence`… | **没有** `mb`/`rmb`/`wmb`/`smp_mb` 包装层 |

`include/rendezvos/sync/barrier.h` **只是** `#include` arch 头——旧稿宣称的 `mb()/rmb()/wmb()` **不存在**。
`include/common/spin.h` 只有 `cpu_idle()` 死循环，**不是**锁包装。

### 1.1 硬件在锁路径里实际干什么

- **x86：** `atomic64_*` / CAS 多靠带 **`lock` 前缀** 的 RMW（Read-Modify-Write，读-改-写），本身带全屏障语义；自旋用 **`pause`**（`arch_cpu_relax`）。显式 `mfence`/`lfence`/`sfence` 在头文件里有，**锁路径几乎不调**。
- **aarch64：** RMW 屏障**按用途分层**——锁路径的 `atomic64_cas`/`exchange` 用 `ldaxr`/`stlxr` + 前后 `dmb ISH`（全屏障）；refcount 的 `atomic64_fetch_add`/`fetch_dec` 用 `ldaxr`/`stlxr`（acquire/release，无 trailing dmb）；纯计数的 `atomic64_add`/`sub`/`inc`/`dec` 用 `ldxr`/`stxr`（最弱序，独占监视器保证原子性，不约束与其他访存的顺序）。自旋用 **`yield`**。TLB 路径才密集用 `dsb`/`isb`（见 TLB 篇）。

MCS 交接：unlock 用 `atomic64_store(successor->spin, 1)`，lock 自旋用 `atomic64_load`——依赖仓库原子实现里的屏障（aarch64 `dmb`；x86 TSO + `barrier`），**并非**另套 C11 `memory_order_*` API，但已不再是「原始 store/load 直接交接」。

#### 1.1.1 x86 内存序要点（TSO）

x86-64 采用 **Total Store Order（TSO）**：所有 store 之间按程序序可见，store 相对 load 可重排（store buffer 可前向读到自己的 store），其余保持顺序。后果：

- **`lock` 前缀**：`arch/x86_64/atomic.c` 的实际指令映射——CAS = `lock cmpxchgq`、exchange = `lock xchgq`、add/sub = `lock addq`/`lock subq`、inc/dec = `lock incq`/`lock decq`、`fetch_add/fetch_sub` = `lock xaddq`（`fetch_inc/fetch_dec` 把 ±1 喂进 `xaddq`）。RMW 原子 + **全屏障**（等价 `mfence`）。
- **`fetch_*` 一律返回修改前的旧值**（`lock` RMW 的固有语义）；`fetch_sub(x)` 直接实现为 `fetch_add(-x)`。
- **`atomic64_load` / `atomic64_store` 不用 `lock` 前缀**：普通 load/store 加编译器 `barrier()`。这在 TSO 下合法——load 间、store 间本就按序可见，acquire/release 不需要硬件屏障；锁的获取/交接全走 exchange/CAS，全屏障由 `lock` 前缀自带。
- **`mfence`**：串行化所有前后访存；`sfence` 仅串行化 store；`lfence` 仅串行化 load（主要配合推测控制 / Spectre 缓解，锁路径不用）。
- **`pause`**：不是内存屏障，只是提示 CPU「这是自旋等待」，减少流水线推测浪费与功耗，避免乱序核上 spin loop 的过度探测。持续时长依微架构而定（老款几十周期，新一代约 140 周期），自旋退避主要靠它。

显式 fence 在锁路径几乎不需要——`lock` 前缀已覆盖。`sfence` 主要给页表 / IO 写顺序；`lfence` 给推测控制。

#### 1.1.2 aarch64 内存序要点（弱序）

ARM 是 **弱内存模型**：load/store 可在满足依赖关系外重排，必须靠屏障显式约束。锁路径关键原语：

- **`ldxr` / `stxr`**：独占监视器配对加载 / 存储，失败重试即 CAS。带 acquire/release 变体 **`ldaxr`/`stlxr`**——前者保证后续读写不提前到 ldaxr 前，后者保证先前读写不延后到 stlxr 后。
- **`dmb`**：内存屏障，约束可见顺序，不等访存完成。`dmb ISH` 是 SMP 锁最常用档（inner shareable 域内全序）。
- **`dsb`**：数据同步屏障，比 `dmb` 更强——等先前访存对指定域**完成**才继续。TLB / 缓存维护指令前后几乎总要 `dsb`。
- **`isb`**：指令同步屏障，刷新流水线、丢弃已推测取的指令。改系统寄存器或自修改代码后必须 `isb` 才能看到新效果。**不**替代 `dmb/dsb` 的数据序。
- **`yield`**：提示 PE「当前在自旋等待」，可让出执行资源给同核超线程；不是内存屏障。注意不少微架构把 `yield` 实现为 NOP——它**不会**像 x86 `pause` 那样自动拉长自旋间隔，自旋退避靠的是 MCS 的结构（只自旋本地 slot），不是靠 `yield`。

对应到仓库实现：`atomic64_load` = 普通 load + `barrier()` + `dmb(ISH)`（acquire 位）；`atomic64_store` = `barrier()` + `dmb(ISH)` + 普通 store（release 位）——MCS 的 `spin` 交接正是配在这一组合上。另外，`arch/aarch64/atomic.c` 全部是手写汇编的 **LL/SC（Load-Linked/Store-Conditional）重试环**，**不用** ARMv8.1 LSE 的单指令原子（`swp`/`ldadd`/`casp`）——手写汇编绕过了编译器 outline-atomics 的自动选择，高竞争下重试环的成本比 LSE 高，这是已知取舍。

#### 1.1.3 acquire / release 语义对照

```text
  acquire 语义：后续读写 不可提前到 acquire 之前
              ┌─────────────────────────┐
  之前 ──────▶│ acquire（如 ldaxr）      │──▶ 之后（含 load/store）
              └─────────────────────────┘
              之后的访存不会越过 acquire 往上跑

  release 语义：先前读写 不可延后到 release 之后
              ┌─────────────────────────┐
  之前 ──────▶│ release（如 stlxr）      │──▶ 之后
              └─────────────────────────┘
              之前的访存不会越过 release 往下跑

  全屏障（mfence / dmb SY / lock 前缀）：前后都不许越过
```

x86 TSO 下 `lock` 前缀天然是 full barrier；aarch64 下 `ldaxr/stlxr` 是 acquire/release，锁路径的 `atomic64_cas`/`exchange` 再加前后 `dmb ISH` 补到全屏障（`fetch_add` 系列只用 acquire/release，纯计数的 `add`/`sub` 系列无屏障）。本仓库 `atomic64_*` 实现按用途分层含屏障，业务代码按场景选用，锁路径无需另加。

## 4. 数据结构与不变量

### 4.1 MCS：为什么要「头指针 + 每核等待节点」

§1 已说明本仓库用短临界区的自旋互斥。若所有核抢同一个字，缓存行会在多核之间来回弹。MCS（Mellor-Crummey & Scott）改成排队：每核自带一个 `spin_lock_t` 节点，只自旋看**自己的** `me->spin`；锁本身只是队列头指针 `spin_lock`。

```c
typedef struct spin_lock_t spin_lock_t;
struct spin_lock_t {
        spin_lock_t *next;
        u64 spin;
};
typedef struct spin_lock_t *spin_lock; /* 队列头；NULL = 无人持锁 */
```

| 字段 | 为什么要有 |
|------|-----------|
| `spin_lock`（头） | 指向当前队尾等待节点；NULL 表示锁空闲。`lock_mcs` 用交换把自己挂上去。 |
| `me->next` | 排队链表：前一个 waiter 通过写我的 `next` 把我链上，unlock 时顺着 `next` 叫醒后继。 |
| `me->spin` | 只属于本 waiter 的本地字。持锁者为 1；后继自旋 `atomic64_load(&me->spin)` 直到被前驱写成 1。这样自旋不砸共享头。 |

**硬纪律：** 传入的 `me` **必须是本 CPU、持锁者私有**的节点（`&percpu(xxx)` 或嵌在本核 `Map_Handler` 里）。借用别的核的 slot 会损坏队列（PMM 历史事故）。

#### 4.1.1 MCS 队列结构示意

```text
  spin_lock（头指针）
        │
        ▼
  CPU0 me          spin = 1（持锁）
        │ next
        ▼
  CPU2 me          spin = 0（自旋等）
        │ next
        ▼
  CPU1 me          spin = 0（自旋等）
        │ next
        ▼
       NULL

  每核自带一个 spin_lock_t 节点；只自旋看自己的 spin。
```

- **lock_mcs**：先置 `me->next = NULL; me->spin = 0;`，然后用**一次** `atomic64_exchange((u64)me)` 无条件把自己换进队头（返回旧队尾）——exchange 必然成功，**没有** CAS 重试环。旧队尾为 NULL → 锁空闲，直接持有；否则 `atomic64_store(&tail->next, me)` 把自己链到旧队尾之后，再自旋 `while (!atomic64_load(&me->spin)) arch_cpu_relax();` 等前驱交接。
- **unlock_mcs**：读 `me->next`。无后继则 CAS 把 head 从 `me` 清回 NULL（若此时恰有人刚 exchange 进来，CAS 失败，自旋等 `me->next` 出现——新尾一定会把自己链上）；拿到 `next` 后 `atomic64_store(&next->spin, 1)` 唤醒后继。

MCS 的核心优势：每核自旋只读自己的 cache line（`me->spin`），不抢共享头，避免 test-and-set 锁的 cache line ping-pong。代价是节点必须预先存在（per-CPU 分配），且 `me` 不能跨核借用。另一个好处是**严格 FIFO**：按入队顺序进临界区，后来者不能抢跑；CAS lock 则相反——unlock 瞬间新来者可能在等待者被唤醒前直接占坑（barging），这正是它只用于极短区的原因之一。

#### 4.1.2 CAS 与 ABA

`atomic64_cas` 是无锁算法基石，但有经典 **ABA** 陷阱：值从 A 变到 B 再变回 A 时，两次读都匹配 CAS 期望值，但中间状态被错过。例：栈顶 A 弹出又压回，CAS「期望 A、写成 C」仍成功，但栈其实已变。

MCS 锁本身不依赖 ABA 检测——队列头是单增链入，CAS 只判「NULL 换成 me」，不会出现「先非 NULL 再变回 NULL」的合法路径，故无 ABA。MSQ 等无锁结构若需抗 ABA，靠 EBR / hazard pointer / tagged pointer（见 `17`）。

### 4.2 CAS lock：单字「占坑」锁

有些临界区极短（改调度环、改 bitmap 一位），不值得为每核准备 MCS 节点。`cas_lock_t` 就是一个 `u64`：0 = 空闲，用原子交换写成 1 表示占住（经典 Test-And-Set）。

```c
typedef u64 cas_lock_t;

static inline void lock_init_cas(cas_lock_t *cas_lock);
static inline void lock_cas(cas_lock_t *cas_lock);
static inline void unlock_cas(cas_lock_t *cas_lock);
static inline u64 trylock_cas(cas_lock_t *cas_lock);
```

实现全在头文件 inline（`trylock_cas` 返回旧值，0 = 拿到）：`lock_cas` 自旋 `atomic64_exchange(cas, 1) == 1` 配 `arch_cpu_relax()`；`unlock_cas` 用 `atomic64_store(cas, 0)`——release 位即可，x86 在 TSO 下普通 store 就够，aarch64 侧前置 `dmb(ISH)`，都不需要 `lock` 前缀；`lock_init_cas` 只是普通写 0 加 `barrier()`，**必须在任何竞争发生之前**调用（现网初始化点：`task_manager.c` 的 `sched_lock`、`vmm.c` 的 `tlb_cpu_mask_lock` / `vspace_register_lock`、`page_slice.c`）。

硬件实情：在 x86 上，`lock_cas` 每轮自旋都是一条完整的 `lock xchgq`——写操作强制把缓存行拉成独占态，即使锁一直被别人持有，自旋核每圈也要让该行在各核之间弹跳一次，比「先读后写」的 test-and-test-and-set 更砸缓存。这是「只适合极短区、竞争多改 MCS」的硬件层注解。

适合极短区；持锁期间**禁止** `schedule`（否则别人自旋等到天荒地老）。竞争多、临界区稍长时改用 MCS。

### 4.3 Atomic

`atomic64_cas/exchange/load/store`、`add/sub/inc/dec`、`fetch_*`。头文件有 `atomic_t` 类型，**无**完整 32-bit 实现族当主路径。

两条跨架构一致的语义：`fetch_*` 一律返回**修改前**的旧值；`fetch_sub(x)` 两边都实现为 `fetch_add(-x)`，`fetch_inc/fetch_dec` 同理走 `fetch_add(±1)`——差别只在底层：x86 把 ±1 喂进 `lock xaddq` 一条指令完成，aarch64 是 `ldaxr/stlxr` 重试环。`add/sub/inc/dec` 不返回旧值，在 aarch64 上因此可以用最弱的裸 `ldxr/stxr`（见 §1.1、§4.4）。

### 4.4 屏障真实情况

| | x86 | aarch64 |
|--|-----|---------|
| 锁路径 | 主要靠 `lock` 前缀；偶尔编译器 `barrier()` | RMW 路径常带 `dmb(ISH)`；`ldaxr/stlxr` 等 |
| 显式 fence | `sfence/lfence/mfence` **几乎不被锁路径调用** | `isb`/`dmb`/`dsb`（TLB 路径更常见） |
| MCS unlock 唤醒后继 | `atomic64_store(spin, 1)` / waiter `atomic64_load` | 走仓库 `atomic64_*` 屏障，非原始 C 赋值 |
| relax | `pause` | `yield` |

riscv / loongarch：伞头 `sync/barrier.h` 有它们的 `#elif` 分支，`include/arch/` 下也有对应目录，但 **`sync/barrier.h` 一档缺失**——真编译会栽在 include 上。主线只验收 x86 / aarch64。

### 4.5 aarch64 屏障速查：域 × 序

手册把屏障拆成 **作用域（shareability）** × **访问类型（Load / Store / Any）**。本仓库锁路径常用 **`dmb(ISH)`**；TLB 维护用 **`dsb` + `tlbi` + `dsb` + `isb`**（见 `11` / `32`）。下面两组表便于读 `barrier.h` / 手册时对照，**并非**主张业务代码随便换域。

**作用域（越往下越大）：**

| 后缀 | 域 | 直观 |
|------|-----|------|
| **NSH** | Non-shareable | 仅本 PE 观察顺序 |
| **ISH** | Inner Shareable | 本 inner 共享域（典型一颗 SoC 上的 CPU 簇；SMP 锁/原子常用） |
| **OSH** | Outer Shareable | 更大域（常含 DMA / 其它 agent，实现相关） |
| **SY** | Full system | 全系统 |

**访问类型：**

| 后缀 | 含义 |
|------|------|
| **LD** | 仅对先前的 Load 排序 |
| **ST** | 仅对先前的 Store 排序 |
| （无 LD/ST） | Load+Store（Any） |

组合例：`DMB ISHST` = Inner 域上「Store 屏障」；`DSB SY` = 全系统数据同步屏障（比 DMB 更强：等先前访存对指定域完成）。**`ISB`** 刷新流水线 / 取指上下文，不替代 DMB/DSB 的数据序——改系统寄存器或依赖刚写的指令流时才成对出现。

`DMB` vs `DSB`：前者约束可见顺序；后者还要等先前访问对指定域**完成**（TLB / 缓存维护指令前后几乎总要 DSB）。锁的 RMW 路径已通过 `atomic64_*` 内的 `dmb(ISH)` 覆盖交接；不要在持 MCS 时再额外插入一层 `dsb sy`「以求安心」。

`trylock_mcs` 的参数怎么填、成功失败返回什么，见 §7.2。它不属于本节的数据结构。

## 7. 公开 API

接口分布在：短临界区同步原语——MCS（`spin_lock.h`）、CAS lock（`cas_lock.h`）、`atomic64_*`（`atomic.h`）、arch 屏障 / `arch_cpu_relax`（经 `sync/barrier.h` 伞头）。说明改写自上述头文件 Doxygen（已与 inline / `arch/*/atomic.c` 核对）。

**本篇不涉及：** MSQ / EBR 无锁协议（见 `18`/`17`）；软 IPI（见 `30`）；TLB `dsb`/`isb` 握手细节（见 `32`/`11`）；`sched_lock` 业务语义（见 `13`）。

**不存在：** 可移植 `mb()` / `rmb()` / `wmb()` / `smp_mb()`。`common/spin.h` 只有 `cpu_idle()`，不是锁。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 顺序 |
|------|------|
| MCS | 取**本核** `me`，`lock_mcs`，做短临界区，再 `unlock_mcs`；若需让出 CPU：**先 unlock 再 `schedule`** |
| CAS | `lock_cas`，做极短区，再 `unlock_cas`（持锁禁 schedule） |
| 同一把 MCS 头 | 禁止同 CPU 嵌套两条不同 `me` 入口（如 `port_table_spin_lock` 与 `name_index_spin_lock`） |

### 7.2 MCS

```c
typedef spin_lock_t *spin_lock;   /* 队列头 */
struct spin_lock_t { spin_lock_t *next; u64 spin; };  /* waiter / me */

void lock_mcs(spin_lock *m, spin_lock_t *me);
void unlock_mcs(spin_lock *m, spin_lock_t *me);
int trylock_mcs(spin_lock *m, spin_lock_t *me);  /* 0=拿到，1=忙 */
```

| 接口 | 说明 |
|------|------|
| `lock_mcs` | `me` = `&percpu(…)` 或本核 `Map_Handler` 内嵌 node。**禁止**使用其他核的 slot。等待时 `atomic64_load(&me->spin)`。 |
| `unlock_mcs` | 无后继则 CAS 清空头；否则 `atomic64_store(&next->spin, 1)`。 |
| `trylock_mcs` | 仅当队列头为 NULL 时用 CAS 把 `(u64)me` 挂进去（注意是 waiter 节点的地址值，不是 `&me` 再取一次地址）；拿到返回 0，忙返回 1。失败时**不会**把本节点链进 `next`。当前**树内无调用者**，备而不用——引入前先想清是否真需要「试锁」语义（见 §10）。 |

### 7.3 CAS lock

```c
typedef u64 cas_lock_t;
void lock_init_cas(cas_lock_t *);
void lock_cas(cas_lock_t *);
void unlock_cas(cas_lock_t *);
u64 trylock_cas(cas_lock_t *);  /* 返回旧值：0=拿到 */
```

单 word TAS。用于 `sched_lock`、`tlb_cpu_mask_lock`、`vspace_register_lock`、kmalloc、page_slice 等极短区。`lock_init_cas` 是普通写 0 + `barrier()`，须在任何竞争出现前调用；`trylock_cas` 当前树内无调用者。

### 7.4 Atomic64

```c
u64 atomic64_cas / exchange / load(…);
void atomic64_store / init / add / sub / inc / dec(…);
i64 atomic64_fetch_add / fetch_sub / fetch_inc / fetch_dec(…);
```

主路径是 **64-bit**。`atomic_t`（32-bit）类型在，无完整 API 族。x86 多靠 `lock` RMW；aarch64 常配 `ldaxr`/`stlxr` 或 `dmb`。

### 7.5 屏障

| | x86 | aarch64 |
|--|-----|---------|
| 宏 | `barrier` / `sfence`/`lfence`/`mfence` / `arch_cpu_relax`=`pause` | `barrier` / `isb`/`dmb`/`dsb` / `arch_cpu_relax`=`yield` |
| 锁路径 | 主要靠 `lock` 前缀；显式 fence 几乎不用 | RMW 常带 `dmb`；TLB 路径才密集 `dsb`/`isb` |

`rendezvos/sync/barrier.h` **仅** `#include` arch 头。

## 8. 多架构

差异集中在两处：原子实现（`arch/{x86_64,aarch64}/atomic.c` 两套手写汇编，§1.1 已对照）与屏障头（`include/arch/*/sync/barrier.h`，仅 x86_64 / aarch64 有文件，§4.4）。`spin_lock.h` / `cas_lock.h` 本身纯 C + `atomic64_*` + `arch_cpu_relax()`，架构无关。aarch64 屏障域速查见 §4.5。主线只验收 x86 / aarch64。

## 9. 测试

**直测：`modules/test/smp_lock_test.c`**，注册在 `modules/test/smp_test.c` 的开机并发测试矩阵中（条目名 "smp spin_lock"，配 `smp_lock_check` 终判）：

- **互斥正确性**：每核各循环 `TEST_ROUND = 100000` 轮，MCS 临界区内做 `mcs_add_value++`、CAS 临界区内做 `cas_add_value++`——**故意用非原子自增**。若互斥失效必然丢计数；终判要求两者都恰等于 `NR_CPU × TEST_ROUND`，是锁生效的直接证据。
- **原子计数**：四组 `atomic64_inc/dec/add/sub`，初值经设计落到精确目标（如 dec 从 `NR_CPU × TEST_ROUND` 减回 0、sub 从 ×2 减回 0），覆盖 `lock` RMW 与 `ldaxr/stlxr` 两条计数路径。
- **编排演示**：BSP 先写完全部初值再置 `have_inited`，AP 用 `while (!have_inited) arch_cpu_relax();` 等待——本身就是 §1.1.3 那套「release store + acquire load」交接的微缩样例。

另：`smp_ms_queue_test.c` 借用 `lock_init_cas` 初始化其校验锁；**间接**：port、PMM、ASID 等 SMP 用例都跑在这些原语上。

## 10. 限制与后续

- 无 mutex；无 `smp_mb` 包装；无 C11 `memory_order_*` API——交接靠 `atomic64_store/load`。
- port / name_index 双 `me` 嵌套禁忌。
- `next` 链入用 `atomic64_store`（自排序，不依赖 `atomic64_exchange` 的 trailing barrier）；`spin` 交接用 `atomic64_store/load`，两者分开。
- `trylock_mcs` / `trylock_cas` 当前树内无调用者，接口冻结前引入新调用需先论证必要性。
- 原子全为手写汇编（aarch64 不用 LSE 单指令原子）；新增 `atomic64_*` 变体必须两架构 `arch/*/atomic.c` 配对实现，并明确落在「按用途分层」的哪一档屏障（§1.1）。
