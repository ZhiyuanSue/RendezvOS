# 锁与内存屏障

v0.1 · 2026-08-27

本篇覆盖：`include/rendezvos/sync/spin_lock.h`、`include/rendezvos/sync/cas_lock.h`、`include/rendezvos/sync/barrier.h`、`include/common/atomic.h`、`include/common/spin.h`、`include/arch/*/sync/barrier.h`、`include/arch/*/sync/sync.h`、`arch/x86_64/atomic.c`、`arch/aarch64/atomic.c`。

MSQ 无锁见 `04-IPC/无锁队列与EBR设计.md`；Task_Manager **`sched_lock`** 用 CAS lock。

---

## 1. 概述

v0.1 同步原语分层：

1. **`atomic64_*` / `atomic_*`** — `include/common/atomic.h` + arch 实现。
2. **MCS spinlock** — `lock_mcs` / `unlock_mcs`（`spin_lock.h`），`me` 必须为 **本 CPU** per-CPU 槽（如 `tid_spin_lock`、`port_table_spin_lock`）。
3. **CAS lock** — `lock_cas` / `unlock_cas`（`cas_lock.h`），用于 Task_Manager 调度环等短临界区。
4. **内存屏障** — `mb()` / `rmb()` / `wmb()` arch 映射（`barrier.h`）。

IPC port MSQ **不用** spinlock 保护主路径；unregister 用 **ops_count + schedule** 与 MSQ 协作。

---

## 2. 目标与边界

core 不提供 mutex、rwsem、RCU（除 EBR）。兼容层长临界区应 IPC 到 server 串行化，而非大 spinlock。

---

## 3. 分层与调用方

| 场景 | 原语 |
|------|------|
| `tid_manager` | MCS |
| `name_index` / port table | MCS |
| `Task_Manager::sched_lock` | CAS |
| MSQ | lock-free + EBR |
| VSpace `tlb_cpu_mask_lock` | CAS |

---

## 4. 数据结构与不变量

- **MCS**：链表 queue lock；**错误 me → 死锁或内存破坏**。
- **CAS lock**：单 word 自旋；适合极短区，持锁不可 schedule（除非设计明确 unlock 后 schedule，如 unregister 等 ops_count）。

---

## 6. 流程

持锁顺序文档化于 **AI INVARIANTS**（全仓库）：避免 cross-CPU 持锁调 schedule 除非已 unlock（IPC/port unregister 模式）。

`lock_mcs`/`unlock_mcs`、`lock_cas`/`unlock_cas`、`atomic64_cas`、`mb`/`rmb`/`wmb`。
