## 1. 概述

core 需要的不是 Linux 式时钟子系统，而是三个可组合的原语：

1. **每核可编程的相对时间 IRQ**（`INT_PER_SECOND=100`，约 10 ms 心跳粒度）。
2. **可排队的软件定时器**（per-CPU 红黑树 + 同到期链表）。
3. **与 IPC 同构的到期 / 取消**（`KMSG_OP_SYSTEM_TIMER_EXPIRE` / `CANCEL`）：等待线程在 port 上 `recv`，ISR **不**把回调放入 IRQ 直接执行业务函数。

硬件侧一律按「下一次到期」编程；软件侧用 heartbeat 事件把周期感补出来。业务单次定时器通过 kmsg 投递，不把回调放入 IRQ。

### 1.1 为什么这样拆

- **相对时间 IRQ 必须每核一份**：调度 / 本地延时 / 本核事件树都挂在「本核会响的那根线」上。板级墙钟（RTC）解决不了「10 ms 后唤醒本核」。
- **x86 选型：** PIC 模式下只有 BSP 能收 8254 IRQ0——SMP 必须切 LAPIC Timer。TSC 读时准确，但**本身不是 IRQ 源**；TSC-Deadline 仍占用 LVT Timer（Local Vector Table，本地向量表）向量。HPET 未接入（校准仍靠 PIT）。`ARAT_support`（Always Running APIC Timer，深 C-state 下仍运行的 APIC 计时器）可探测「深 C-state 下 APIC timer 是否仍在运行」，**现行路径未据此选型**（见 `26` §5.4）。
- **aarch64：** Generic Timer + 每核 PPI（Private Peripheral Interrupt，私有外设中断）；IRQ 号由 DTB `arm,armv8-timer` 的 ns-phys 组给出（见 §6.4）。
- **软件树与硬件单次模式配对**：硬件若只启用 periodic，最近 deadline 难以调整；默认 `TIMER_TYPE_ONE_SHOT`（或 TSC-Deadline），IRQ 末尾按树顶重编程。heartbeat 是树里的周期事件，不依赖 LVT Periodic 位。
- **到期走 IPC**：ISR 里执行任意睡眠路径会破坏推拉模型；投递 kmsg（可经 system proxy）让等待方在线程上下文处理，与 Port 篇一致。

刻意不做：墙钟权威 / NTP、POSIX `timer_create`、跨核迁移定时器、CFS 式 tick。兼容层若要 sleep / alarm，应在 `rendezvos_timer_event_*` 上构建，而不是另造一套 tick。

### 1.2 时钟源设备 vs 时钟事件设备

Linux 把定时硬件分成两类，core v0.1 不做完整抽象，但实际分层与此对齐：

- **时钟源设备（clock source）**：只读、单调、高精度计数器，回答「现在几点」。本仓库用：x86 TSC（`rdtsc`）/ PIT 软件累加基；aarch64 `CNTPCT_EL0`。
- **时钟事件设备（clock event device）**：可编程、能产生 IRQ，回答「多久以后叫我」。本仓库用：x86 LAPIC Timer（或 PIT Channel0 在 PIC 模式）；aarch64 EL1 physical timer（`CNTP_TVAL` 编程）。

```text
  core time 子系统（per-CPU）
  │  event_tree (rb + same_expired_list)
  │  rendezvos_time_now() / jeffies_get()
  │
  ├─ 读计数（单调）
  │       │
  │       ▼
  │  clock source（只读）
  │    x86: TSC / PIT 累加基
  │    arm: CNTPCT_EL0
  │
  └─ 编程下一次 IRQ
          │
          ▼
     clock event（可编程）
       x86: LAPIC Timer / PIT ch0
       arm: CNTP_TVAL (EL1 phys)
```

core 把两类设备的职责合并到 `arch_timer_read`（取源）与 `arch_reset_timer`（编程事件）两个钩子，不暴露 Linux 式 `struct clocksource` / `struct clock_event_device`。

## 2. 目标与边界

**提供：** arch 读计数 / 编程钩子；per-CPU 事件树；heartbeat；`udelay` / `mdelay`（依赖 LPJ（Loops Per Jiffy，每 jiffy 的循环数）自旋）；与 IPC 集成的单次定时器（model B：`init` 持有 port 引用）。

**不做：** 墙钟权威时间源（`rtc.c` 只读 CMOS 并打印）；跨核共享一棵树；HPET；riscv / loongarch 实现（空 `#elif`）。

**并发硬约束：** 树操作必须关 IRQ。`time.c` 注释写明——syscall 可继承用户态 IRQ 使能，若在启用中断下改树，与 timer IRQ 并发会破坏 rb。per-CPU 树不需要跨核锁，**关本核 IRQ 即可**。

## 3. 分层与调用方

| 场景 | 用法 |
|------|------|
| 单次 | `init(event, 0, wait_port, token)`，再 `add(now+delta)`，port `recv` 后校验 token，最后 `fini` |
| cancel | `cancel`：先 del，再 CANCEL kmsg（`proxy=false`）；**不** fini、不放 port ref |
| periodic / heartbeat | `periodic_gap != 0`，`wait_port==NULL`；IRQ 内 `change`；**勿** fini |
| Boot | 每核 `arch_start_core` 路径上调 `rendezvos_time_init` |

事件必须在**将触发的那颗 CPU** 上 `add`。跨核排队不在 v0.1 约定内。

## 4. 数据结构与不变量

### 4.1 事件：一颗定时器在软件里长什么样

§1 已把「只读时钟源」和「可编程时钟事件」分开。硬件每次只能安排「下一次到期响一声」；软件侧在每核一棵红黑树上排出许多事件。每个事件是一颗 `rendezvos_timer_event`：

```c
typedef struct rendezvos_timer_event {
        struct rb_node node;
        struct list_entry same_expired_list;
        tick_t expired;
        u64 periodic_gap;
        Message_Port_t *wait_port;
        u64 delivery_token;
} rendezvos_timer_event;
```

| 字段 | 为什么要有 |
|------|-----------|
| `node` | 挂进本核按 `expired` 排序的红黑树，便于取最近到期、以及 `del`/`change` 任意节点。 |
| `same_expired_list` | 多个事件同一 `expired` 时，只有一个占 rb 节点，其余挂这条链表——避免同键撑爆树。 |
| `expired` | 到期时刻（与 `arch_timer_read()` 同一计数域）。 |
| `periodic_gap` | 0 = 单次；非 0 = 周期（IRQ 里 `change(now+gap)` 留在树上）。heartbeat 走周期路径。 |
| `wait_port` | **仅单次**：到期后往这个 port 投 `KMSG_OP_SYSTEM_TIMER_EXPIRE`。`init` 时对 port `ref_get`，成功投递的 `fini` 或调用方 `fini` 才 put。周期事件必须为 NULL。 |
| `delivery_token` | 单次 kmsg 载荷里带的令牌；等待方校验，忽略「早已 cancel 却迟到」的投递。 |

```text
  per-CPU event_tree_root（按 expired 排序的 rb）
        │
        ▼
  expired=100（rb 头）
        │  same_expired_list:
        │    ev_A
        │      │
        │      ▼
        │    ev_B
        │      │
        │      ▼
        │    ev_C
        │
        ▼
  expired=250（下一 rb 节点）
        │
        ▼
       …

  IRQ 扫描 (rendezvos_do_time_irq)：
    取最小 expired
      now < expired  → 停，按 (expired-now) 重编程硬件
      now >= expired → 处理
        周期 / heartbeat → change(now+gap)，留在树里
        单次 → 投递 EXPIRE kmsg
                 -E_REND_AGAIN / -E_REND_NO_MEM → change(now+jeffy_ticks) 等待 jeffy_ticks 重试，不 fini
                 其余（成功或永久失败）→ fini
                 （永久失败会丢弃本次 EXPIRE，等待线程可能收不到）
    卸下 rb 头时若 same_expired_list 非空：
      把后继提升为新头再插入，下一轮继续扫
```

**数据结构选型（红黑树 vs 最小堆）：** v0.1 用红黑树而非最小堆，原因：定时器需支持 `del` / `change` 任意节点（cancel / 重排），红黑树按 `expired` 键可 O(log n) 删除指定节点；最小堆删中间节点需先定位再重排，常数更大。同 `expired` 用链表挂在头节点上，避免同值节点占独立 rb 节点造成树退化与多余比较。

- 单次：`periodic_gap==0`，`wait_port` 必填；`init` 时 `ref_get_not_zero`；非可重试 EXPIRE 结果直接 `fini`、或调用方 `fini` 才 `ref_put`。
- Periodic：`wait_port` 必须为 NULL；只用 `del` 卸树，禁止 `fini`。

**投递失败语义（以 `time.c` / `time.h` 为准）：** `-E_REND_AGAIN` / `-E_REND_NO_MEM` 走 `change(now+jeffy_ticks)` **不** fini（保留事件与 port ref）。其余失败（`PORT_CLOSED` / `RC_UNEQUAL` 等）与成功一样 `fini`——**会丢弃本次 EXPIRE**，已在 port 上等待的线程可能永远收不到。

### 4.2 Per-CPU / 全局

| 量 | 范围 |
|----|------|
| `event_tree_root`、`heartbeat_event`、`boot_base_time`、`tick_cnt` | per-CPU |
| `heartbeat_gap`、`clock_hz`、`jeffy_ticks`、`loop_per_jeffies`、`sys_timer_type` | 全局（`clock_hz` / LPJ 由 BSP 校准，AP 共用） |
| `udelay_max_loop` | 全局，但**每核各自重算**——`rendezvos_time_init` 末尾在 `is_bsp` 判断之外执行（`time.c` 中 `(loop_per_jeffies * UDELAY_MAX * UDELAY_MUL) >> UDELAY_SHIFT`），只是各核输入相同、结果相同 |

### 4.3 读时语义（易混）

| API | 基准 |
|-----|------|
| `rendezvos_time_now()` | **本核** `arch_timer_read() - boot_base_time` |
| `jeffies_get()` | `(arch_timer_read() - per_cpu(boot_base_time, BSP_ID)) / jeffy_ticks` — **不读** `tick_cnt` |
| `tick_cnt` | heartbeat 路径更新；主用途是 LPJ 校准自旋等待「下一 jeffy」 |

「jeffies 由 `tick_cnt` 驱动」不完全正确：`tick_cnt` 由 heartbeat 驱动，但 `jeffies_get` 直接读硬件计数。

`jeffies_get` 开头有一道守卫：`if (!clock_hz) return 0`——BSP 校准完成之前（AP 启动极早、或校准本身失败时）直接返回 0，而不是用尚未初始化的 `jeffy_ticks` 做除法。同理 `rendezvos_time_count_to_us/_ms` 等换算函数未校准时也返回 0（见 §7.4）。

### 4.4 向量 / INTID

| Arch | Timer 身份 |
|------|------------|
| x86 | `arch_get_timer_irq_num` 即 `ARCH_IRQ_ID_TIMER`（`0x20`）；写入 LVT Timer，或 PIC 下 IRQ0 对应向量 `0x20` |
| aarch64 | BSP 从 DTB `arm,armv8-timer` 的 **第 2 组** interrupts（ns-phys / CNTP）解析 PPI 得 INTID，再换算为 trap id 返回；virt 上常见为 PPI14、INTID **30**、trap **94**（= 30 + `AARCH64_IRQ_OFFSET` 64，见 `27`）。**返回值已是 trap id，不是裸 INTID**，注册 handler 时直接喂给 `register_irq_handler` 即可 |

## 6. 流程

### 6.1 `rendezvos_time_init`（每核）

```text
timer_irq = arch_get_timer_irq_num(is_bsp)   // aarch64: BSP 读 DTB 一次并缓存
register_irq_handler(timer_irq, this_cpu, rendezvos_do_time_irq, IRQ_NEED_EOI)
heartbeat_gap = arch_init_timer(is_bsp)
boot_base_time = arch_timer_read()
init+add heartbeat_event   // periodic_gap=heartbeat_gap, wait_port=NULL
BSP:   clock_hz = arch_timer_get_hz(); jeffy_ticks = clock_hz/100（为 0 则取 1）; LPJ 校准
所有核: udelay_max_loop 重算（is_bsp 判断之外；AP 只是用 BSP 的 LPJ 重算同一个值）
```

heartbeat 初始化失败（`init`/`add` 任一返回错误）直接 `kernel_panic`——没有 heartbeat 就没有 `tick_cnt` 与树的重装动力，带病运行不如早死。极端边界：PIC 模式下若 ACPI 报 timer 为 `NO_IRQ`，`arch_init_timer` 返回 0，`heartbeat_gap=0` 通不过 `rendezvos_timer_event_init` 的「gap 与 port 二选一」检查 → 也是 panic，没有降级路径。

时序：x86 在 `arch_irq_local_enable` **之后**（APIC 软使能常推迟到本函数内的 `arch_init_timer`）；aarch64 在已启用 IRQ + GIC CPU IF 之后（见 GIC 篇）。先注册 handler 再让硬件产生首次 tick。

### 6.2 `rendezvos_do_time_irq`

1. 反复取 rb 最小；`now < expired` 停。
2. **periodic**（含 heartbeat）：`change(now+gap)`；若是本核 heartbeat 且已有 `clock_hz`，则按 `(now-base)/jeffy_ticks` 写 `tick_cnt`。
3. **单次**：`timer_event_deliver_kmsg(EXPIRE, proxy=true)`；`AGAIN`/`NO_MEM` → `change(now + (jeffy_ticks ? jeffy_ticks : 1))`（未校准时退化为 1 tick，至少不忙等）；其余 → `fini`（永久失败丢 EXPIRE）。
4. 按下一树顶算 gap 后调 `arch_reset_timer`；树空则 fallback `heartbeat_gap`（正常不应发生——heartbeat 会再入树）。

载荷格式 `KMSG_FMT_SYSTEM_TIMER = "q"`，值为 `delivery_token`。CANCEL 在线程上下文调用，`use_system_proxy=false`。

同到期链表：卸下 rb 头时若链表非空，把后继提升为新头再插入，IRQ 循环下一轮继续扫。

### 6.3 硬件：x86

**选型（`arch_irq_type`）：**

| 模式 | 时钟源 | 读时 | 重编程 |
|------|--------|------|--------|
| `PIC_IRQ` | 8254 Channel0 经 8259 IRQ0 进向量 `0x20` | `PIT_timer_read`（软件累加 `pit_timer_base` + latch） | Mode0 单次 + `PIT_update_timer`；**仅 BSP**（注释：SMP 必须走 APIC） |
| `xAPIC_IRQ` / `x2APIC_IRQ` | LAPIC Timer（或 TSC-Deadline） | `APIC_timer_read` | `APIC_timer_reset` |

**三类候选定时源（仅作背景，选型见上表）：**

| 设备 | 接口 | 用途 | v0.1 状态 |
|------|------|------|-----------|
| **PIT Channel 0** | PIO `40h`/`43h`，Mode 0/2 | PIC 模式系统 tick / 校准参考 | PIC 模式启用；APIC 模式仅 `PIT_mdelay` 校准 |
| **HPET 主计数器** | MMIO 配置块 + 主计数器 | 高精度时钟源 / 替代 PIT | **未接入**；校准仍靠 PIT |
| **Local APIC Timer** | MMIO LVT Timer / DCR / INIT_CNT | per-CPU 时钟事件 | xAPIC/x2APIC 主路径 |

顺带一提：`include/arch/x86_64/time.h` 里还留着一个 `enum TIMER_SRC_type`（`TSC/ACPI/PIT/HPET` 位标志），全仓除声明外零引用——早期选型遗留的死代码，读代码时可以直接跳过。

另外，相关网上内容，我也找了两篇知乎文章，用来建立「读时基 vs 可编程事件」和「LAPIC 为何要校准」的印象，**不是**本仓库选型依据（以上表 / `arch/x86_64/time/time.c` 为准）：

- [x86 时钟选型](https://zhuanlan.zhihu.com/p/678583925)：PIT / HPET / LAPIC / TSC 各自适合干什么。文中「QEMU 没有 TSC-Deadline」不要当真——本仓库在 `TSC_DDL_support()` 为真时会走 TSC-Deadline。
- [APIC 时钟校准](https://zhuanlan.zhihu.com/p/678583968)：用已知频率的 PIT 去量 LAPIC。步骤和常数以 `PIT.c` / `LocalAPIC.c` 为准；文中端口 `61H`、8254 方式 1 等旁路本仓库时间路径不用。

HPET（Intel ICH 文档 / HPET spec v1.0a）有 Configuration + General Capabilities + Main Counter 等寄存器，主计数器在 ~14.318 MHz 或更高上单调递增，本仓库未启用——校准与读时基仍使用 PIT/TSC，避免引入额外 MMIO 依赖。

**LAPIC Timer 三种模式（LVT Timer 位 [18:17]，宏写作 `0xN << 17`）：**

| 模式 | LVT 位 | 行为 | v0.1 用法 |
|------|--------|------|-----------|
| One-shot | `00` | 写 INIT_CNT 后递减一次，到 0 触发一次 | **默认**（`TIMER_TYPE_ONE_SHOT`），每次 IRQ 末按树顶重编程 |
| Periodic | `01` | 写 INIT_CNT 后周期性触发 | 显式 `TIMER_TYPE_PERIODIC` 才用；v0.1 倾向软件周期+硬件单次 |
| TSC-Deadline | `10` | 写 `IA32_TSC_DEADLINE` MSR，TSC 到值触发 | `TSC_DDL_support()` 为真时可选；仍使用同一 LVT 向量 |

**8254（`PIT.c`）：** 控制口 `43h`，计数器0 口 `40h`。控制字按「SC=0（计数器0）/ RW=3（先低后高）/ M=0（Mode0）」拼出，写入 `43h` 后再把计数值 lo/hi 两字节依次写 `40h`（`init_8254_one_shot`）。Mode0 = 计数到 0 出一次中断，供系统 tick / 校准；Mode2 循环发生器的 `init_8254_cyclical` 虽在代码中，但**全仓无调用方**，不只是「默认不使用」。读值用 latch 命令（向 `43h` 写 0）冻结计数器快照，再 `inb` 两次拼出（`read_8254_val`）。`PIT_mdelay` 用 Mode0 忙等，给 APIC / TSC 校准作为**已知频率参考**（`PIT_TICK_RATE ≈ 1.193181 MHz`）：重编程 `PIT_TICK_RATE*ms/1000` 个计数、latch 后倒读直至计满；注意代码用 `i16` 存读数，等于只用 16 位计数器的一半（注释原话 "only half can we use"），单次最多约 25 ms——这正是校准必须分成多个 `APIC_CALIBRATE_MS` 轮次的原因之一。`PIT_timer_read` 的读数 = `pit_timer_base + pit_timer_gap - read_8254_val()`，即「软件累加基 − 硬件倒计数」。

**LAPIC Timer（SDM）：**

- **LVT Timer**：向量 = `arch_get_timer_irq_num`（`0x20`）；位 [18:17] 选 单次 / 周期 / TSC-Deadline。
- **DCR**（Divide Configuration Register，分频配置寄存器）：本仓库校准与运行用 **÷16**（`APIC_DCR_DIV_16 = 0b0011`）。注意 CURR_CNT 走的是**分频后**的计数域，所以校准算回真实 Hz 时要 `<<4` 还原，`APIC_timer_hz` 对非 TSC 路径也返回 `apic_hz_per_second >> 4`，两边都与 INIT_CNT 域一致。
- **INIT_CNT / CURR_CNT**：写入初值后递减；到 0 经 LVT 投递。软件用 `apic_timer_base` + `apic_timer_gap` 组合出单调读数：`APIC_timer_read` 在 ONE_SHOT 路径 = `base + gap - CURR_CNT`——和 PIT 的 `base + gap - 倒计数` 是同一套记账手法，只是硬件从 8254 换成了 LAPIC。
- **TSC-Deadline**：若 `TSC_DDL_support()`（CPUID.1:ECX[24]），BSP 设 `sys_timer_type = TIMER_TYPE_X86_TSC_DDL`，校准改用 `rdtsc` 差值；到期改写 MSR `IA32_TSC_DEADLINE`（`0x6E0`）为 `rdtsc() + gap`，仍使用同一 LVT 向量。此模式下读时也直接 `rdtsc`，不再碰 CURR_CNT。
- **默认 `sys_timer_type = TIMER_TYPE_ONE_SHOT`**：即使硬件支持 Periodic，v0.1 也用软件周期 + 硬件单次模式重编程（除非显式切 PERIODIC / TSC-DDL）。

**LAPIC 频率怎么校出来的（`APIC_timer_calibration`，仅 BSP）：** LAPIC Timer 的内部频率不来自 ACPI/DTB，SDM 也不保证，只能拿已知频率的 PIT 去量。每轮：DCR 设 ÷16、LVT 装 timer 向量 + 单次模式、INIT_CNT 写 `0xFFFFFFFF`（**满量程**，保证 25 ms 窗口内绝不倒数到 0 产生中断）、`PIT_mdelay(25)` 等窗口过、把 LVT 位打 MASKED 兜底、读 CURR_CNT。elapsed = `-CURR_CNT`（u32 回绕正好等于「初值 − 现值」），`<<4` 还原分频，再 `×(1000/25)` 折算每秒；共 10 轮取平均。TSC 侧同理：每轮 `rdtsc → PIT_mdelay(25) → rdtsc`，差值 `×1000/25`，10 轮平均。代码注释自陈「用 PIT 量；将来应换 HPET」——HPET 接入后校准精度还能再提一档。

**TSC-Deadline 的 `mfence` 坑（SDM 10.5.4.1）：** xAPIC 模式下 LVT Timer 是 **MMIO 写**，而 `IA32_TSC_DEADLINE` 是 **WRMSR**——两者属于不同总线路径，不互相保序；若不隔开，CPU 可能先执行 WRMSR 再落地 LVT 的模式切换，deadline 就被旧模式吞掉。所以切到 TSC-DDL 时，LVT 写与 WRMSR 之间必须插一条 `mfence()`（`APIC_timer_init` 的注释正引 SDM 此节）。x2APIC 模式下 LVT 也是 WRMSR，两条 MSR 访问在同一核上天然串行，**不需要**栅栏——代码按 `if (arch_irq_type == xAPIC_IRQ) mfence();` 精确分支，x2APIC 下直接跳过。

**periodic 重装分支的小字：** `APIC_timer_reset` 的 periodic 分支只改软件 `base/gap` 记账、**不写任何硬件寄存器**——因为硬件 periodic 模式会自动重装 INIT_CNT，软件只需跟着累加读数基。当前默认 ONE_SHOT / TSC-DDL 不走这条分支；若将来真启用硬件 periodic，读数语义要按这个前提重新审视。

**软件使能做了什么（`software_enable_APIC`）：** 给 SVR（Spurious Interrupt Vector Register）置软件使能位，并把 spurious 向量填成 `ARCH_IRQ_ID_SPURIOUS`——收到「向量在但没挂上中断源」的伪中断时用这个向量投递，便于发现误配。

**软使能陷阱：** `software_enable_APIC()` 在 `arch_init_timer` 末尾，不在 `init_irq`。执行 `sti` 与「APIC 开始工作」之间可能有窗口——排障时不要假设 `init_irq` 完成后就能收到 timer。

**RTC：** `get_rtc_time` 经 CMOS index/data 口（`70h`/`71h`）依次读秒/分/时/日/月/年，外加**世纪寄存器**拼出完整年份（`year += 100 × 世纪`，否则 2000 年后会读成 00 年），全部 `BCD_TO_BIN` 换算后以 `[ RTC ] yy-mm-dd hh:mm:ss` 打印并返回 `struct rtc_time`。不是 IRQ 源，不驱动事件树，core 内也无第二个调用方。墙钟语义若需要，由链接方 / 兼容层另行维护。

### 6.4 硬件：aarch64

**Generic Timer（ARM ARM）：** 系统计数器 + 每 PE 多套 timer（EL1/EL2/EL3 的 phys / virt）。本仓库只用 **EL1 physical**：读 `CNTPCT_EL0`，编程 `CNTP_*`。`generic_time.c` 里还留着零调用方的 `get_virt_cnt`（`CNTVCT_EL0`）与 `get_cval`（`CNTV_CVAL_EL0`）——它们**定义在 `.c` 文件内，头文件并未声明**（不存在 `get_compare_value` 这个名字），读代码时勿误认为现行路径。

**EL1 physical vs virtual timer 寄存器布局：**

| 寄存器 | physical (本仓库用) | virtual (未接入) | 说明 |
|--------|---------------------|------------------|------|
| 计数器 | `CNTPCT_EL0` | `CNTVCT_EL0` | 64 位单调只读；virtual 受 `CNTVOFF_EL2` 偏移影响 |
| 比较值 | `CNTP_CVAL_EL0` | `CNTV_CVAL_EL0` | 64 位绝对值；计数器 ≥ CVAL 触发 |
| 倒计时 | `CNTP_TVAL_EL0` | `CNTV_TVAL_EL0` | 32 位；写「再过多少 tick 响」，硬件换算成 CVAL |
| 控制 | `CNTP_CTL_EL0` | `CNTV_CTL_EL0` | bit0=ENABLE, bit1=IMASK, bit2=ISTATUS |

物理 timer 使用 GIC PPI ns-phys（DTB 第 2 组），虚拟 timer 使用 ns-virt（DTB 第 3 组）。本仓库运行在 EL1（无 hypervisor 接管），用物理 timer 与 ns-phys PPI 对应最直接；头文件里 `CNTV_CTL_EL0_ENABLE` 宏名虽带 `V`，但 ENABLE 位位置与 `CNTP_CTL_EL0` 相同，故对物理 timer 也可正常工作——属命名遗留，勿据此误判走的是虚拟 timer。

**TimerValue vs CompareValue：**

| 视图 | 寄存器 | 含义 |
|------|--------|------|
| **TV（本仓库）** | `CNTP_TVAL_EL0` | 近似 32 位**倒计时**：写「再过多少 tick 响」；硬件内部会换算成 CVAL |
| **CV** | `CNTP_CVAL_EL0` | 64 位**绝对比较值**：计数器 ≥ CVAL 时响 |

`arch_init_timer` / `arch_reset_timer` 都写 **TVAL**。源码旁「compare value way」注释是旧措辞，**以实际 `msr CNTP_TVAL` 为准**。

其余：

- **读：** `CNTPCT_EL0`（读前 `isb`）。
- **使能：** `CNTP_CTL_EL0`；宏名用了 `CNTV_CTL_EL0_ENABLE`——ENABLE 位位置相同，可正常工作，但「物理定时器 / 虚拟控制宏」名字混用。
- **频率：** BSP `mrs CNTFRQ_EL0` 写入 `timer_freq`；`time_irq_cycle = timer_freq / INT_PER_SECOND`。

**IRQ 号来源：** `arch_get_timer_irq_num`——BSP 读 DTB `arm,armv8-timer` 的 **第 2 组** interrupts（ns-phys）并缓存于 `.c` 内 static 变量（0 表示尚未探测；缓存的是 trap id，注释特意提醒「IRQ trap id 都 ≥ 64，0 可以安全当哨兵」）；AP 复用；失败 **统一** `kernel_panic`（不再分多处失败路径）。解析细节：`armv8-timer` 的 interrupts 属性按「secure phys / ns-phys / virt / hyp phys」顺序（头文件注释里写明了这个 DTB binding 顺序）每组 3 cells，ns-phys 是第 2 组（`ARCH_TIMER_NS_PHYS = 1`，组号从 0 计），故从 `cell0 = 1×3 = 3` 起取；第 1 个 cell 是 trigger type，必须是 `GIC_DT_TYPE_PPI`(1)，第 2 个是 PPI 号；`INTID = GIC_PPI_START(16) + PPI号`，还要过 `gic_is_ppi` 检查。同节点常见：第 1 组 secure phys、第 3 组 virt——不要误读。QEMU virt 上 ns-phys 多为 PPI14 → INTID 30（trap 94），换板以 DTB 为准。

**Heartbeat 硬件形态：** 与 x86 相同——软件周期事件 + 硬件单次模式重装 TVAL，不是「内核假设 PPI 自动周期」。

## 7. 公开 API

接口分布在：可移植时间与软件定时器——`rendezvos/time.h`（`rendezvos_time_*` / `rendezvos_timer_event_*` / `jeffies_get` / `udelay`/`mdelay`）、arch 钩子声明（`arch_init_timer` / `reset` / `read` / `get_hz`）、x86 `get_rtc_time`、aarch64 Generic Timer 实现细节（`generic_time.c`）。以头文件注释为准（`rendezvos/time.h`；已与 `kernel/time/time.c` 核对）。

**本篇不涉及：** `register_irq_handler` / EOI（见 `25`）；8254 / LAPIC Timer 后端（`PIT_*`、`APIC_timer_*`、`software_enable_APIC`，见 `26`）；GIC PPI 投递（见 `27`）；`KMSG_OP_SYSTEM_TIMER_*` 载荷约定（见 `21`）；`ipc_system_try_deliver`（见 `20`）。

> 注：本篇「不拥有」指这些接口的契约文档在别篇；本篇仍会引用其行为来说明 timer 路径，但不重复定义。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 顺序 |
|------|------|
| 每核启动 | IRQ 路径就绪后调 **`rendezvos_time_init`**（内：挂 handler，再 `arch_init_timer`，然后 heartbeat） |
| 单次 | `init(event,0,port,token)`，再 `add(now+δ)`，port `recv` 后校验 token，最后 **`fini`** |
| cancel | **`cancel`**（del + CANCEL kmsg）后可选再 **`fini`**（cancel **不**放 port ref） |
| periodic / heartbeat | `init(gap,NULL,0)` 后 `add`；卸树只用 **`del`**，禁止 `fini` |
| 树读写 | **关本核 IRQ**（API 内部已做）；勿在开中断的 syscall 路径手工访问 rb |

事件必须在**将触发的那颗 CPU** 上 `add`。

### 7.2 启动 / IRQ / 读时

```c
void rendezvos_time_init(void);
void rendezvos_do_time_irq(struct trap_frame *tf);
tick_t rendezvos_time_now(void);   /* 本核 boot_base */
i64 jeffies_get(void);             /* BSP boot_base / jeffy_ticks；≠ tick_cnt */
```

| 接口 | 说明 |
|------|------|
| `rendezvos_time_init` | 每核；BSP 校准 `clock_hz` / `jeffy_ticks` / LPJ。 |
| `rendezvos_do_time_irq` | 扫到期；periodic 调 `change`；单次 EXPIRE：`AGAIN`/`NO_MEM` → `change(now+jeffy_ticks)`，否则 `fini`。末尾 `arch_reset_timer`。 |
| `rendezvos_time_now` | `arch_timer_read() - percpu(boot_base_time)`。 |
| `jeffies_get` | 用 **BSP** base；**不读** `tick_cnt`；`clock_hz==0`（尚未校准）时返回 0。 |

### 7.3 软件定时器（`rendezvos_timer_event_*`）

```c
error_t rendezvos_timer_event_init(event, periodic_gap, wait_port, token);
error_t rendezvos_timer_event_add / del / change(event, expires_at);
error_t rendezvos_timer_event_cancel(event);  /* del + CANCEL；不 fini */
error_t rendezvos_timer_event_fini(event);    /* 仅单次；放 port ref */
bool    rendezvos_timer_event_exist(event);
```

| 接口 | 说明 |
|------|------|
| `init` | 单次：`gap==0` 且 port 非空，`ref_get`；periodic：port 必须 NULL。 |
| `add`/`del`/`change`/`exist` | 操作**当前 CPU** 树；IRQ-off。同 `expired` 挂 `same_expired_list`。 |
| `cancel` | 线程上下文；`use_system_proxy=false`。 |
| `fini` | 仅单次；IRQ 在 EXPIRE 非可重试结果后调用（含永久失败丢消息）。 |

一个易踩的实现细节：`change` = 先 `del_inner` 再 `add_inner`。对**尚未入树**的事件调 `change`，`del_inner` 返回 `-E_REND_NOFOUND`、`change` 随即失败且**不会**补 `add`——它不是「不存在就插入」的 upsert，先 `add` 再 `change`。

### 7.4 延时与换算

```c
void udelay(u64 us); void mdelay(u64 ms);
u64 rendezvos_time_count_to_us / _ms(tick_t);
tick_t rendezvos_time_us_to_count / _ms_to_count(u64);
```

依赖 BSP `clock_hz` / `loop_per_jeffies`；未校准返回 0（换算）或忙等不准。

常量：`SYS_TIME_MS_PER_INT=10`，因而 `INT_PER_SECOND=100`。

**`udelay` 的实现细节：** `__udelay` 把 µs 折成空转圈数 `loops = (lpj × us × UDELAY_MUL) >> UDELAY_SHIFT`，其中 `UDELAY_MUL / 2³¹ ≈ 10⁻⁴`，恰是「us 占一个 jeffy（10 ms = 10000 µs）的比例」的定点近似——`lpj` 是每 jeffy 的圈数，乘上这个比例就得到所需圈数。`_udelay` 对超过 `UDELAY_MAX = 2000 µs` 的请求按 2 ms 一块递减累转，防止 `lpj × us` 溢出；`udelay_max_loop` 是「一整块对应的圈数」，在 `time_init` 里预计算好，免每块重复乘除。`mdelay(ms)` 即 `_udelay(..., ms × 1000)`。空转本体 `loop_delay(loop_cnt)` 是一条 `while (loop_cnt--);` 式循环——它**必须**带 `__attribute__((optimize("O0")))` 且参数 `volatile`：否则优化器会认定「空循环无副作用」直接删光，所有延时瞬间归零。

## 10. 限制与后续

- EXPIRE 永久失败直接 `fini`，等待线程可能收不到；`AGAIN`/`NO_MEM` 按 `jeffy_ticks` 重试，尚无重试预算上限。
- AP 不重校 `clock_hz` / LPJ。
- `time_now`（本核 base）与 `jeffies_get`（BSP base）基准核不同。
- `CNTV_*` 宏名用于 `CNTP_CTL`（位位置相同可正常工作，属命名遗留）；`generic_time.c` 内的 `get_virt_cnt` / `get_cval` 零调用方，且头文件未声明。
- RTC 未接入软件队列；无 HPET。
- timer IRQ 号走 DTB，失败单点 panic。
- §9 测例未覆盖：heartbeat 本身、`udelay`/`mdelay`、周期事件与 AGAIN/NO_MEM 重试链（见 §9 未覆盖清单）。
