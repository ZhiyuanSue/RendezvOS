# 时间与定时器子系统

v0.1 · 2026-08-29

本篇覆盖：`kernel/time/time.c`、`include/rendezvos/time.h`、`arch/x86_64/time/time.c`、`arch/x86_64/time/rtc.c`、`arch/x86_64/PIC/PIT.c`（**不是** `modules/driver/timer/8254.c`）、`arch/aarch64/time/generic_time.c`。

IRQ 注册见 IRQ 篇；LVT / GIC PPI 见 APIC / GIC 篇；`KMSG_OP_SYSTEM_TIMER_*` 见 kmsg 篇；投递 proxy 见收发篇；rb 结构见基础设施篇。

---

## 1. 概述

core 要三件事，不是 Linux 式时钟子系统：

1. **每核可编程的相对时间 IRQ**（`INT_PER_SECOND=100`，约 10ms 心跳）。  
2. **可排队的软件定时器**（per-CPU 红黑树）。  
3. **与 IPC 同构的到期/取消**（`TIMER_EXPIRE` / `TIMER_CANCEL`），等待线程在 port 上 `recv`，ISR **不**直接回调。

硬件 one-shot 重编程 + 软件周期心跳；one-shot 业务走 kmsg。

刻意不做：wall-clock/NTP、POSIX `timer_create`、跨核迁移定时器、CFS tick。兼容层在 `rendezvos_timer_event_*` 上搭 sleep/alarm。

---

## 2. 目标与边界

**提供：** arch 计数/编程钩子；per-CPU 事件树；heartbeat；udelay；IPC 集成的 one-shot（model B：init hold port ref）。

**不做：** 墙钟权威（RTC 仅 x86 读 CMOS 打印）；跨核共享一棵树。

**并发：** 树操作必须关 IRQ（`time.c` 注释：syscall 可继承用户 IRQ 开，与 timer IRQ 并发会毁树）。

---

## 3. 分层与调用方

| 场景 | 用法 |
|------|------|
| one-shot | `init(event, 0, wait_port, token)` → `add(now+delta)` → port `recv` → 校验 token → `fini` |
| cancel | `cancel`：del + CANCEL kmsg（`proxy=false`）；**不** fini、不放 port ref |
| periodic / heartbeat | `periodic_gap != 0`，`wait_port==NULL`；IRQ 内 `change`；**勿** fini |
| Boot | 每核 `arch_start_core` → `rendezvos_time_init` |

事件必须在**将触发的那颗 CPU** 上 add。

---

## 4. 数据结构与不变量

### 4.1 事件

`rendezvos_timer_event`：rb 节点 + `same_expired_list`（同 `expired` 不占独立 rb 节点）+ `periodic_gap` / `wait_port` / `delivery_token`。

Model B：`init` 时 `ref_get` port；`fini` 或成功 EXPIRE 才 `ref_put`。

### 4.2 Per-CPU / 全局

| 量 | 范围 |
|----|------|
| `event_tree_root`、`heartbeat_event`、`boot_base_time`、`tick_cnt` | per-CPU |
| `heartbeat_gap`、`clock_hz`、`jeffy_ticks`、`loop_per_jeffies` | 全局（BSP 校准，AP 共用） |

### 4.3 读时语义（易混）

| API | 基准 |
|-----|------|
| `rendezvos_time_now()` | **本核** `boot_base_time` |
| `jeffies_get()` | `(arch_timer_read() - per_cpu(boot_base_time, BSP_ID)) / jeffy_ticks` — **不读** `tick_cnt` |
| `tick_cnt` | heartbeat 更新；主用途 LPJ 校准自旋 |

旧稿「jeffies 由 tick_cnt 更新」半错。

### 4.4 向量

| Arch | Timer 身份 |
|------|------------|
| x86 | `ARCH_IRQ_VEC_TIMER = 0x20`（=`timer_irq_num`）；LVT / PIC IRQ0 |
| aarch64 | INTID **PPI 30** → trap **94**（+64）；**不是 SPI** |

## 6. 流程

### 6.1 `rendezvos_time_init`（每核）

```text
register_irq_handler(timer_irq_num, rendezvos_do_time_irq, NEED_EOI)
heartbeat_gap = arch_init_timer(is_bsp)
boot_base_time = arch_timer_read()
init+add heartbeat_event   // periodic_gap=heartbeat_gap, wait_port=NULL
BSP: 校 clock_hz / jeffy_ticks / LPJ
```

时序：x86 在 `arch_enable_irq` **之后**；aarch64 在已开 IRQ + GIC CPU IF 之后（见 GIC 篇）。

### 6.2 `rendezvos_do_time_irq`

1. 反复取 rb 最小；`now < expired` 停。  
2. **periodic**（含 heartbeat）：`change(now+gap)`；本核 heartbeat 且有 `clock_hz` → `tick_cnt++`。  
3. **one-shot**：`timer_event_deliver_kmsg(EXPIRE, proxy=true)` → 成功 `fini`；**失败则 `change(now+1)` 重试，不 fini**（与部分头注释相反）。  
4. 下一 gap → `arch_reset_timer`；树空 fallback `heartbeat_gap`。

Payload：`"q"` = `delivery_token`。CANCEL 在线程上下文，`proxy=false`。

### 6.3 硬件

**x86：** `arch_irq_type` → PIC 用 8254；APIC 用 LVT（默认软 one-shot；BSP 可 TSC-DDL）。校准：`PIT_mdelay`。PIC 模式注释要求 SMP 走 APIC。

**aarch64：** 读 `CNTPCT_EL0`；编程 `CNTP_TVAL` + `CNTP_CTL`。频率 BSP 读 `CNTFRQ`。

**Quirk（必写）：** 代码编程 **物理 CNTP**，向量绑 **PPI 30**（惯例上常为 virtual；物理 EL1 常见 PPI **29**）。QEMU virt 上可能碰巧工作——**不是架构正确性**（与 GIC 篇一致）。

**Heartbeat 硬件形态：** 默认软件周期 + 硬件 one-shot 重编程，不是 LAPIC periodic 模式（除非显式 PERIODIC）。

## 10. 限制与后续

- EXPIRE 失败 ISR 内 `now+1` 忙重试 → 可能风暴。  
- AP 不重校 Hz/LPJ。  
- `time_now` vs `jeffies_get` 基准核不同。  
- CNTP vs PPI30 quirk。  
- RTC 未接入软件队列。
