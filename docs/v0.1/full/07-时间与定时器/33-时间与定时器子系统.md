## 1. 概述

core 要的不是 Linux 式时钟子系统，而是三件可组合的原语：

1. **每核可编程的相对时间 IRQ**（`INT_PER_SECOND=100`，约 10 ms 心跳粒度）。  
2. **可排队的软件定时器**（per-CPU 红黑树 + 同到期链表）。  
3. **与 IPC 同构的到期 / 取消**（`KMSG_OP_SYSTEM_TIMER_EXPIRE` / `CANCEL`）：等待线程在 port 上 `recv`，ISR **不**直接回调业务函数。

硬件侧一律按「下一次到期」编程；软件侧用 heartbeat 事件把周期感补出来。业务单次定时器走 kmsg，不把回调塞进 IRQ。

### 1.1 为什么这样拆

- **相对时间 IRQ 必须每核一份**：调度 / 本地延时 / 本核事件树都挂在「本核会响的那根线」上。板级墙钟（RTC）解决不了「10 ms 后叫醒本核」。  
- **x86 选型：** PIC 模式下只有 BSP 能收 8254 IRQ0——SMP 必须切 LAPIC Timer。TSC 读得准，但**本身不是 IRQ 源**；TSC-Deadline 仍占用 LVT Timer 向量。HPET 未接入（校准仍靠 PIT）。`ARAT_support` 可探测「深 C-state 下 APIC timer 是否仍跑」，**现行路径未据此选型**（见 `26` §5.4）。  
- **aarch64：** Generic Timer + 每核 PPI；IRQ 号由 DTB `arm,armv8-timer` 的 ns-phys 组给出（见 §6.4）。  
- **软件树与硬件单次模式配对**：硬件若只开 periodic，最近 deadline 难调；默认 `TIMER_TYPE_ONE_SHOT`（或 TSC-Deadline），IRQ 末尾按树顶重编程。heartbeat 是树里的周期事件，不是依赖 LVT Periodic 位。  
- **到期走 IPC**：ISR 里跑任意睡眠路径会毁推拉模型；投递 kmsg（可走 system proxy）让等待方在线程上下文处理，与 Port 篇一致。

刻意不做：墙钟权威 / NTP、POSIX `timer_create`、跨核迁移定时器、CFS 式 tick。兼容层若要 sleep / alarm，应在 `rendezvos_timer_event_*` 上搭，而不是另造一套 tick。

## 2. 目标与边界

**提供：** arch 读计数 / 编程钩子；per-CPU 事件树；heartbeat；`udelay` / `mdelay`（LPJ 自旋）；与 IPC 集成的单次定时器（model B：`init` 持有 port 引用）。

**不做：** 墙钟权威时间源（`rtc.c` 只读 CMOS 并打印）；跨核共享一棵树；HPET；riscv / loongarch 实现（空 `#elif`）。

**并发硬约束：** 树操作必须关 IRQ。`time.c` 注释写明——syscall 可继承用户态 IRQ 使能，若在开中断下改树，与 timer IRQ 并发会毁 rb。per-CPU 树不需要跨核锁，**关本核 IRQ 就够**。

---

## 3. 分层与调用方

| 场景 | 用法 |
|------|------|
| 单次 | `init(event, 0, wait_port, token)` → `add(now+delta)` → port `recv` → 校验 token → `fini` |
| cancel | `cancel`：先 del，再 CANCEL kmsg（`proxy=false`）；**不** fini、不放 port ref |
| periodic / heartbeat | `periodic_gap != 0`，`wait_port==NULL`；IRQ 内 `change`；**勿** fini |
| Boot | 每核 `arch_start_core` → `rendezvos_time_init` |

事件必须在**将触发的那颗 CPU** 上 `add`。跨核排队不在 v0.1 约定内。

## 4. 数据结构与不变量

### 4.1 事件

`rendezvos_timer_event`：rb 节点 + `same_expired_list`（同一 `expired` 不占独立 rb 节点，挂在头节点的链表上）+ `periodic_gap` / `wait_port` / `delivery_token`。

- 单次：`periodic_gap==0`，`wait_port` 必填；`init` 时 `ref_get_not_zero`；成功 EXPIRE 的 `fini` 或调用方 `fini` 才 `ref_put`。  
- Periodic：`wait_port` 必须为 NULL；只用 `del` 卸树，禁止 `fini`。

**投递失败语义（以 `.c` / 现行头文件注释为准）：** EXPIRE 失败走 `change(now+1)` **不** fini——保留事件与 port ref，避免丢令牌。（旧头注释「失败仍 fini」已对齐删除。）

### 4.2 Per-CPU / 全局

| 量 | 范围 |
|----|------|
| `event_tree_root`、`heartbeat_event`、`boot_base_time`、`tick_cnt` | per-CPU |
| `heartbeat_gap`、`clock_hz`、`jeffy_ticks`、`loop_per_jeffies`、`sys_timer_type` | 全局（BSP 校准，AP 共用 Hz / LPJ） |

### 4.3 读时语义（易混）

| API | 基准 |
|-----|------|
| `rendezvos_time_now()` | **本核** `arch_timer_read() - boot_base_time` |
| `jeffies_get()` | `(arch_timer_read() - per_cpu(boot_base_time, BSP_ID)) / jeffy_ticks` — **不读** `tick_cnt` |
| `tick_cnt` | heartbeat 路径更新；主用途是 LPJ 校准自旋等待「下一 jeffy」 |

「jeffies 由 `tick_cnt` 驱动」是半错：`tick_cnt` 跟着 heartbeat 走，但 `jeffies_get` 直接读硬件计数。

### 4.4 向量 / INTID

| Arch | Timer 身份 |
|------|------------|
| x86 | `arch_get_timer_irq_num` → `ARCH_IRQ_VEC_TIMER`（`0x20`）；写入 LVT Timer 或 PIC IRQ0→`0x20` |
| aarch64 | BSP 从 DTB `arm,armv8-timer` 的 **第 2 组** interrupts（ns-phys / CNTP）解析 PPI→INTID→trap；virt 上常见为 PPI14→INTID **30**→trap **94** |

## 6. 流程

### 6.1 `rendezvos_time_init`（每核）

```text
timer_irq = arch_get_timer_irq_num(is_bsp)   // aarch64: BSP 读 DTB 一次并缓存
register_irq_handler(timer_irq, rendezvos_do_time_irq, IRQ_NEED_EOI)
heartbeat_gap = arch_init_timer(is_bsp)
boot_base_time = arch_timer_read()
init+add heartbeat_event   // periodic_gap=heartbeat_gap, wait_port=NULL
BSP: clock_hz / jeffy_ticks / LPJ 校准
```

时序：x86 在 `arch_enable_irq` **之后**（APIC 软使能常拖到本函数内的 `arch_init_timer`）；aarch64 在已开 IRQ + GIC CPU IF 之后（见 GIC 篇）。先挂 handler 再让硬件响第一声 tick。

### 6.2 `rendezvos_do_time_irq`

1. 反复取 rb 最小；`now < expired` 停。  
2. **periodic**（含 heartbeat）：`change(now+gap)`；若是本核 heartbeat 且已有 `clock_hz` → 按 `(now-base)/jeffy_ticks` 写 `tick_cnt`。  
3. **单次**：`timer_event_deliver_kmsg(EXPIRE, proxy=true)` → 成功则 `fini`；**失败则 `change(now+1)` 重试，不 fini**。  
4. 按下一树顶算 gap → `arch_reset_timer`；树空则 fallback `heartbeat_gap`（正常不应发生——heartbeat 会再入树）。

载荷格式 `KMSG_FMT_SYSTEM_TIMER = "q"`，值为 `delivery_token`。CANCEL 在线程上下文调用，`use_system_proxy=false`。

同到期链表：卸下 rb 头时若链表非空，把后继提升为新头再插入，IRQ 循环下一轮继续扫。

### 6.3 硬件：x86

**选型（`arch_irq_type`）：**

| 模式 | 时钟源 | 读时 | 重编程 |
|------|--------|------|--------|
| `PIC_IRQ` | 8254 Channel0 → 8259 IRQ0 → 向量 `0x20` | `PIT_timer_read`（软件累加 `pit_timer_base` + latch） | Mode0 单次 + `PIT_update_timer`；**仅 BSP**（注释：SMP 必须走 APIC） |
| `xAPIC_IRQ` / `x2APIC_IRQ` | LAPIC Timer（或 TSC-Deadline） | `APIC_timer_read` | `APIC_timer_reset` |

**8254（`PIT.c`）：** 控制口 `43h`，计数器0 口 `40h`。Mode0（方式0）= 计数结束一次中断，供系统 tick / 校准；Mode2 循环发生器在代码里有，时间路径默认不用。`PIT_mdelay` 用 Mode0 忙等，给 APIC / TSC 校准当**已知频率参考**（`PIT_TICK_RATE ≈ 1.193181 MHz`）。16 位计数器限制单次延时上限（注释约 25 ms 量级），校准拆成多次 `APIC_CALIBRATE_MS`。

**LAPIC Timer（SDM）：**

- **LVT Timer**：向量 = `arch_get_timer_irq_num`（`0x20`）；模式位选 单次 / 周期 / TSC-Deadline。  
- **DCR**：本仓库校准与运行用 **÷16**（`APIC_DCR_DIV_16`）。`APIC_timer_hz` 对非 TSC 路径返回 `apic_hz_per_second >> 4`，与 INIT_CNT 域一致。  
- **INIT_CNT / CURR_CNT**：写入初值后递减；到 0 经 LVT 投递。软件用 `apic_timer_base` + `apic_timer_gap` 拼出单调读数。  
- **TSC-Deadline**：若 `TSC_DDL_support()`，BSP 设 `sys_timer_type = TIMER_TYPE_X86_TSC_DDL`，校准用 `rdtsc` + `PIT_mdelay`；到期写 MSR `IA32_TSC_DEADLINE`，仍走同一 LVT 向量。  
- **默认 `sys_timer_type = TIMER_TYPE_ONE_SHOT`**：即使硬件支持 Periodic，v0.1 也用软件周期 + 硬件单次模式重编程（除非显式切 PERIODIC / TSC-DDL）。

**软使能陷阱：** `software_enable_APIC()` 在 `arch_init_timer` 末尾，不在 `init_irq`。开 `sti` 与「APIC 开始干活」之间可能有窗口——排障时别假设 `init_irq` 完就能收 timer。

**RTC：** `get_rtc_time` 经 CMOS index/data 口读 BCD 年月日时分秒并打印。不是 IRQ 源，不驱动事件树。墙钟语义若需要，由链接方 / 兼容层另维护。

### 6.4 硬件：aarch64

**Generic Timer（ARM ARM）：** 系统计数器 + 每 PE 多套 timer（EL1/EL2/EL3 的 phys / virt）。本仓库只用 **EL1 physical**：读 `CNTPCT_EL0`，编程 `CNTP_*`。头文件里还有未接线的 `get_virt_cnt`（`CNTVCT`）/ `get_compare_value`（`CNTV_CVAL`），勿当成现行路径。

**TimerValue vs CompareValue：**

| 视图 | 寄存器 | 含义 |
|------|--------|------|
| **TV（本仓库）** | `CNTP_TVAL_EL0` | 近似 32 位**倒计时**：写「再过多少 tick 响」；硬件内部会换算成 CVAL |
| **CV** | `CNTP_CVAL_EL0` | 64 位**绝对比较值**：计数器 ≥ CVAL 时响 |

`arch_init_timer` / `arch_reset_timer` 都写 **TVAL**。源码旁「compare value way」注释是旧措辞，**以实际 `msr CNTP_TVAL` 为准**。

其余：

- **读：** `CNTPCT_EL0`（读前 `isb`）。  
- **使能：** `CNTP_CTL_EL0`；宏名用了 `CNTV_CTL_EL0_ENABLE`——ENABLE 位位置相同，能工作，但「物理定时器 / 虚拟控制宏」名字混用。  
- **频率：** BSP `mrs CNTFRQ_EL0` → `timer_freq`；`time_irq_cycle = timer_freq / INT_PER_SECOND`。  

**IRQ 号来源：** `arch_get_timer_irq_num`——BSP 读 DTB `arm,armv8-timer` 的 **第 2 组** interrupts（ns-phys）并缓存；AP 复用；失败 **统一** `kernel_panic`（不再分多处失败路径）。同节点常见：第 1 组 secure phys、第 3 组 virt——不要误读。QEMU virt 上 ns-phys 多为 PPI INTID 30（trap 94），换板以 DTB 为准。

**Heartbeat 硬件形态：** 与 x86 相同——软件周期事件 + 硬件单次模式重装 TVAL，不是「内核假设 PPI 自动周期」。

## 7. 公开 API

本篇拥有：可移植时间与软件定时器——`rendezvos/time.h`（`rendezvos_time_*` / `rendezvos_timer_event_*` / `jeffies_get` / `udelay`/`mdelay`）、arch 钩子声明（`arch_init_timer` / `reset` / `read` / `get_hz`）、x86 `get_rtc_time`、aarch64 Generic Timer 实现细节（`generic_time.c`）。以头文件注释为准（`rendezvos/time.h`；已与 `kernel/time/time.c` 核对）。

**本篇不拥有：** `register_irq_handler` / EOI → `25`；8254 / LAPIC Timer 后端（`PIT_*`、`APIC_timer_*`、`software_enable_APIC`）→ `26`；GIC PPI 投递 → `27`；`KMSG_OP_SYSTEM_TIMER_*` 载荷约定 → `20`；`ipc_system_try_deliver` → `19`。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 顺序 |
|------|------|
| 每核启动 | IRQ 路径就绪后 → **`rendezvos_time_init`**（内：挂 handler → `arch_init_timer` → heartbeat） |
| 单次 | `init(event,0,port,token)` → `add(now+δ)` → port `recv` → 校验 token → **`fini`** |
| cancel | **`cancel`**（del + CANCEL kmsg）→ 可选再 **`fini`**（cancel **不**放 port ref） |
| periodic / heartbeat | `init(gap,NULL,0)` → `add`；卸树只用 **`del`**，禁止 `fini` |
| 树读写 | **关本核 IRQ**（API 内部已做）；勿在开中断的 syscall 路径手工摸 rb |

事件必须在**将触发的那颗 CPU** 上 `add`。

### 7.2 启动 / IRQ / 读时

```c
void rendezvos_time_init(void);
void rendezvos_do_time_irq(struct trap_frame *tf);
tick_t rendezvos_time_now(void);   /* 本核 boot_base */
i64 jeffies_get(void);             /* BSP boot_base / jeffy_ticks；≠ tick_cnt */
```

| 接口 | 说明 |
|------|------|
| `rendezvos_time_init` | 每核；BSP 校准 `clock_hz` / `jeffy_ticks` / LPJ。 |
| `rendezvos_do_time_irq` | 扫到期；periodic→`change`；单次 EXPIRE 成功→`fini`，失败→`change(now+1)`。末尾 `arch_reset_timer`。 |
| `rendezvos_time_now` | `arch_timer_read() - percpu(boot_base_time)`。 |
| `jeffies_get` | 用 **BSP** base；**不读** `tick_cnt`。 |

### 7.3 软件定时器（`rendezvos_timer_event_*`）

```c
error_t rendezvos_timer_event_init(event, periodic_gap, wait_port, token);
error_t rendezvos_timer_event_add / del / change(event, expires_at);
error_t rendezvos_timer_event_cancel(event);  /* del + CANCEL；不 fini */
error_t rendezvos_timer_event_fini(event);    /* 仅单次；放 port ref */
bool    rendezvos_timer_event_exist(event);
```

| 接口 | 说明 |
|------|------|
| `init` | 单次：`gap==0` 且 port 非空，`ref_get`；periodic：port 必须 NULL。 |
| `add`/`del`/`change`/`exist` | 操作**当前 CPU** 树；IRQ-off。同 `expired` 挂 `same_expired_list`。 |
| `cancel` | 线程上下文；`use_system_proxy=false`。 |
| `fini` | 仅单次；IRQ 仅在 EXPIRE **成功**后调用。 |

### 7.4 延时与换算

```c
void udelay(u64 us); void mdelay(u64 ms);
u64 rendezvos_time_count_to_us / _ms(tick_t);
tick_t rendezvos_time_us_to_count / _ms_to_count(u64);
```

依赖 BSP `clock_hz` / `loop_per_jeffies`；未校准返回 0（换算）或忙等不准。

常量：`SYS_TIME_MS_PER_INT=10` → `INT_PER_SECOND=100`。

### 7.5 Arch 钩子（声明在本篇；实现分 arch）

```c
u64 arch_init_timer(bool is_bsp);
void arch_reset_timer(u64 next_event_gap);
tick_t arch_timer_read(void);
tick_t arch_timer_get_hz(void);
/* x86 only */
struct rtc_time get_rtc_time(void);  /* CMOS 打印；不进事件树 */
```

后端细节（PIT / LVT / DCR）见 `26`；CNTP TVAL / DTB ns-phys 见本篇 §6.4。

## 10. 限制与后续

- EXPIRE 失败在 ISR 内 `now+1` 忙重试 → 可能风暴。  
- AP 不重校 `clock_hz` / LPJ。  
- `time_now`（本核 base）与 `jeffies_get`（BSP base）基准核不同。  
- `CNTV_*` 宏名写进 `CNTP_CTL`；`get_virt_cnt` / `get_compare_value` 未接线。  
- RTC 未接入软件队列；无 HPET。  
- （已对齐）`fini`：EXPIRE 失败不 fini；timer IRQ 号走 DTB，失败单点 panic。
