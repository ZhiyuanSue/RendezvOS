# 名称索引注册表

v0.1 · 2026-09-27

本篇覆盖：`kernel/registry/name_index.c`、`include/rendezvos/registry/name_index.h`。

port 注册表消费见 `19-Port与消息模型.md`；线程 port LRU / token 见 TM 篇；MCS 双 `me` 禁忌见锁篇。

**纠正：** VSpace「按名注册」是 **rb_tree + CAS**（Compare-And-Swap，比较并交换），**不是** name_index。目前生产实例基本只有 **`global_port_table.by_name`**——原语可复用，不是「多实例广泛复用」。

本篇几乎不涉及板级硬件；并发上主要涉及 **MCS 锁 + per-CPU `me` 节点**。

---

## 1. 概述

`name_index_t`：把字符串键映射到对象指针的扁平注册表。实现是 **行数组**（slot + generation）+ **开放寻址哈希** + 一把 MCS 锁；可选 hold/drop、on_register/unregister；**token**（`row_index` + `row_gen`）供无锁外缓存后 `resolve`。

给 port 名做均摊 O(1) 查找；不是层级命名空间，没有通配。

### 1.1 为什么需要 token

热路径（`thread_lookup_port`）避免每次 strcmp 扫字符串。缓存 `(row_index, row_gen)`，下次 `resolve` 校验 generation——行被 unregister 再复用时 gen 变，旧 token 失效。

### 1.2 数据结构鸟瞰

```text
  name_index_t
  │  lock（MCS，单把）
  │  hooks（get_name / hold / drop / on_*）
  │
  ├─ rows[]：行数组
  │     rows[i]
  │       used : 0/1
  │       gen  : u64
  │       value / next_free（占用存对象，空闲串链）
  │
  └─ ht[]：开放寻址哈希桶（i64）
        EMPTY = -1   ← 空桶
        TOMB  = -2   ← 删除墓碑
        ≥0           ← row_idx，指回 rows[i]

  token = { row_index, row_gen }
    行内 gen 是 u64；写出 token 时截成 u16
```

桶值三种哨兵：`EMPTY=-1`（从未写入）、`TOMB=-2`（删除后留坑，probe 时跳过但可复用）、`row_idx≥0`（指向 rows 中对应行）。线性探测（linear probing）遇 `EMPTY` 终止、遇 `TOMB` 继续并记可复用槽、遇匹配 key 命中。

## 2. 目标与边界

**提供：** register / lookup / resolve / unregister；HT grow/shrink；钩子。

**不做：** 通配、路径层级、per-thread cache（那在 `Thread_Base`）；同名查重（**name_index 层可插两行同名**——**port 层**先 `search` 再拒）。
---

## 3. 分层与调用方

| 入口 | 谁加锁 | percpu `me` |
|------|--------|-------------|
| `register_port` / `unregister` / `port_is_live` | **port 层**持 `by_name.lock`，再调**无锁**的 search/register/unregister | `port_table_spin_lock` |
| `name_index_lookup` / `resolve` / `fini` | **name_index 内部** `lock_mcs` | `name_index_spin_lock` |

对**同一把** `by_name.lock`、两套 `me`——合法（MCS 要求 `me` 是当前 CPU 的节点），但 **同 CPU 禁止嵌套**两条会争用同一把锁的入口（双节点自死锁）。详见锁篇。

Token 缓存：`thread_lookup_port` 热路径优先 `resolve`。

## 4. 数据结构：rows、ht、token 各管什么

§1 已说明：这是「字符串到对象指针」的扁平原语，并用 `name_index_token_t`（`row_index` + `row_gen`）供线程侧 cache 后 `resolve`。鸟瞰图见 §1.2；下面按字段说明用途。哈希怎么算见 §6.1。

```c
typedef struct {
        u32 row_index;
        u16 row_gen;
} name_index_token_t;

struct name_index_row {
        u64 gen;
        u64 used; /* 0 free, 1 used */
        union {
                void *value;
                u64 next_free;
        } storage;
};

typedef struct name_index {
        spin_lock lock;
        struct allocator *alloc;
        void *owner_context;
        name_index_get_name_fn get_name;
        name_index_hold_fn hold;
        name_index_drop_fn drop;
        name_index_on_register_fn on_register;
        name_index_on_unregister_fn on_unregister;
        struct name_index_row *rows;
        u64 row_cap;
        u64 free_head;
        u64 live;
        i64 *ht;
        u64 ht_cap, ht_mask, ht_tombs;
        u32 name_len_max;
} name_index_t;
```

| 字段 / 概念 | 为什么要有 |
|-------------|-----------|
| `rows[]` + `row_cap` | 槽位数组。一行对应一个已登记（或空闲）条目。 |
| `row.used` | 区分占用 / 空闲。 |
| `row.gen` | 行被拿去复用前递增。外面若缓存了旧代际，注销后再占用同一行时代际对不上，旧缓存自动失效。行内是 64 位；写进缓存记号时截成 16 位（极长期回绕有理论风险，见文末限制）。 |
| `storage.value` / `next_free` | 占用时存对象指针；空闲时串成空闲链表。 |
| `free_head` | 空闲行链表头，分配槽位常数时间。 |
| `live` | 当前占用行数，用来决定要不要扩哈希表。 |
| `ht[]` | 开放寻址的哈希桶。取值：空、删除后留下的「墓碑」、或指向某一行的下标。 |
| `ht_cap` / `ht_mask` / `ht_tombs` | 容量、取模用的掩码、墓碑个数（决定要不要缩表）。 |
| `name_len_max` | 名字最长多少；Port 侧用 64。 |
| `lock` | 一把可扩展自旋锁。按名查找 / 按记号解析 / 销毁时**内部**加锁；登记 / 注销 / 无锁搜索则**假定调用方已经持锁**（Port 层就是这样包的）。 |
| `get_name` 等钩子 | 索引不认识具体对象类型：用钩子取名字、在查找成功时加引用、在登记/注销时通知上层（例如 Port 改生命周期）。 |
| `owner_context` | 传给上述回调的上下文（例如所属 port 注册表）。 |
| `name_index_token_t` | `{row_index, row_gen}`，给线程侧热路径 cache 用，避免每次 `strcmp`（§1.1）。 |
**名字怎么映射到首个桶：** 把名字每个字节混进一个 64 位数（源码按常见的 FNV-1a 字符串哈希风格——非加密、算得快），再对表容量取模；冲突则顺着桶位往后探。不必按密码学哈希理解。

其它约定：

- 初始大约 32 行、64 桶；占用超过约七成则扩容；负载很低且墓碑很多时缩容。
- **加引用钩子可空。** 空：返回裸指针，不额外加引用。非空：返回非空指针就表示加引用已经成功，调用方用完必须配对放掉；加引用失败则当作没找到。Port 侧的加引用就是「引用计数尚非零才成功」。

## 6. 流程

```text
Cold:  name_index_lookup(idx, name, &tok)  → 内部加锁 + hold
Hot:   name_index_resolve(idx, &tok, name) → 校验 gen + hold
Register(port):
  持 by_name.lock
  search → 已有同名则 -E_RENDEZVOS
  name_index_register → on_register
Unregister:
  持锁 → unregister(row_idx, name) → unlock 后 ops drain（Port 篇）
```

### 6.1 哈希查找 / 插入算法

```text
hash(name) = 按字节混合（FNV-1a 风格，见 §4），结果 mod ht_size 得首桶 j

lookup / search:
  j = hash(name) % ht_size
  first_tomb = -1
  while ht[j] != EMPTY:                 // EMPTY 终止
      if ht[j] == TOMB:
          if first_tomb < 0: first_tomb = j   // 记首个可复用墓碑
      else if ht[j] == row_idx and rows[row_idx].used
          and strcmp(get_name(rows[row_idx].value), name) == 0:
          return rows[row_idx].value    // 命中
      j = (j + 1) % ht_size             // 线性探测
  return NULL                           // 未命中

register:
  先按上面 search 找空位（first_tomb 优先，否则首个 EMPTY）
  → 分配空闲行 row_idx（空闲链取出一个，gen++）
  → rows[row_idx] = {used=1, value, gen}
  → ht[空位] = row_idx
  → 若 live > 70% 触发 grow（扩容 + rehash）
```

墓碑（TOMB）的作用：删除后不能直接置 `EMPTY`，否则会截断后续 probe 链；先留 `TOMB`，查找时跳过、插入时复用。`shrink` 在 `load ≤ 25%` 且墓碑足够多时触发，rehash 顺带清理墓碑。

## 7. 公开 API

本篇涉及的接口分布在：字符串键注册表原语——`name_index_t` / token / register·lookup·resolve·unregister（`registry/name_index.h`）。以头文件注释为准（见该头；已与 `name_index.c` 核对）。

**本篇不涉及：** `Port_Table` / `register_port` / 同名拒绝（见 `19`）；`thread_lookup_port` token LRU（见 `13`）；MCS / 双 `me` 纪律（见 `31`）。VSpace 命名 **不是** name_index。

生产实例：基本只有 **`global_port_table.by_name`**。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 锁 / `me` | 顺序 |
|------|-----------|------|
| Port 注册 | port 持 `by_name.lock`（`port_table_spin_lock`） | 先 `search`，已有则拒，否则 **`name_index_register`**（无锁 API） |
| Port 注销 | 同上持锁 | **`name_index_unregister`**，unlock 后 ops drain（`19`） |
| 冷查找 | name_index **内部**加锁（`name_index_spin_lock`） | **`name_index_lookup`** 后 hold |
| 热路径 | 同上 | **`name_index_resolve(tok, name)`** |
| 同 CPU | — | **禁止**嵌套 port 与 name_index 两套 `me` 争用同一把锁 |

hold 成功后调用方必须 drop（port 用 refcount 钩子）。「若设置了 hold 则必须成功」= **非 NULL 返回值保证 hold 已做过**，不是「hold 禁止返回 false」（失败时 lookup/resolve 直接 NULL）。

### 7.2 类型与 token

```c
typedef struct { u32 row_index; u16 row_gen; } name_index_token_t;
void name_index_token_invalidate(name_index_token_t *tok);

typedef struct name_index {
        spin_lock lock;
        /* hooks: get_name / hold / drop / on_register / on_unregister */
        struct name_index_row *rows;  i64 *ht;  u32 name_len_max;
        …
} name_index_t;
```

行内 `gen` 为 u64，token 截 **u16**。HT：`EMPTY=-1` / `TOMB=-2` / row_idx；live&gt;70% grow。

### 7.3 生命周期 / 无锁 API（调用方已持锁）

```c
void name_index_init(idx, alloc, name_len_max, owner, get_name, hold, drop,
                     on_register, on_unregister);
void name_index_fini(idx);                    /* 内部加锁 */

void *name_index_search(idx, name, &row_idx); /* 无 hold；不查重 */
error_t name_index_register(idx, value, &row_idx);
void name_index_register_abort(idx, row_idx, value);
void name_index_unregister(idx, value, row_idx, name);
```

### 7.4 加锁查找

```c
void *name_index_lookup(idx, name, tok_out);           /* 锁 + hold */
void *name_index_resolve(idx, const tok, name);        /* 锁 + gen 校验 + hold */
```

同名查重在 **port 层**；本层 register 可插两行同名（勿依赖）。
