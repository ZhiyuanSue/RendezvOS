# 名称索引注册表

v0.1 · 2026-09-27

本篇覆盖：`kernel/registry/name_index.c`、`include/rendezvos/registry/name_index.h`。

port 注册表消费见 Port 篇（`19`）；线程 port LRU / token 见线程篇（`13`）；MCS 双 `me` 禁忌见锁篇（`31`）。

**纠正：** VSpace 并不按名注册——`register_vspace` 把它挂进以 `vspace_root_addr` 为键的 rb_tree，插入用 `vspace_register_lock` 这把 CAS 锁（Compare-And-Swap，比较并交换）包住，与 name_index 无关。目前生产实例基本只有 **`global_port_table.by_name`**——原语可复用，不是「多实例广泛复用」。

本篇几乎不涉及板级硬件；并发上主要涉及 **MCS 锁 + per-CPU `me` 节点**。

---

## 1. 概述

`name_index_t`：把字符串键映射到对象指针的扁平注册表。实现是 **行数组**（slot + generation）+ **开放寻址哈希** + 一把 MCS 锁；可选 hold/drop、on_register/on_unregister 钩子；**token**（`row_index` + `row_gen`）供上层缓存后走 `resolve` 快路径。

名字本身**不进索引**——登记时只存对象指针，比较时经 `get_name` 钩子现取。因此 value 的名字必须在其登记期间保持稳定（port 的 `name[64]` 内嵌在对象里，天然满足）。

给 port 名做均摊 O(1) 查找；不是层级命名空间，没有通配。

### 1.1 为什么需要 token

热路径（`thread_lookup_port`）想跳过的是**哈希计算与探测链扫描**：缓存 `(row_index, row_gen)`，`resolve` 直接按行下标定位，不再走 hash→probe 整条链。注意 `resolve` **仍会做一次** `strcmp_s`——`name` 参数是必选项而非可省项，这是针对 u16 代际回绕别名的安全阀：万一旧 token 的代际与复用后的新行凑巧对上，靠全名比对兜底拒绝。

行被 unregister 时 gen 递增，旧 token 随之失效；也可显式失效——`name_index_token_invalidate` 把 `row_index` 置 `U32_MAX` 哨兵，`resolve` 对它在**加锁之前**就返回 NULL。

### 1.2 数据结构鸟瞰

```text
  name_index_t
  │  lock（MCS，单把）
  │  hooks（get_name / hold / drop / on_*）
  │
  ├─ rows[]：行数组
  │     rows[i]
  │       used : 0/1
  │       gen  : u64
  │       value / next_free（占用存对象，空闲串链）
  │
  └─ ht[]：开放寻址哈希桶（i64）
        EMPTY = -1   ← 空桶
        TOMB  = -2   ← 删除墓碑
        ≥0           ← row_idx，指回 rows[i]

  token = { row_index, row_gen }
    行内 gen 是 u64；写出 token 时截成 u16
```

桶值三种哨兵：`EMPTY=-1`（从未写入）、`TOMB=-2`（删除后留坑）、`row_idx≥0`（指向 rows 中对应行）。线性探测（linear probing）按**用途**分两条路：**查找**遇 `EMPTY` 终止、遇 `TOMB` 直接跳过（不记录复用槽——查找路径不关心插坑）；**插入**则取探测路上**第一个 `EMPTY` 或 `TOMB`** 就写（先到先得，并非「墓碑优先」），复用墓碑时顺带 `ht_tombs--`。

## 2. 目标与边界

**提供：** register / lookup / resolve / unregister；HT grow/shrink；钩子。

**不做：** 通配、路径层级、per-thread cache（那在 `Thread_Base`）；同名查重（**name_index 层可插两行同名**——**port 层**先 `search` 再拒；同名且同对象则按幂等放行 `REND_SUCCESS`）。

---

## 3. 分层与调用方

| 入口 | 谁加锁 | percpu `me` |
|------|--------|-------------|
| `register_port` / `unregister_port` / `port_table_port_is_live` | **port 层**持 `by_name.lock`，再调**无锁**的 search/register/unregister | `port_table_spin_lock` |
| `name_index_lookup` / `resolve` / `fini` | **name_index 内部** `lock_mcs` | `name_index_spin_lock` |

对**同一把** `by_name.lock`、两套 `me`——`port.c` 与 `name_index.c` 各 `DEFINE_PER_CPU` 了一组 `spin_lock_t` 节点伺候同一把锁——合法（MCS 要求 `me` 是当前 CPU 的节点），但 **同 CPU 禁止嵌套**两条会争用同一把锁的入口（双节点自死锁）。详见锁篇（`31`）。

Token 缓存：`thread_lookup_port` 热路径不直接查索引，而是先过**每线程 16 项**的端口名缓存（`THREAD_MAX_KNOWN_PORTS`）——线程侧另有一套自己的 **64 位** FNV-1a 做预筛，哈希命中只是候选，最终仍要 `name_index_resolve(token, name)` 在锁内做代际 + 全名双校验才拿引用。token 失效（stale）就逐出该缓存项再试下一候选；缓存**不钉住**端口，每次命中都重新校验并重新持引用。细节见线程篇（`13`）。

## 4. 数据结构：rows、ht、token 各管什么

§1 已说明：这是「字符串到对象指针」的扁平原语，并用 `name_index_token_t`（`row_index` + `row_gen`）供线程侧 cache 后 `resolve`。鸟瞰图见 §1.2；下面按字段说明用途。哈希怎么算见 §6.1。

```c
typedef struct {
        u32 row_index;
        u16 row_gen;
} name_index_token_t;

struct name_index_row {
        u64 gen;
        u64 used; /* 0 free, 1 used */
        union {
                void *value;
                u64 next_free;
        } storage;
};

typedef struct name_index {
        spin_lock lock;
        struct allocator *alloc;
        void *owner_context;
        name_index_get_name_fn get_name;
        name_index_hold_fn hold;
        name_index_drop_fn drop;
        name_index_on_register_fn on_register;
        name_index_on_unregister_fn on_unregister;
        struct name_index_row *rows;
        u64 row_cap;
        u64 free_head;
        u64 live;
        i64 *ht;
        u64 ht_cap, ht_mask, ht_tombs;
        u32 name_len_max;
} name_index_t;
```

| 字段 / 概念 | 为什么要有 |
|-------------|-----------|
| `rows[]` + `row_cap` | 槽位数组。一行对应一个已登记（或空闲）条目。 |
| `row.used` | 区分占用 / 空闲。 |
| `row.gen` | 代际。递增发生在**释放**时——unregister / register_abort / fini 把行归还空闲链的那一刻；分配时**不**动 gen，行首次使用代际为 0。外面若缓存了旧代际，行被回收再占用后对不上，旧缓存自动失效。行内是 64 位；写进缓存记号时截成 16 位（极长期回绕有理论风险，见文末限制）。 |
| `storage.value` / `next_free` | 占用时存对象指针；空闲时串成空闲链表。 |
| `free_head` | 空闲行链表头，分配槽位常数时间。 |
| `live` | 当前占用行数，用来决定要不要扩哈希表。 |
| `ht[]` | 开放寻址的哈希桶。取值：空、删除后留下的「墓碑」、或指向某一行的下标。 |
| `ht_cap` / `ht_mask` / `ht_tombs` | 容量、取模用的掩码、墓碑个数（决定要不要缩表）。 |
| `name_len_max` | 名字最长多少；Port 侧用 64。 |
| `lock` | 一把 MCS 自旋锁——类型 `spin_lock` 是**队列头指针**（`NULL`＝无人持锁），等待者用 per-CPU 的 `{next, spin}` 节点排队。按名查找 / 按记号解析 / 销毁时**内部**加锁；登记 / 注销 / 无锁搜索则**假定调用方已经持锁**（Port 层就是这样包的）。 |
| `get_name` 等钩子 | 索引不认识具体对象类型：用钩子取名字、在查找成功时加引用、在登记/注销时通知上层（例如 Port 改生命周期）。 |
| `owner_context` | 传给上述回调的上下文（例如所属 port 注册表）。 |
| `name_index_token_t` | `{row_index, row_gen}`，给线程侧热路径 cache 用，跳过哈希与探测链、直达行下标（§1.1；`resolve` 仍做一次全名比对兜底）。 |

**名字怎么映射到首个桶：** 32 位 FNV-1a（`offset=2166136261`、`prime=16777619`，非加密、算得快）：逐字节 `hash ^= b; hash *= prime`，**至多消费 `name_len_max` 字节**、遇 `\0` 早停；`name_len_max == 0` 时恒返回 0。首桶 `= hash & ht_mask`——容量恒为 2 的幂，按位与代替取模；冲突则顺着桶位往后线性探。注意这与线程侧端口缓存的 **64 位** FNV-1a 是**两套**哈希，别混为一谈（§3）。不必按密码学哈希理解。

其它约定：

- 初始**恰为** 32 行、64 桶（`NAME_INDEX_ROWS_INITIAL_CAP` / `NAME_INDEX_HT_INITIAL_CAP` 宏，编译期可覆盖）。行数组在空闲链掏空时**翻倍**扩容（旧空闲链原样串到新段之后，不丢槽位）。`live×100 > ht_cap×70` 触发哈希表倍增（检查发生在插入探测**之前**）；`ht_cap > 64` 且墓碑 ≥ 10% 容量、负载 ≤ 25%（或 `live == 0` 直接缩回 64）才缩容——缩容只发生在 **unregister / register_abort** 路径。rehash 按行序升序重新探测插入，墓碑就此清零。
- **加引用钩子可空。** 空：返回裸指针，不额外加引用。非空：返回非空指针就表示加引用已经成功，调用方用完必须配对放掉；加引用失败则当作没找到。Port 侧的加引用就是「引用计数尚非零才成功」。

## 6. 流程

```text
Cold:  name_index_lookup(idx, name, &tok)  → 内部加锁；先写 tok 再 hold
Hot:   name_index_resolve(idx, &tok, name) → 内部加锁；gen + 全名双校验 + hold
Register(port):
  持 by_name.lock
  search → 同名同对象→REND_SUCCESS（幂等）；同名异对象→-E_RENDEZVOS
  ops_allow(PORT_OPS_REGISTER) 门闩（可拒）
  name_index_register → 行分配 → ht_insert → on_register（ACTIVE→REGISTERED）
  ref_get_not_zero 给表持引用；失败→ name_index_register_abort 回滚 → -E_RENDEZVOS
Unregister(port):
  持锁 → search；无名或本就未 REGISTERED → REND_SUCCESS（幂等）
  unregister(row_idx, name)（on_unregister: table=NULL, REGISTERED→CLOSING）
  → unlock 后 ops drain + 清线程队列 + CLOSING→CLOSED（Port 篇）
```

### 6.1 哈希查找 / 插入算法

```text
hash(name) = 32 位 FNV-1a（§4），首桶 j = h & ht_mask（容量恒为 2 的幂）

lookup / search（ht_find_bucket）:
  for probe in 0..ht_cap:               // 最多探一整圈
      j = (h + probe) & ht_mask
      if ht[j] == EMPTY: return 未命中  // 终止
      if ht[j] == TOMB:  continue       // 只跳过，不记复用槽
      row = ht[j]；行不占用 / 名为空 / 名不等 → continue
      strcmp_s(get_name(row.value), name, name_len_max) == 0 → 命中

register（无锁原语；外层 port 编排见 §6）:
  前提：调用方持锁；get_name 必须存在、名字非空（否则 -E_IN_PARAM）
  行分配：free_head 弹出（空则行数组翻倍）；gen 不在这里动
  live++ 后才 ht_insert：
      先 maybe_grow（live>70% 倍增 + rehash）
      探测取第一个 EMPTY 或 TOMB 写入 row_idx（复用墓碑则 tombs--）
  插入失败 → 行原样归还空闲链（gen 不动，token 从未发过）
  成功 → on_register 回调

unregister / register_abort:
  校验 row 在界内、used 且 value 对得上（不符静默返回）
  name 非 NULL 才在 ht 里把命中桶置 TOMB（ht_tombs++）
  行归还：gen++ → 串回 free_head → live--
  maybe_shrink（仅这条路径）
```

墓碑（TOMB）的作用：删除后不能直接置 `EMPTY`，否则会截断后续 probe 链；先留 `TOMB`，查找时跳过、插入时先到先得地复用。`shrink` 条件三连：`ht_cap > 64`、`ht_tombs ≥ 10%×ht_cap`、负载 ≤ 25%（`live == 0` 则直接缩回 64），rehash 顺带把墓碑清零。另外，index 层允许的同名双行在 rehash 后哪行先被探测到取决于行序与桶位，**查找可见性不稳定**——「勿依赖同名两行」在 rehash 后更是如此。

## 7. 公开 API

本篇涉及的接口集中在一个头文件：字符串键注册表原语——`name_index_init` / `fini`、无锁侧 `search` / `register` / `register_abort` / `unregister`、带锁侧 `lookup` / `resolve`，以及 `name_index_t` / `name_index_token_t` 类型与 `name_index_token_invalidate`（`registry/name_index.h`）。以头文件注释为准（已与 `name_index.c` 核对）。

**本篇不涉及：** `Port_Table` / `register_port` / 同名拒绝（见 `19`）；`thread_lookup_port` token LRU（见 `13`）；MCS / 双 `me` 纪律（见 `31`）。VSpace 的注册机制 **不是** name_index（见篇首纠正）。

生产实例：基本只有 **`global_port_table.by_name`**。

### 7.1 编排顺序（调用方须遵守）

| 场景 | 锁 / `me` | 顺序 |
|------|-----------|------|
| Port 注册 | port 持 `by_name.lock`（`port_table_spin_lock`） | 先 `search`（同名同对象幂等放行，异对象拒绝），过 `ops_allow(REGISTER)` 门闩，再 **`name_index_register`**（无锁 API） |
| Port 注销 | 同上持锁 | **`name_index_unregister`**，unlock 后 ops drain（`19`） |
| 冷查找 | name_index **内部**加锁（`name_index_spin_lock`） | **`name_index_lookup`**（锁内 hold，成功经 `tok_out` 带回 token） |
| 热路径 | 同上 | **`name_index_resolve(tok, name)`**（gen + 全名双校验 + hold） |
| 同 CPU | — | **禁止**嵌套 port 与 name_index 两套 `me` 争用同一把锁 |

hold 成功后调用方必须 drop（port 用 refcount 钩子）。「若设置了 hold 则必须成功」= **非 NULL 返回值保证 hold 已做过**，不是「hold 禁止返回 false」（失败时 lookup/resolve 直接 NULL）。

### 7.2 类型与 token

```c
typedef struct { u32 row_index; u16 row_gen; } name_index_token_t;
void name_index_token_invalidate(name_index_token_t *tok);

typedef struct name_index {
        spin_lock lock;
        /* hooks: get_name / hold / drop / on_register / on_unregister */
        struct name_index_row *rows;  i64 *ht;  u32 name_len_max;
        …
} name_index_t;
```

行内 `gen` 为 u64，token 截 **u16**（`resolve` 比较时同样先截再比）。`row_index = U32_MAX` 是非法哨兵（`name_index_token_invalidate` 所置），`resolve` 见它**不加锁**直接返回 NULL。HT：`EMPTY=-1` / `TOMB=-2` / row_idx；负载超 70%（`live×100 > ht_cap×70`）触发 grow。

### 7.3 生命周期 / 无锁 API（调用方已持锁）

```c
void name_index_init(idx, alloc, name_len_max, owner, get_name, hold, drop,
                     on_register, on_unregister);
void name_index_fini(idx);                    /* 内部加锁 */

void *name_index_search(idx, name, &row_idx); /* 无 hold，裸指针；持锁期内有效（port 层查重用的就是它） */
error_t name_index_register(idx, value, &row_idx);
void name_index_register_abort(idx, row_idx, value);
void name_index_unregister(idx, value, row_idx, name);
```

`register` 要求 `get_name` 存在且名字非空（否则 `-E_IN_PARAM`）；插入 HT 失败会把行**原样**归还空闲链（gen 不动，token 从未发过）。`unregister` / `register_abort` 都先核对「行在界内、占用、且 value 对得上」，不符**静默返回**——防错行误删。`register_abort` 的实际用武之地在 port 层：`name_index_register` 已成功、但表引用 `ref_get_not_zero` 失败时的回滚（§6）。

### 7.4 加锁查找

```c
void *name_index_lookup(idx, name, tok_out);           /* 锁 + hold + 可选 token 输出 */
void *name_index_resolve(idx, const tok, name);        /* 锁 + gen + 全名双校验 + hold */
```

两个注意点。其一，`lookup` 在 hold **之前**就把 token 写进 `tok_out`——返回 NULL（含 hold 失败）时 `tok_out` 内容不可信，调用方必须丢弃；`thread_lookup_port` 正只在成功路径才把 token 入缓存。hold 失败与 miss 同为 NULL，调用方无需区分。其二，同名查重在 **port 层**；本层 register 可插两行同名（rehash 后可见性不稳定，§6.1，勿依赖）。

## 10. 限制与后续

- 同名查重在消费者（port 层）；index 层同名双行不仅可插，rehash 后哪行可见还不确定。
- u16 gen 截断：同代际别名靠 `resolve` 的全名比对兜底。
- 有界比较双刃剑：哈希与 `strcmp_s` 都只消费前 `name_len_max` 字节——两个**超出**该长度且前缀相同的名字会被视为同名（port 名缓冲 64 字节含 `\0`，实际名字 ≤63 字节，安全；复用方若名字更长须自审）。
- `unregister` 的 `name` 传 NULL 会**跳过 HT 删除**——行已归还但该桶仍指着它；后续查找虽会跳过（行不占用），该桶也再也清不掉——直到某次 grow/shrink 触发 rehash 整体重建 HT 才会被顺带抹去。契约上必须传真名。
- `fini` 只在 `drop` 钩子存在时逐个回调释放残余值；`drop == NULL` 时直接放掉 rows/ht 数组，残余对象归调用方自理。
- `init` 里引导性自举注册失败被静默忽略（`(void)`），靠首次 register 惰性重试——初始化阶段不留错误信号。
- 仅 port 生产实例。
- 双 `me` 嵌套禁忌依赖纪律（`port_table_spin_lock` 与 `name_index_spin_lock` 两套 per-CPU 节点伺候同一把 `by_name.lock`）。
