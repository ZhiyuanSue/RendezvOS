# 公共基础库与数据结构

v0.1 · 2026-10-02

本篇覆盖：`include/common/**`（重点 DSA（Data Structure Abstractions，数据结构抽象）/ refcount / types / atomic / string）、`kernel/mm/string.c`。

MSQ（Michael-Scott Queue，无锁队列）算法细节见 `18`；atomic / MCS 见锁篇（`31`）；timer / VSpace 如何用 rb 见各子系统篇。
**不**展开 `include/arch/*/sys_ctrl`、cpuinfo、SBI（Supervisor Binary Interface，RISC-V 监管模式二进制接口）——ISA 寄存器与特权指令都归 arch 头文件，本篇不写。

---

## 1. 概述

`common/` 提供 **无业务语义** 的积木：定宽类型、原子、侵入式链表/树/位图、引用计数、字符串子集。线程 / VSpace / Port **不**在此处。

这里只有可复用的容器与原语：没有 malloc，也没有 printf——打印走 log，堆走 kmalloc。

---

## 2. 目标与边界

**提供：** §4 分级表中的组件。
**不做：** 完整 libc；格式化 IO；堆分配器；OF（Open Firmware，开放固件/设备树）/ 驱动框架；第二套「通用对象模型」。

新代码优先复用 DSA，不要再发明第二套链表 / 哈希。

---

## 3. 分层与调用方

全核：调度环用 list；timer 与 **VSpace 注册树**用 rb；ASID / tlb mask 用 bitmap；IPC 用 MSQ + taggedptr + refcount；字符串拷贝用 `string.h`（实现在 `kernel/mm/string.c`）。

## 4. 数据结构与不变量（分级）

### 4.1 需明确职责的头

| 头 | 要点 |
|----|------|
| `refcount.h` | `ref_init`（置 1）/ `ref_init_zero`（置 0）/ `ref_get_not_zero`（见 0 即败，防复活）/ `ref_get_claim`（0→1 领首引用）/ `ref_put`（末次引用释放；传 NULL 只减不释放）/ `ref_count`（调试快照）；贯穿 port / message / EBR |
| `taggedptr.h` | `tagged_ptr_t`（u64：低 48 位地址 + 高 16 位 tag，另有 NONE 哨兵）；MSQ 的 head/tail/next 即此类型；IPC（ipc.c / port.c）与分配器（kmalloc / page_slice 空闲链）直接用 `tp_*` |
| `dsa/ms_queue.h` | Michael–Scott；头文件较大；算法见 `18` |
| `dsa/list.h` | intrusive 双向（`INIT_LIST_HEAD` / `list_add_*` / `list_del*` / `list_empty`…） |
| `dsa/rb_tree.h` | 自实现 RB（`RB_Link_Node` / `RB_SolveDoubleRed` / `RB_Remove` / `RB_First`·`RB_Next`…；算法要点见 §4.4）；timer、**VSpace 注册树**（**不是** name_index） |
| `dsa/bitmap.h` | `BITMAP_DEFINE_TYPE` / `BITMAP_OPS`；ASID（Address Space ID，地址空间标识）等 |
| `types.h` | `i8..i64` / `u8..u64`（另附 std 别名）、`vaddr`/`paddr`（`addr_t` 别名）、`asid_t`（u16）、`error_t`（int）… |
| `atomic.h` | + arch `atomic.c`（与屏障篇衔接） |
| `string.h` | 最小集（`memset`/`memcpy`/`strlen`/`strcmp`/`strcmp_s`/`strncpy`）；实现在 **`kernel/mm/string.c`**（不在 modules） |

### 4.2 简表即可

`bit.h`（`BIT_U8/16/32/64`——`BIT_U64` 是 `1ull << n`，另有各宽度的 `set_mask_*` / `clear_mask_*` / `set_bit_*` / `clear_bit_*` 与 `BCD_TO_BIN`）、`align.h`（`ROUND_UP` / `ROUND_DOWN` / `ALIGNED`）、`endianness.h`（仅 `SWAP_ENDIANNESS_16/32/64`）、`mm.h`（`PAGE_SIZE` 等页尺寸，`L0`–`L3_INDEX` 48 位 VA 的四级 9 位索引，`PPN` / `VPN` / `PADDR` / `VADDR`）、`spin.h`（**只有一个** `cpu_idle` 死循环）、`dsa/tree.h`（device / pci 父子 sibling 树：`tree_node_insert` / `tree_node_get_next` / `for_each_tree_node_child`，节点字段 `parent/child/last_child/sibling`，非搜索树）。

**字节序政策：** 全支持架构（x86_64 / aarch64 / …）按 **小端（LE）** 构建与运行；**不做**大端适配层。`endianness.h` 只提供一组纯字节交换函数 `SWAP_ENDIANNESS_16/32/64`——**没有** Linux 式的 `be32_to_cpu` / `cpu_to_be32` 封装（LE 前提下「BE→host」就是裸交换，方向语义由调用点自明）。目前唯一实际消费者是 **FDT（Flattened Device Tree，扁平设备树）**：其线格式为大端，libfdt 的 `fdt_get_header` 系列宏与 `dev_tree.c` 的 `property_read_u32` 都直接包一层 `SWAP_ENDIANNESS_32`。注意 **ACPI 表在本仓库支持的平台上按小端序列化，直接读、不转换**。这是「外来 blob 解码」，不是「内核改 BE」。详见 DTB 篇（`36`）。

### 4.3 勿展开

`stdbool` / `stddef` / `stdarg` / `limits` / `assemble` / `rand`。

早期 `nexus.h` 已删除；用户映射走 `vmm_radix_tree` / `mm_user_utils`。历史名 `tcb.h` 以当前线程头为准。

### 4.4 算法要点（背景）

#### refcount 原子操作与释放语义

```text
refcount 状态机（ref_count_t 内嵌 atomic64_t，全原子）：
  ref_init            count = 1（入队用的初始 dummy / 单持有者节点）
  ref_init_zero       count = 0（新节点；入队时才 ref_get）
  ref_get_not_zero    CAS 循环：仅当 count > 0 时 count++ 并返回 true，
                      否则返回 false          // 复活防护：见 0 即失败
  ref_get_claim       CAS 0→1，领走首引用；仅用于明知起点为 0 的新节点，
                      别人已 claim 过则返回 false
  ref_put(free_fn)    fetch_dec；仅当「递减前的值 == 1」且 free_fn 非 NULL
                      时调 free_fn(节点)，其返回的 error 原样上抛；
                      free_fn 传 NULL = 只减计数、不释放
  ref_count           原子快照；有竞态，只供调试/启发，不可据此判对象存活

  复活防护链：
    put 到 0 后，ref_get_not_zero 永远失败；
    0→正 的合法通道只剩 ref_get_claim（新节点专用）与重新 init，
    而 init 由分配者独占保证。
  贯穿 port / message / EBR（Epoch-Based Reclamation，基于世代的回收）：释放语义统一靠这套，不再各自实现一套。
```

#### rb_tree 插入与旋转

```text
插入：按 BST（Binary Search Tree，二叉搜索树）找位置 → RB_Link_Node 挂上
（挂上即更新祖先黑高）→ 可能违反「红红相邻」，交 RB_SolveDoubleRed 自底向上修：
  本节点即根         → 染黑收工（黑高 +1）
  父黑               → 无冲突收工
  叔黑：同侧（LL/RR）父染黑、异侧（LR/RL）本节点染黑，爷一律染红，
        然后对「本节点」做一次 rotateAt —— 四种形态走同一条
        rotateAt / connect34 重联路径，没有四套旋转代码
  叔红：父/叔染黑、爷染红（黑高字段同步增减），爷作新焦点递归上移
删除：BST 后继替换 → RB_Remove；出现「双黑」由 RB_SolveDoubleBlack 调整
遍历：RB_First / RB_Last / RB_Next / RB_Prev

  实现注记：RB_RED=0、RB_BLACK=1（与直觉相反）；父指针与颜色打包进
  rb_parent_color（低 2 位为标志位）；每个节点自带 black_height 字段，
  染色/旋转处同步维护，供一致性断言（RB_HIGHT_UPDATED）。

  概念示意（LL 单旋；实际实现是通用 rotateAt）：
        G(r)                  P(b)
       /    \                /    \
     P(r)   U    →    N(r)   G(r)
    /                              \
   N(r)                            U
```

#### list 侵入式节点

```text
侵入式（intrusive）：节点字段嵌在宿主对象里，不独立分配
  struct my_obj { int x; list_node_t link; ... };
  list_add_tail(&obj->link, &head);          // 不分配节点
  obj = container_of(link, my_obj_t, link);  // 反推宿主

  head <-> A <-> B <-> C <-> head   // 双向循环
  list_del(&obj->link)  // 仅摘链，不释放对象（对象由 refcount 管）
```

#### bitmap 位运算技巧

```text
  固定长度位图，64 位一格（BITMAP_CELL_TYPE = u64）：
  set bit i:      cells[i/64] |=  BIT_U64(i%64)   // 1ull << n，勿写 1u
  clear bit i:    cells[i/64] &= ~BIT_U64(i%64)
  test bit i:     (cells[i/64] >> (i%64)) & 1
  BITMAP_DEFINE_TYPE(Name, nb_bits)
      → struct { u64 cells[ROUND_UP(nb_bits,64)/64]; } Name
      → 同时生成 Name_zero / Name_is_zero / Name_test / Name_set /
        Name_clear 五个操作；不内置 find-first 之类的扫描原语，
        「找第一个空位」由调用方自己遍历 cells
  BITMAP_OPS(prefix, verb) → prefix##_t##_##verb
      命名约定：类型名必须恰为 prefix + "_t"（如 asid_bitmap_t，则
      BITMAP_OPS(asid_bitmap, zero) 展开为 asid_bitmap_t_zero）
  nb_bits 必须是编译期常量。ASID 分配 / TLB mask 均用此。
```

#### endian 转换

```text
  全支持架构（x86_64 / aarch64）按小端（LE）构建运行
  外来 blob 中 FDT 线格式是大端（BE）；ACPI 在本仓库支持的平台为小端，
  不转换。endianness.h 只提供纯交换原语：
    SWAP_ENDIANNESS_16(x)
    SWAP_ENDIANNESS_32(x)
    SWAP_ENDIANNESS_64(x)
  没有 be32_to_cpu / cpu_to_le32 之类的方向封装——LE 前提下 BE→host
  就是裸交换；方向由调用点自明（libfdt fdt_get_header 宏、
  dev_tree.c property_read_u32 均包 SWAP_ENDIANNESS_32）。
  政策：内核本体不改 BE；仅解码外来 BE blob 时转换。
```

## 8. 多架构

类型 / DSA 与 ISA 无关；atomic / barrier 分 arch。

**架构支持现状：** x86_64、aarch64 为当前主线构建目标；riscv64、loongarch64 在 `common/` 与构建配置中仅为占位（部分 arch 头/`atomic.c` 分支可能缺失），尚未作为完整支持架构运行。本篇所述 DSA 与 endian 政策对占位架构同样适用，但实际启用前需补齐对应 arch 层。
