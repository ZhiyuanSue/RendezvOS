# 内核测试框架与测试用例索引

v0.1 · 2026-09-27

本篇覆盖：`modules/test/test.c`、`single_test.c`、`smp_test.c`、`include/modules/test/test.h` 及各 `single_*` / `smp_*` / `thread_affinity_test.c`。

开关 `RENDEZVOS_TEST` 见构建篇；关机见 `40-错误码与panic.md`。这里验证的是 **core 原语**，不是 compat syscall 回归。

---

## 1. 概述

启用后：

| 角色 | 行为 |
|------|------|
| **BSP**（Bootstrap Processor，启动处理器） | `BSP_test` → `single_cpu_test` + `multi_cpu_test` → 常 **`rendezvos_request_poweroff`** |
| **AP**（Application Processor，应用处理器） | 只执行 `multi_cpu_test` |

两张**静态表**驱动，没有构造器 / linker section 自动注册。加测试用例 = 改表。

框架分层与分发：

```text
   cmain (BSP)                         start_secondary_cpu (AP)
      │                                    │
      ▼                                    ▼
   create_test_thread(true)            create_test_thread(false)
      │                                    │
      ▼                                    ▼
   BSP_test                            AP_test
   ┌──────────────┐                    ┌──────────────┐
   │ single_cpu_   │→ 顺序执行 single_test[]  │ (跳过)      │
   │ test          │                    │              │
   ├──────────────┤                    ├──────────────┤
   │ multi_cpu_    │→ 各核并行 smp_test[]  │ multi_cpu_   │→ 同步执行 smp_test[]
   │ test          │   BSP 做 barrier      │ test         │   等 curr_test 推进
   └──────┬───────┘                    └──────┬───────┘
          ▼                                   ▼
   rendezvos_request_poweroff            schedule (循环)
          │
          ▼
   schedule
```

| 表 | 行为 |
|----|------|
| `single_test[]` | BSP 顺序执行；返回值 0=pass，非 0=fail（多用 `-E_REND_TEST`） |
| `smp_test[]` | 各核并行同一 case；BSP 做 barrier（内含 `schedule`）；若提供 `check_result()` 则 **忽略**每核返回值，只信 BSP 汇总 |

槽上限 `MAX_SINGLE_TEST_CASE = MAX_SMP_TEST_CASE = 10`。single 现约 9 槽（含常 skip 的 PCI stub）、smp 约 8——再加需数槽位。

---

## 2. 目标与边界

**提供：** 表驱动框架；barrier；按域索引。
**不做：** 自动发现；失败时整机一致优雅退出（见 §6）；compat / 用户态回归。

`pmm_test` 在 single 表里 **注释掉**（会耗尽物理帧）。`smp_log_test` 常注释（只看输出）。

---

## 3. 分层与调用方

- BSP：`cmain` → `create_test_thread(true)`（`#ifdef RENDEZVOS_TEST`）。
- AP：`start_secondary_cpu` 路径 `create_test_thread(false)`。
- 禁用：`OVERRIDE_CFLAGS=-URENDEZVOS_TEST` 或关 json feature。
- 注册：改 `single_test[]` / `smp_test[]`。

测试用例线程与 boot IPC 循环 **非互斥**（boot 仍进入 `kernel_handle_msg`，在 `recv_msg` 上阻塞，RR（Round Robin，轮转调度）只选 `ready`）。

---

## 4. 数据结构与不变量

- `test()` 非 0 = fail。
- `check_result != NULL`：每核只执行 `test()` 标 success；**只 BSP** 调 `check_result()` 判总结果。
- `test_state[cpu]` + `curr_test`：跨核同步当前 case 下标。
- `NR_CPU`：barrier 扫 `0..NR_CPU-1`——与拓扑篇「稀疏 APIC / 稠密逻辑 id」同一套计数。

## 6. 流程与失败注意

```text
BSP: single 顺序 → smp 各 case → request_poweroff → schedule
AP:  等 curr_test → 执行 smp case → …
```

### 6.1 SMP 测试 case 同步与 check_result 判定

```text
multi_cpu_test 主循环（BSP 视角）：
  for (i = 0; i < n_smp_cases; i++) {
      curr_test = i;                       // 公布当前 case 下标
      barrier(NR_CPU, &schedule);          // 等所有核就位
      // 各核并行调用 smp_test[i].test()
      barrier(NR_CPU, &schedule);          // 等所有核执行完
      if (smp_test[i].check_result != NULL) {
          // 只信 BSP 汇总：每核 test() 返回值被忽略
          ok = smp_test[i].check_result(); // BSP 调，判全局状态
          if (!ok) { fail; break; }        // 失败则 break（见 §6.2）
      } else {
          // 每核 test() 返回值都计入：任一非 0 即 fail
          for (cpu = 0..NR_CPU-1)
              if (test_state[cpu] != 0) { fail; break; }
      }
      curr_test++;                         // 推进（失败路径可能跳过 → AP 卡住）
  }
```

`check_result` 判定语义：

```text
  check_result == NULL   →  每核 test() 返回值都计入，任一非 0 即 fail
  check_result != NULL   →  每核只执行 test() 标 success；
                            只 BSP 调 check_result() 判总结果，
                            每核 test() 返回值被忽略
  返回 true  → 该 case 通过
  返回 false → 该 case 失败（BSP break）
```

`test_state[cpu]` + `curr_test` 是跨核同步状态：AP 在 `while (curr_test == i)` 上自旋等待 BSP 推进，BSP barrier 内含 `schedule` 让出 CPU。

### 6.2 失败非干净收敛（必读）

- **single fail：** `break` 出循环，可能不打「SINGLE PASS」，但 BSP **仍会执行** smp，并在末尾 **仍可能 poweroff**。
- **smp fail：** BSP `break` 且可能 **不**执行 `curr_test++` → **AP 卡在** `while (curr_test == i)`；BSP 仍可能走到 poweroff。

不是「失败则整机一致优雅退出」。排障时不要假设「没 PASS 就一定立刻停」。

## 7. 公开 API

本篇涉及的接口分布在：内核测试用例框架——`create_test_thread` / `BSP_test` / `AP_test` / `single_cpu_test` / `multi_cpu_test`、表结构与槽上限（`modules/test/test.h`），以及 `single_test[]` / `smp_test[]` 编排（`single_test.c` / `smp_test.c`）。以头文件注释为准（`test.h`；已与 `test.c` 核对）。

**本篇不涉及：** 各 case 所验证的子系统约定（MM/IPC/… → 对应篇）；`RENDEZVOS_TEST` 构建开关 → `01`；`request_poweroff` → `40`；compat syscall 回归。

各 `*_test` / `*_check` **不是**给兼容层的稳定 ABI——增删改表即可。

### 7.1 编排顺序（调用方须遵守）

| 角色 | 顺序 |
|------|------|
| BSP | `cmain` → **`create_test_thread(true)`** → 执行 `BSP_test`：`single_cpu_test` → `multi_cpu_test` → **`rendezvos_request_poweroff`** → `schedule` |
| AP | `start_secondary_cpu` → **`create_test_thread(false)`** → `AP_test`：仅 `multi_cpu_test` → `schedule` |
| 加 case | 实现函数 → 填入 **`single_test[]` / `smp_test[]`**（≤10 槽） |

禁用：`-URENDEZVOS_TEST` 或关 json feature。

### 7.2 框架入口

```c
error_t create_test_thread(bool is_bsp_test);
void *BSP_test(void *arg);
void *AP_test(void *arg);
void single_cpu_test(void);
void multi_cpu_test(void);

#define MAX_SINGLE_TEST_CASE 10
#define MAX_SMP_TEST_CASE    10
```

| 接口 | 说明 |
|------|------|
| `create_test_thread` | `gen_thread_from_func` 挂到本核 `core_tm`。 |
| `single_cpu_test` | 顺序执行表；非 0 fail → `break`（**仍可能继续 smp + poweroff**）。 |
| `multi_cpu_test` | barrier + `schedule`；`check_result!=NULL` 时只信 BSP 汇总。fail 时 AP 可能卡在 `curr_test`。 |

### 7.3 表结构

```c
struct single_test_case { int (*test)(void); char name[32]; };
struct smp_test_case {
        int (*test)(void);
        char name[32];
        bool (*check_result)(void);  /* NULL → 每核返回值都算 */
};
```

无 linker section 自动注册。测试用例索引见 **§8**。

## 8. 测试用例索引（按域）

索引结构：两张静态表 + case 实现文件，编译期固定，无运行时注册。

```text
   single_test[]  (BSP 顺序)          smp_test[]  (各核并行)
   ┌─────────────────────┐            ┌─────────────────────────┐
   │ [0] {test, name}   │ ← .c 文件  │ [0] {test, name, check?}│ ← .c 文件
   │ [1]  ...            │    一一    │ [1]  ...                 │    一一
   │ ...                 │    对应    │ ...                      │    对应
   │ [9] (MAX=10)        │            │ [9] (MAX=10)            │
   └─────────────────────┘            └─────────────────────────┘
        │                                   │
        └─ 域：DSA / MM / 平台 / IPC / 时间     └─ 域：锁 / 堆 / MSQ / IPC / 调度 / 日志
```

### Single（`single_test[]`）

| 域 | 入口 / 文件 |
|----|-------------|
| DSA | `rb_tree_test` ← `single_rb_tree_test.c` |
| MM | `arch_vmm_test`；`kmalloc_test`；`page_slice_test`；可选 `pmm_test`（注释） |
| 平台 | `test_pci_scan`（无 `PCI` 时直接 `REND_SUCCESS`） |
| IPC/Port | `ipc_test`、`ipc_multi_round_test`；`port_discovery` ← `single_port_test.c` |
| 时间 | `single_timer_test` |

### SMP（`smp_test[]`）

| 域 | 入口 | 备注 |
|----|------|------|
| 锁 | `smp_lock_test` + `smp_lock_check` | |
| 堆 | `smp_kmalloc_test` | |
| MSQ | `smp_ms_queue_*`（**三 case 同文件** `smp_ms_queue_test.c`） | 勿虚构独立 dyn/check 文件 |
| IPC/Port | `smp_ipc_test`；`smp_port_robustness_test` | |
| 调度 | `smp_thread_affinity_*` ← `thread_affinity_test.c` | `check_result` |
| 日志 | `smp_log_test` | **表内常注释掉** |

**磁盘上无** `*nexus*` / `single_elf_read` / `single_task` 一类陈旧叙述——不再索引。
